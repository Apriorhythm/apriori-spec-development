**Responsibility.** Bind spec scenario IDs to a TAP-emitting test run; report per-scenario red/green; act as STEP5's deterministic gate. Fail-closed: a broken or vacuous run is never GREEN.

**Public interface (module exports).**
- `leadId(text, idRe)` → leading ID or null. Word-boundary strict: `XX-01b`, `XX-01_x` are NOT `XX-01`.
- `stripFences(text)` → text with ``` fenced blocks removed (fenced scenarios are documentation, not spec).
- `mdFiles` is internal; `collectScenarios(specTargets, idRe)` → `{ byId, unidentified:[[file,title]], files, missingTargets, duplicates:[{id,files}] }`. A target may be a dir (recursed for `*.md`, sorted) or a single file (accepted as-is, ANY extension); dedupes overlapping targets. Scenario discovery matches exact h4 lines `#### Scenario: …` only.
- `parseTap(out, idRe)` → `{ results: Map<id,{pass,fail,skip}>, untagged:[], untaggedFails, bailout }`. Only lines shaped exactly `ok|not ok <n> - <name>` parse — a TAP result line without the ` - ` separator is ignored. `# SKIP`/`# TODO` counts as skip (proves nothing); untagged `not ok` without directive increments `untaggedFails`; `Bail out!` line captured.
- `zeroTapParsed(out, results, untagged)` → true when output exists but no TAP line parsed AND no `TAP version`/`1..N` plan line (plan line = TAP reporter with an empty suite, not a reporter problem).

- `evaluate(byId, unidentified, results)` → `{ boundGreen, boundRed, unbound, orphan, unidentified, clean }`. A scenario whose only results are skips is UNBOUND.
- `verify(opts {specs:[], testCmd, idPattern, cwd})` → run object `{ verdict, results, fileCount, failCount, scenarioCount, missingTargets, duplicates, bailout, noTap, exec{status,signal,error}, errors }`. `failCount` = tagged fails + `untaggedFails`.
- `infraErrors(run)` → string[] (empty = trustworthy). Triggers: missing spec target · zero spec files · zero scenarios · spawn error · signal kill · bailout · zero-TAP-parsed · non-zero exit with `failCount === 0` (TAP picture doesn't explain the exit).
- `formatReport(...)` → human report; RESULT line: `ERROR — run not trustworthy (see stderr)` / `GREEN — spec is the test suite` / `GAPS`. Duplicates block GREEN.
- `verifyJson(run)` → `{ clean, result: GREEN|GAPS|ERROR, errors, specFiles, exec, duplicates, boundGreen[], boundRed[], unbound[], orphan[], unidentified[] }`.
- `configTestCmd(cwd)` → test-cmd from `apriori/process-config.md`'s `| test-cmd | … |` row, or null.

# Requirement — change-projection (v1)

change: change-projection
target lineage: **v3 branch** (independent lineage; never merge to main or v2). Ships as apriori-cli **3.1.0** (minor, backward compatible).

## Background — the problem (current state A)

STEP5's deterministic gate (`apriori verify`) can only scan **on-disk spec directories**. During STEP5 the change's delta specs are not yet merged into the living store, so today an agent must choose between two wrong targets:

1. Scan only `apriori/specs/` (the living store) → the change's new scenarios are invisible; new tests show as ORPHAN.
2. Scan both `apriori/specs/` and `apriori/changes/<name>/specs/` → correct only for pure-ADDED deltas. A **MODIFIED** block appears in both dirs → duplicate scenario IDs → GAPS; a **REMOVED** requirement still demands its store scenarios be bound; a **RENAMED** requirement demands both old and new IDs.

Separately, `apriori archive` is a single-file primitive (`--store <file> --delta <file>`): a multi-module change needs one manual invocation per module, with no cross-module dry-run and no atomicity across modules. And a delta records nothing about the store state it was authored against, so a store that changed since branching merges silently (§4.11's serialize rule has no tooling).

## Goal (target state B)

Three consumer surfaces of the **same `merge()` pure function** (already exported by `lib/archive-merge.js`):

1. **Projected verify** — `apriori verify --change <name>`: construct the candidate post-merge store ("projection") by applying the change's delta specs to the living store **in memory** (never writing to the living store's location), and bind scenarios against that projection. Verify and archive share one merge semantics: what verify proved is exactly what archive will produce.
2. **High-level archive** — `apriori archive --change <name>`: auto-discover every delta spec under the change dir, map each to its store target by the layout convention, dry-run the whole set by default, and on `--write` commit **all modules or none**.
3. **CAS (compare-and-swap) base stamp** — a delta may declare the store state it was authored against; both projected verify and archive detect a store that has since diverged and refuse with a clear message instead of merging/projecting silently.

## Mapping convention (shared by 1 and 2)

`apriori/changes/<name>/specs/<module>/spec.md` ↔ `apriori/specs/<module>/spec.md` (path suffix after `specs/` is the key). A delta whose suffix has no store counterpart targets a **new** store file (legal: first spec of a new module).

## Acceptance criteria (testable)

**Projected verify**
- V1. If a change contains an ADDED-only delta for module M, then `verify --change <name>` reports the new scenarios as bindable (UNBOUND until tests exist, BOUND-GREEN when tagged tests pass) alongside all existing store scenarios — with no duplicate-ID error.
- V2. If a delta MODIFIES requirement R (changing scenario set), then verification binds against the **delta's** version of R's scenarios only; scenarios that the modification drops are not demanded.
- V3. If a delta REMOVES requirement R, then R's scenarios are **not** demanded by `verify --change` (deprecated blocks don't demand tests; see open question Q2).
- V4. If a delta RENAMES requirement Old→New, then verification demands exactly the projected (post-rename) picture.
- V5. If the merge of the deltas reports any conflict, `verify --change` exits **2** (run untrustworthy: there is no well-defined projection) naming the conflicts — never verifies a partial or wrong projection.
- V6. `verify --change` with a nonexistent change name, or a change with zero delta spec files, exits 2 with a message naming the path it looked under (fail-closed, no vacuous GREEN).
- V7. Without `--change`, `verify` behavior is byte-identical to 3.0.1 (backward compatible).
- V8. Exit taxonomy preserved: 0 = projection GREEN · 1 = gaps · 2 = untrustworthy.

**High-level archive**
- A1. `archive --change <name>` (dry-run default) discovers all delta files under the change's `specs/`, prints per-module merged/modified/deprecated/renamed/no-op IDs and a result line, and writes nothing.
- A2. `archive --change <name> --write` applies every module's merge transactionally: all stores committed, or — on any conflict or I/O failure in any module — **no store file changed**.
- A3. Zero delta files found under the change → exit 2 naming the searched path (consistent with the existing zero-op guard's spirit).
- A4. `--changes-dir` interplay unchanged: with it, the change dir moves to `changes/archive/<stamp>-<name>/` after stores commit; without it, only stores are written.
- A5. The single-file form (`--store` + `--delta`) keeps working unchanged (backward compatible).
- A6. Rerunning an already-archived change remains a no-op per existing idempotency rules, now across all modules.

**CAS base stamp**
- C1. A delta file may carry a base-stamp declaring the fingerprint of the store file it was authored against; the stamp's format and location are fixed by the spec (STEP2 decides the concrete syntax).
- C2. When the stamp is present and the current store file's fingerprint differs, `archive` (single-file and `--change` forms) and `verify --change` refuse with a message naming the module, expected vs actual fingerprint, exit 2 — nothing written, nothing projected.
- C3. When the stamp is absent, behavior is exactly pre-3.1 (opt-in; backward compatible).
- C4. A stamp against a **not-yet-existing** store file is expressible (the "new module" case) and verifies as matching only while the store file still does not exist.
- C5. The CLI offers a way to produce the correct current stamp for a store file (so delta authors never hand-compute it), and the runbook's delta-authoring instructions reference it.

**Cross-cutting**
- X1. All new behavior covered by spec scenarios with stable IDs + bound TAP tests (`apriori verify` GREEN on this repo, dogfooded — the change's own delta specs verified via `verify --change change-projection` before archiving).
- X2. No new dependencies (zero-dep constraint holds).
- X3. Existing 84 tests keep passing unmodified (except where a spec is deliberately extended — any such modification is listed in the delta).

## Out of scope (won't do in this change)

- `apriori doctor`, `apriori gate --change` (roadmap items 4-5).
- `--help`/unknown-flag strictness across subcommands (roadmap item 6).
- Change Bundle layout, non-reusable change IDs, approval digests, executable state machine (roadmap 13-15).
- Any behavior change to `check`, `init`, `new`, `status`, `update`.
- Auto-writing base stamps into deltas at authoring time by the CLI (the author or a future `new`-side helper does that; this change only defines, checks, and prints stamps).

## Open questions (for STEP0 review / STEP2)

- Q1. Projection mechanics: temp files vs in-memory scenario collection (`collectScenarios` currently reads the filesystem). Constraint fixed by V5/V8 either way; implementation choice is STEP2's.
- Q2. Should a REMOVED (deprecated-in-place) requirement's scenarios be demanded by plain `verify` against the post-archive store today? (Current behavior: deprecated blocks keep their scenarios and ARE demanded.) V3 assumes projected verify must NOT demand them; if that requires changing how deprecated blocks are scanned, the delta must state it explicitly.
- Q3. Fingerprint algorithm and normalization (raw bytes vs trimmed) — STEP2 decides; C2/C4 fix the observable behavior.

# TRUTH — archive-merge (`lib/archive-merge.js`, CLI subcommand `archive`)

## Contract (code-is-truth)

source-commit: 30fa38e

**Responsibility.** Merge a change's delta spec into the living store by stable Requirement ID (STEP6 archive action); move the change dir to `changes/archive/`. Zero deps.

**Delta format.** `## ADDED|MODIFIED|REMOVED|RENAMED Requirements` (h2 sections) containing `### Requirement: <name>` blocks (h3); RENAMED carries `- Old -> New` lines. Parsing: `parseDelta(text)` → `{ ADDED:Map, MODIFIED:Map, REMOVED:Map, RENAMED:[[old,new]] }`; `parseRequirements(text)` → Map name→full block — a Map, so DUPLICATE requirement names in one document silently collapse (last block wins, no conflict reported); `deltaOpCount(delta)` → total parsed ops (0 = no recognized section OR recognized sections that contained no parseable requirement/rename lines).

**Public interface.**
- `merge(storeText, delta, change)` — PURE. → `{ store:Map, merged, modified, deprecated, renamed, conflicts, unchanged }`. Order of application: RENAMED first (in-place key swap preserving document order), then ADDED, MODIFIED, REMOVED.
  - ADDED on existing name: identical trimmed content → `unchanged` (idempotent rerun no-op) UNLESS the name was created by this run's RENAMED (`renamedTargets`) → conflict.
  - MODIFIED replaces the whole block; missing target → conflict.
  - REMOVED keeps the block, injects `_deprecated (superseded by <change>)_` into the heading line.
  - RENAMED with source gone + target present → `unchanged` ("already renamed" rerun signature); source gone + target absent → conflict; target already exists → conflict.
  - ANY conflict → nothing written (CLI exit 1).
- `renderStore(storeText, store)` — preserves the store's header (text before the first `### Requirement:`), then blocks joined with `\n`.
- `archiveStamp(d)` → `YYYY-MM-DDThhmm` (colon-free, CLI clock).
- `CHANGE_NAME_RE` = `/^[a-z0-9]+(-[a-z0-9]+)*$/` (same rule as `apriori new`).
- `archiveChangeDir(changesDir, name, now)` — validates name, resolve-containment path guard, `renameSync` to `changes/archive/<stamp>-<name>/`; returns dest or null when source missing; throws on invalid name/escape.
- `cli(argv)`: `--store <FILE> --delta <FILE> --change <name> [--write] [--changes-dir <dir>]`. Single store FILE + single delta FILE per invocation (multi-module changes need one call per module — roadmap item 2 targets this). Missing store file = start from empty ("will be created"). Content-bearing delta parsing to 0 ops → error, exit 1 (silent-no-op guard). `--changes-dir` preflights the change dir exists (exit 2 if not). Exit: 0 merged · 1 conflict/zero-op/move-failure · 2 usage/invalid name/missing change dir.

**Transactional write ordering (`--write`).** store staged to `<store>.tmp-archive` → dir move (atomic rename) → store committed via `renameSync(tmp, store)`. Move failure → tmp discarded, store byte-for-byte untouched. Limits: (a) tmp+rename gives single-file replace atomicity, NOT crash durability (no fsync on file or dir) — do not claim crash-durable; (b) the final `renameSync(tmp, store)` is NOT guarded — if it throws AFTER the change dir moved, the store is unchanged but the change dir is already archived and the tmp file is left behind (the "all or nothing" claim covers move failure, not store-commit failure after the move).

**Three moments.** The store file is the shared state: init = created on first `--write`; update = full rewrite via temp+rename; cleanup = none (grows monotonically; REMOVED deprecates, never deletes).

**Pitfalls.**
- `merge` compares ADDED blocks with `.trim()` equality — whitespace-only differences count as conflicts, not no-ops.
- `renderStore` drops anything BETWEEN requirement blocks that isn't part of a block (inter-block prose is not preserved — only the pre-first-block header is). Needs human confirmation whether any store relies on inter-block prose (repo's own stores do not).
- The delta has no base-store fingerprint: concurrent modification between delta authoring and archive is undetectable (roadmap item 3, CAS — this change).
- Deprecation rewrites the heading LINE (`### Requirement: Name  _deprecated (superseded by x)_`), so on re-parse the requirement's map KEY includes the marker — a REMOVED rerun therefore conflicts (`no target in store`) instead of no-opping, and MODIFIED/RENAMED can no longer address the block by its original name.
- Unknown CLI flags silently ignored (roadmap item 6).

## Decisions (doc-is-truth)

- D-AM-1 (active): same-ID conflict = stop, ledger issue, human resolves — the §4.11 serialize-per-module rule; the tool never auto-resolves.
- D-AM-2 (active): archive rerun idempotency as ratified in 3.0.1 covers TWO signatures only — identical-content ADDED, and RENAMED source-gone+target-present. MODIFIED reruns re-apply (same content → same store, reported as modified); REMOVED reruns conflict (see Contract pitfall on heading rewrite) — a known, accepted limitation, not a violated invariant.
- D-AM-3 (active): a content-bearing delta parsing to zero operations errors instead of silently merging nothing.
- D-AM-4 (active): REMOVED deprecates in place (audit trail), never physically deletes.

const REQ_RE = /^###\s+Requirement:\s+(.+?)\s*$([\s\S]*?)(?=^###\s+Requirement:|$(?![\s\S]))/gm;
const SECTION_SPLIT_RE = /^##\s+(ADDED|MODIFIED|REMOVED|RENAMED)\s+Requirements\s*$/m;

// name -> full block (heading + body), in document order
function parseRequirements(text) {
  const out = new Map();
  let m;
  REQ_RE.lastIndex = 0;
  while ((m = REQ_RE.exec(text)) !== null) out.set(m[1].trim(), m[0].replace(/\s+$/, '') + '\n');
  return out;
}

function parseDelta(text) {
  const buckets = { ADDED: new Map(), MODIFIED: new Map(), REMOVED: new Map(), RENAMED: [] };
  const parts = text.split(SECTION_SPLIT_RE);
  for (let i = 1; i < parts.length; i += 2) {
    const kind = parts[i];
    if (kind === 'RENAMED') {
      // one rename per line: `- Old Name -> New Name`
      for (const m of parts[i + 1].matchAll(/^\s*-\s*(.+?)\s*->\s*(.+?)\s*$/gm))
        buckets.RENAMED.push([m[1].trim(), m[2].trim()]);
    } else {
      for (const [name, block] of parseRequirements(parts[i + 1])) buckets[kind].set(name, block);
    }
  }
  return buckets;
}

// total number of operations a parsed delta carries (0 = the delta matched no known section)
function deltaOpCount(delta) {
  return delta.ADDED.size + delta.MODIFIED.size + delta.REMOVED.size + delta.RENAMED.length;
}

// Pure merge. Returns { store: Map, merged, modified, deprecated, renamed, conflicts }
function merge(storeText, delta, change) {
  const store = parseRequirements(storeText);
  const merged = [], modified = [], deprecated = [], renamed = [], conflicts = [], unchanged = [];
  const renamedTargets = new Set();   // names created by THIS run's renames — an ADDED hitting one is a same-delta collision, never a rerun no-op
  // RENAMED first: rename the store block's ID, preserving its content
  for (const [oldName, newName] of (delta.RENAMED || [])) {
    if (!store.has(oldName)) {
      // rerun signature: source already gone AND target present → this rename already happened
      if (store.has(newName)) { unchanged.push(`${oldName} -> ${newName} (already renamed)`); continue; }
      conflicts.push(`RENAMED '${oldName}' has no target in store`); continue;
    }
    if (store.has(newName)) { conflicts.push(`RENAMED target '${newName}' already exists in store`); continue; }
    const block = store.get(oldName);
    const renamedBlock = block.replace(/^###\s+Requirement:\s+.+$/m, `### Requirement: ${newName}`);
    // rebuild the map preserving order, swapping the key at the old position
    const rebuilt = new Map();
    for (const [k, v] of store) rebuilt.set(k === oldName ? newName : k, k === oldName ? renamedBlock : v);
    store.clear();
    for (const [k, v] of rebuilt) store.set(k, v);
    renamed.push(`${oldName} -> ${newName}`);
    renamedTargets.add(newName);
  }
  for (const [name, block] of delta.ADDED) {
    if (store.has(name)) {
      // idempotent rerun: identical content means this delta already merged — a no-op, not a collision.
      // But a name just created by THIS run's RENAMED is a same-delta collision, never a rerun.
      if (!renamedTargets.has(name) && store.get(name).trim() === block.trim()) unchanged.push(name);
      else conflicts.push(`ADDED '${name}' already exists in store`);
    } else { store.set(name, block); merged.push(name); }
  }
  for (const [name, block] of delta.MODIFIED) {
    if (!store.has(name)) conflicts.push(`MODIFIED '${name}' has no target in store`);
    else { store.set(name, block); modified.push(name); }
  }
  for (const name of delta.REMOVED.keys()) {
    if (!store.has(name)) conflicts.push(`REMOVED '${name}' has no target in store`);
    else {
      const block = store.get(name);
      const nl = block.indexOf('\n');
      store.set(name, block.slice(0, nl) + `  _deprecated (superseded by ${change})_` + block.slice(nl));
      deprecated.push(name);
    }
  }
  return { store, merged, modified, deprecated, renamed, conflicts, unchanged };
}

function renderStore(storeText, store) {
  const idx = storeText.indexOf('### Requirement:');
  const header = idx >= 0 ? storeText.slice(0, idx) : '';
  return header + [...store.values()].join('\n');
}

// colon-free date-time stamp YYYY-MM-DDThhmm (CLI's own clock; never an agent guess)
function archiveStamp(d) {
  const p = (n) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${p(d.getMonth() + 1)}-${p(d.getDate())}T${p(d.getHours())}${p(d.getMinutes())}`;
}

const CHANGE_NAME_RE = /^[a-z0-9]+(-[a-z0-9]+)*$/;   // bare kebab-case — same rule as `apriori new`

// Move an in-flight change dir (bare name) → changes/archive/<stamp>-<name>/
// Fail-closed on path escape: the source must be strictly inside changesDir.
function archiveChangeDir(changesDir, name, now) {
  if (!CHANGE_NAME_RE.test(name)) throw new Error(`invalid change name '${name}' — bare kebab-case only`);
  const src = path.join(changesDir, name);
  const base = path.resolve(changesDir) + path.sep;
  if (!(path.resolve(src) + path.sep).startsWith(base)) throw new Error(`change path escapes ${changesDir}`);
  if (!fs.existsSync(src)) return null;
  const dest = path.join(changesDir, 'archive', `${archiveStamp(now)}-${name}`);
  fs.mkdirSync(path.dirname(dest), { recursive: true });
  fs.renameSync(src, dest);
  return dest;
}

function cli(argv) {
  const a = { store: null, delta: null, change: null, write: false, changesDir: null };
  for (let i = 0; i < argv.length; i++) {
    const k = argv[i];
    if (k === '--store') a.store = argv[++i];
    else if (k === '--delta') a.delta = argv[++i];
    else if (k === '--change') a.change = argv[++i];
    else if (k === '--write') a.write = true;
    else if (k === '--changes-dir') a.changesDir = argv[++i];
  }
  if (!a.store || !a.delta || !a.change) { console.error('usage: apriori archive --store <f> --delta <f> --change <name> [--write] [--changes-dir <dir>]'); return 2; }
  if (!CHANGE_NAME_RE.test(a.change)) { console.error(`archive: invalid change name '${a.change}' — bare kebab-case only (path segments are not allowed)`); return 2; }
  if (a.changesDir && !fs.existsSync(path.join(a.changesDir, a.change))) {
    console.error(`archive: change '${a.change}' not found under ${a.changesDir} — nothing to move`); return 2;
  }
  // first archive in a repo: the store file may not exist yet — start from an empty store
  const storeExists = fs.existsSync(a.store);
  const storeText = storeExists ? fs.readFileSync(a.store, 'utf8') : '';
  if (!storeExists) console.log(`store ${a.store} does not exist yet — will be created${a.write ? '' : ' on --write'}`);
  const deltaText = fs.readFileSync(a.delta, 'utf8');
  const delta = parseDelta(deltaText);
  // Guard against a silent no-op: a delta with real content that parsed to zero operations
  // is almost always a format mismatch (wrong heading level/keyword), not an empty change.
  // Report it and write nothing — never print MERGED for a delta the parser didn't understand.
  if (deltaText.trim() && deltaOpCount(delta) === 0) {
    console.error(`archive: parsed 0 delta operations from ${a.delta} — it has content but no recognized operations.`);
    console.error('  expected `## ADDED|MODIFIED|REMOVED Requirements` (h2) with `### Requirement: <name>` (h3) blocks,');
    console.error('  or `## RENAMED Requirements` with `- Old -> New` lines. Nothing written.');
    return 1;
  }
  const { store, merged, modified, deprecated, renamed, conflicts, unchanged } = merge(storeText, delta, a.change);

  for (const [label, ids] of [['merged (ADDED)', merged], ['modified (MODIFIED)', modified], ['deprecated (REMOVED)', deprecated], ['renamed (RENAMED)', renamed], ['already merged (no-op)', unchanged]])
    if (ids.length) console.log(`${label}: ${ids.join(', ')}`);

  if (conflicts.length) {
    console.log('\nCONFLICTS (stop — open a ledger issue, human resolves):');
    for (const c of conflicts) console.log(`  ✗ ${c}`);
    console.log('\nRESULT: CONFLICT — nothing written');
    return 1;
  }
  if (a.write) {
    // Transactional ordering: stage the store to a temp file, do the (atomic) dir move, then
    // commit the store via rename. If the move fails, the temp is discarded and the store on
    // disk stays byte-for-byte untouched — never a half-completed archive.
    fs.mkdirSync(path.dirname(a.store), { recursive: true });
    const tmp = a.store + '.tmp-archive';
    fs.writeFileSync(tmp, renderStore(storeText, store));
    let moved = null;
    if (a.changesDir) {
      try { moved = archiveChangeDir(a.changesDir, a.change, new Date()); }
      catch (e) { fs.rmSync(tmp, { force: true }); console.error(`archive: ${e.message} — store left untouched`); return 1; }
      if (moved === null) { fs.rmSync(tmp, { force: true }); console.error(`archive: change dir vanished mid-run — store left untouched`); return 1; }
    }
    fs.renameSync(tmp, a.store);
    console.log(`\nRESULT: MERGED — ${a.store} rewritten${moved ? `; change archived → ${moved}` : ''}`);
  } else {
    console.log(`\nRESULT: MERGED (dry-run; ${store.size} requirements in result) — pass --write to apply`);
  }
  return 0;
}

'use strict';
/*
 * spec-runner — bind spec scenario IDs to test runs, report per-scenario red/green.
 * VISION endgame, weak form: "spec IS the test suite". Zero deps — pure Node stdlib.
 * Coupling surface is tiny and language-agnostic: markdown scenarios + a TAP-emitting test command.
 *
 * FAIL-CLOSED: a deterministic gate must refuse to say GREEN when its inputs are missing,
 * its instrument misbehaved, or its evidence is ambiguous. Vacuous success is a bug.
 * Exit codes: 0 = GREEN · 1 = spec/test gaps · 2 = invocation or infrastructure error.
 */
const fs = require('fs');
const path = require('path');
const { spawnSync } = require('child_process');

const DEFAULT_ID = '[A-Z]+-\\d+';
const SCENARIO_RE = /^####\s+Scenario:\s+(.*)$/gm;
// TAP result line, directive split off separately (# SKIP / # TODO)
const TAP_RE = /^(ok|not ok)\s+\d+\s+-\s+(.*)$/gm;

// Leading scenario/test ID. The match must end at a word boundary: `XX-01b` is NOT `XX-01` —
// silently truncating would merge two different scenarios into one binding.
function leadId(text, idRe) {
  const m = text.trim().match(idRe);
  if (!m || m.index !== 0) return null;
  const next = text.trim()[m[0].length];
  if (next !== undefined && /[A-Za-z0-9_]/.test(next)) return null;
  return m[0];
}

function stripFences(text) { return text.replace(/```[\s\S]*?```/g, ''); }

function mdFiles(target) {
  if (!fs.existsSync(target)) return [];
  const st = fs.statSync(target);
  if (st.isFile()) return [target];
  const out = [];
  for (const e of fs.readdirSync(target, { withFileTypes: true })) {
    const p = path.join(target, e.name);
    if (e.isDirectory()) out.push(...mdFiles(p));
    else if (e.name.endsWith('.md')) out.push(p);
  }
  return out.sort();
}

// Collect scenarios from spec files.
// → { byId, unidentified:[[file,title]], files, missingTargets:[], duplicates:[{id,files}] }
// Code-fence content is excluded: an example scenario inside ``` is documentation, not a spec.
function collectScenarios(specTargets, idRe) {
  const byId = new Map();          // id -> [titles]
  const idFiles = new Map();       // id -> [files] (for duplicate reporting)
  const unidentified = [];
  const missingTargets = specTargets.filter((t) => !fs.existsSync(t));
  const files = [...new Set(specTargets.flatMap(mdFiles))].sort();
  for (const f of files) {
    const text = stripFences(fs.readFileSync(f, 'utf8'));
    let m;
    SCENARIO_RE.lastIndex = 0;
    while ((m = SCENARIO_RE.exec(text)) !== null) {
      const id = leadId(m[1], idRe);
      if (id) {
        if (!byId.has(id)) { byId.set(id, []); idFiles.set(id, []); }
        byId.get(id).push(m[1]);
        idFiles.get(id).push(f);
      } else unidentified.push([f, m[1]]);
    }
  }
  const duplicates = [...byId.entries()].filter(([, titles]) => titles.length > 1)
    .map(([id]) => ({ id, files: [...new Set(idFiles.get(id))] }));
  return { byId, unidentified, files, missingTargets, duplicates };
}

// Parse TAP text → { results: Map<id,{pass,fail,skip}>, untagged: [], bailout: string|null }
// A # SKIP / # TODO directive is neither pass nor fail — a skipped test proves nothing.
function parseTap(out, idRe) {
  const results = new Map();
  const untagged = [];
  let untaggedFails = 0;
  const bm = out.match(/^Bail out!(.*)$/m);
  const bailout = bm ? bm[0].trim() : null;
  let m;
  TAP_RE.lastIndex = 0;
  while ((m = TAP_RE.exec(out)) !== null) {
    const hash = m[2].search(/#\s*(SKIP|TODO)\b/i);
    const name = hash >= 0 ? m[2].slice(0, hash).trim() : m[2];
    const directive = hash >= 0;
    const id = leadId(name, idRe);
    if (id === null) { untagged.push(name); if (m[1] === 'not ok' && !directive) untaggedFails++; continue; }
    const cur = results.get(id) || { pass: 0, fail: 0, skip: 0 };
    if (directive) cur.skip++;
    else cur[m[1] === 'ok' ? 'pass' : 'fail']++;
    results.set(id, cur);
  }
  return { results, untagged, untaggedFails, bailout };
}

// true when the test command produced output but not a single TAP result line was parsed —
// almost always means the runner used a human reporter (node: add --test-reporter=tap)
function zeroTapParsed(out, results, untagged) {
  if (results.size > 0 || untagged.length > 0) return false;
  if (!out.trim()) return false;
  // a TAP version line or plan (1..N) proves the reporter IS TAP — an empty suite is not a reporter problem
  if (/^TAP version \d+|^1\.\.\d+/m.test(out)) return false;
  return true;
}

function runTestCommand(cmd, cwd) {
  const r = spawnSync(cmd, { shell: true, cwd, encoding: 'utf8' });
  return {
    out: (r.stdout || '') + '\n' + (r.stderr || ''),
    status: r.status,               // null when killed by signal
    signal: r.signal || null,
    error: r.error ? String(r.error.message || r.error) : null,
  };
}

// Pure evaluation: cross-reference scenarios vs results → verdict object.
// A scenario whose only results are skips is UNBOUND — skips prove nothing.
function evaluate(byId, unidentified, results) {
  const specIds = [...byId.keys()].sort();
  const boundGreen = [], boundRed = [], unbound = [], orphan = [];
  for (const id of specIds) {
    const r = results.get(id);
    if (!r || (r.pass === 0 && r.fail === 0)) unbound.push(id);
    else if (r.fail === 0) boundGreen.push(id);
    else boundRed.push(id);
  }
  for (const id of [...results.keys()].sort()) if (!byId.has(id)) orphan.push(id);
  const clean = !boundRed.length && !unbound.length && !orphan.length && !unidentified.length;
  return { boundGreen, boundRed, unbound, orphan, unidentified, clean };
}

// Fail-closed guard: reasons this run cannot be trusted regardless of the TAP picture.
// Returns [] when the run is trustworthy.
function infraErrors(run) {
  const errs = [];
  for (const t of run.missingTargets) errs.push(`spec target does not exist: ${t}`);
  if (!run.missingTargets.length && run.fileCount === 0)
    errs.push('no spec files found under the given targets — nothing to verify');
  if (run.fileCount > 0 && run.scenarioCount === 0)
    errs.push('spec files contain zero scenarios — nothing to verify');
  if (run.exec.error) errs.push(`test command failed to spawn: ${run.exec.error}`);
  if (run.exec.signal) errs.push(`test command was killed by signal ${run.exec.signal}`);
  if (run.bailout) errs.push(`test run aborted: ${run.bailout}`);
  if (run.noTap)
    errs.push('test command produced output but ZERO TAP results were parsed — the command is probably not emitting TAP (node test runner: add --test-reporter=tap)');
  if (run.exec.status !== null && run.exec.status !== 0 && run.failCount === 0)
    errs.push(`test command exited with status ${run.exec.status} but no parsed TAP failure explains it — the TAP picture is incomplete or truncated; refusing to trust this run`);
  return errs;
}

function formatReport(v, results, fileCount, extras = {}) {
  const lines = [];
  const specCount = v.boundGreen.length + v.boundRed.length + v.unbound.length;
  const tagged = [...results.values()].reduce((s, r) => s + r.pass + r.fail, 0);
  const skipped = [...results.values()].reduce((s, r) => s + (r.skip || 0), 0);
  lines.push(`specs: ${fileCount} file(s), ${specCount} identified scenario(s)`);
  lines.push(`tests: ${tagged} tagged result(s)${skipped ? `, ${skipped} skipped (not counted)` : ''}\n`);
  const groups = [['BOUND-GREEN', v.boundGreen], ['BOUND-RED', v.boundRed],
                 ['UNBOUND (scenario, no test)', v.unbound], ['ORPHAN (test, no scenario)', v.orphan]];
  for (const [label, items] of groups) {
    if (!items.length) continue;
    lines.push(`${label === 'BOUND-GREEN' ? '✓' : '✗'} ${label}: ${items.length}`);
    for (const id of items) {
      const r = results.get(id);
      lines.push(`    ${id}${r ? `  ${r.pass}p/${r.fail}f${r.skip ? `/${r.skip}s` : ''}` : ''}`);
    }
  }
  if (v.unidentified.length) {
    lines.push(`✗ UNIDENTIFIED (scenario, no ID — unbindable): ${v.unidentified.length}`);
    for (const [f, t] of v.unidentified) lines.push(`    ${path.basename(f)}: ${t.slice(0, 60)}`);
  }
  if (extras.duplicates && extras.duplicates.length) {
    lines.push(`✗ DUPLICATE scenario IDs (ambiguous binding): ${extras.duplicates.length}`);
    for (const d of extras.duplicates) lines.push(`    ${d.id}: ${d.files.map((f) => path.basename(f)).join(', ')}`);
  }
  const errs = extras.errors || [];
  lines.push('\nRESULT: ' + (errs.length ? 'ERROR — run not trustworthy (see stderr)'
    : (v.clean && !(extras.duplicates || []).length ? 'GREEN — spec is the test suite' : 'GAPS')));
  return lines.join('\n');
}

// Full verify run. opts: { specs:[], testCmd, idPattern, cwd }
function verify(opts) {
  const idRe = new RegExp(opts.idPattern || DEFAULT_ID);
  const { byId, unidentified, files, missingTargets, duplicates } = collectScenarios(opts.specs, idRe);
  const exec = runTestCommand(opts.testCmd, opts.cwd || '.');
  const { results, untagged, untaggedFails, bailout } = parseTap(exec.out, idRe);
  const verdict = evaluate(byId, unidentified, results);
  const failCount = [...results.values()].reduce((s, r) => s + r.fail, 0) + untaggedFails;
  const run = {
    verdict, results, fileCount: files.length, failCount,
    scenarioCount: byId.size + unidentified.length,
    missingTargets, duplicates, bailout,
    noTap: zeroTapParsed(exec.out, results, untagged),
    exec: { status: exec.status, signal: exec.signal, error: exec.error },
  };
  run.errors = infraErrors(run);
  return run;
}

// machine-consumable shape for a verify run
function verifyJson(run) {
  const { verdict: v, results } = run;
  const clean = v.clean && run.duplicates.length === 0 && run.errors.length === 0;
  return {
    clean,
    result: run.errors.length ? 'ERROR' : (clean ? 'GREEN' : 'GAPS'),
    errors: run.errors,
    specFiles: run.fileCount,
    exec: run.exec,
    duplicates: run.duplicates,
    boundGreen: v.boundGreen.map((id) => ({ id, ...results.get(id) })),
    boundRed: v.boundRed.map((id) => ({ id, ...results.get(id) })),
    unbound: v.unbound,
    orphan: v.orphan.map((id) => ({ id, ...results.get(id) })),
    unidentified: v.unidentified.map(([file, title]) => ({ file, title })),
  };
}
