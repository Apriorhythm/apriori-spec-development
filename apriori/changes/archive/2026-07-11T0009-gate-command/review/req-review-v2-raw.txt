## Background — the problem (current state A)

The runbook's exit conditions for a change are individually machine-checkable — `verify` GREEN, tasks.md all `[x]`, a legal flow-state, a ledger with no open rows, every `VERDICT:` line backed by a raw archive (§1 enforcement layer ①), fresh KB stamps — but no command aggregates them. Today an agent (or a CI job, or a human at gate ④) assembles the picture by hand from five artifact formats. The verdict-evidence check in particular ("every verdict line must have a matching raw archive — a mechanical backstop against simulated reviews") exists only as prose; nothing enforces it.

Since 3.1.0, the binding gate has two forms (projected `verify --change` mid-change, plain `verify --specs` post-archive) — picking the right one is itself a rule an aggregator should encode.

## Goal (target state B)

`apriori gate --change <name>` — one read-only command, one exit code, aggregating the machine-checkable gate conditions for one change. It reuses the existing parsers and gates (status's flow-state/ledger parsers, spec-runner's verify, archive-merge's discovery) — it invents no new semantics.

**Explicitly NOT a human-gate substitute:** `GATE: PASS` means the mechanical face is clean; protected human gates (KB sign-off, shrink, intent-card) remain human. The output states this in one line.

## The checks

**Validation first (GREQ-4):** `--change` must match `CHANGE_NAME_RE` (bare kebab-case) — else exit 2; the resolved change dir must satisfy realpath containment inside its root (`apriori/changes/` for in-flight, `apriori/changes/archive/` for archived — `containsReal` semantics) — an escaping resolution exits 2 and reads nothing further.

**Stage resolution (GREQ-1):** the change dir is looked up at `apriori/changes/<name>/` (**in-flight**) or, failing that, among directories under `apriori/changes/archive/` whose basename matches EXACTLY `/^\d{4}-\d{2}-\d{2}T\d{4}-<name>$/`; candidates are sorted by full basename lexicographically (the stamp prefix makes that chronological) and the LAST is taken (**archived** — the gate-④-pending window; identical basenames cannot coexist in one directory, so there are no ties). Found in neither → exit 2 naming both searched locations. Flow-state and tasks.md are read from the resolved dir; the ledger is ALWAYS `<cwd>/apriori/review/<name>-issues.md` regardless of stage (GREQ-7).

### C1 spec — binding gate (GREQ-6)

- Test command: `--test-cmd` if given, else the process-config `test-cmd` row (`configTestCmd(cwd)`); neither → usage error, exit 2 (same rule as `verify`).
- In-flight: internally the equivalent of `verify({ change: <name>, cwd: <cwd>, testCmd })` — projected verify, same code path incl. CAS and hygiene guards; default id-pattern only (`--id-pattern` is NOT exposed on gate this change — out of scope, documented).
- Archived: the equivalent of `verify({ specs: [<cwd>/apriori/specs], cwd: <cwd>, testCmd })` — the deltas are already merged.
- Classification: verify clean (exit-0 equivalent) → `✓` with `GREEN`; gaps (exit-1 equivalent) → blocked, detail counts red/unbound/orphan/unidentified/duplicates; untrustworthy (exit-2 equivalent: infra errors, projection failures, CAS mismatch) → **gate exit 2**, the verify errors printed as the check detail.

### C3 spec — flow-state legality (GREQ-2, ADV-G1)

- The flow-state file missing or unreadable at the resolved dir → **exit 2** (tier-aware checks are impossible without it).
- Parsing = the status module's `parseFlowState` semantics (inline `# comment` stripped from values).
- Required keys: `change`, `tier`, `track`, `lineage`, `current-step`. A missing required key → blocked naming it. `round`/`next-action` are not required by gate.
- `change` must equal the `--change` argument → else blocked (wrong file in the dir).
- Placeholder rule: a required value containing `<` or `>` is unfilled → blocked.
- `current-step` must be EXACTLY one of (case-sensitive, after comment stripping): `STEP0 STEP1 STEP2 STEP3 STEP4 STEP5 STEP6 INTENT-CARD SPIKE EXTRACTION DONE ABANDONED` → else blocked.
- `tier` must be one of `trivial medium large` (this value drives C2/C4 applicability) → else blocked.

### C5 spec — verdict evidence (GREQ-3)

- Doc set: files matching `apriori/review/<name>-*.md` and `apriori/design/<name>-review-v*.md`, excluding `<name>-issues.md` and any file whose stem ends `-raw`. Only REGULAR files count; a symlink matching the doc globs → C5 blocked naming it (an excluded-by-type verdict doc must never silently drop out of the evidence check).
- VERDICT detection: any line matching `/^VERDICT:/` (line start, exact case).
- Raw rule: for a VERDICT-bearing doc with stem S (basename minus `.md`), at least one REGULAR file must exist matching `apriori/review/S-raw.*` whose realpath is inside `apriori/review/`. Multiple matching raws are allowed (any one satisfies). Missing → blocked naming the doc.

### C6 spec — KB freshness (GREQ-5)

- Module set: `<m>` = first path segment of each delta-spec suffix under the resolved change dir's `specs/` (`.md` files only). No specs dir / no files → C6 `–` ("no delta specs to map").
- Preconditions per module, each failing → `–` with the reason (never a block): `apriori/truth/<m>.md` exists; it carries a `source-commit: <c>` line; `lib/<m>.js` exists; the `git` binary is invocable.
- Check: `git -C <cwd> log --oneline <c>..HEAD -- lib/<m>.js` (no timeout; local). Exit 0 + empty stdout → `✓` for that module. Exit 0 + non-empty stdout → **blocked**, detail = the commit count and `<m>`. Non-zero exit (invalid commit, shallow history, not a repo, detached oddities) → `–` with git's first stderr line — an infra failure must never fabricate a block.
- C6 overall: blocked if any module blocked; `✓` if ≥1 module checked clean and none blocked; `–` otherwise.

## Output & CLI contract

- One line per check: `✓` / `✗ (reason)` / `– (why not applicable)`; final line `GATE: PASS — mechanical checks only; human gates remain human` or `GATE: BLOCKED (<n> item(s))`.
- `apriori gate --change <name> [--test-cmd "<cmd>"] [--cwd <dir>] [--json]`. `--json` → `{ change, stage: "in-flight"|"archived", checks: [{id, status: "pass"|"blocked"|"n/a", detail}], result: "PASS"|"BLOCKED", blocked: <n> }` (stdout pure JSON in every outcome; errors also as check details).
- Exit: **0** PASS · **1** BLOCKED · **2** change not found in either location / flow-state file unreadable / C1's verify itself exits 2 / usage error (`--change` missing).
- Read-only: gate writes nothing, ever.
- `gate` joins the subcommand list in `apriori --help` and the CLI spec.

## Acceptance criteria (testable)

- A1. In-flight change, all conditions met → every check `✓`, `GATE: PASS`, exit 0.
- A2. One unchecked task → C2 `✗`, `GATE: BLOCKED (1 item(s))`, exit 1; the failing check names the file.
- A3. Ledger with an `open` row → C4 blocked naming the row ID; a `rejected` row with a reason does not block; a bare `rejected` row blocks.
- A4. Placeholder tier (`<trivial | medium | large>`) in flow-state → C3 blocked; a legal filled flow-state passes.
- A5. A VERDICT-bearing review doc whose `S-raw.*` sibling is missing → C5 blocked naming the doc; adding the raw file flips it to `✓`; a symlinked doc-glob match blocks naming the symlink.
- A6. In-flight stage runs the projected verify (a delta-only scenario with a bound test passes C1 in-flight; the same store WITHOUT projection would report it unbindable); archived stage (change dir only under `changes/archive/`) runs plain verify and resolves flow-state/tasks from the archived path.
- A7. Change found nowhere → exit 2 naming both searched locations; invalid name (`../x`) → exit 2 before any read; two archived dirs for the same name → the lexicographically last basename is used (deterministic).
- A7b. Missing/unreadable flow-state at the resolved dir → exit 2; flow-state whose `change` key mismatches `--change` → C3 blocked.
- A8. Trivial tier without tasks.md and without ledger → C2 and C4 report `–`, not blockers.
- A9. C6: a truth doc whose `source-commit` predates a later commit touching `lib/<m>.js` → blocked with the commit count; up-to-date stamp → `✓`; no git / bad commit (non-zero git exit) / no truth doc / no lib file → `–` with the reason, never a block.
- A10. `--json` parses as JSON for PASS, BLOCKED, and exit-2 outcomes; shape as contracted above.
- A11. Zero-dep constraint holds; no behavior change to any existing subcommand.

## Out of scope (won't do)

- Wiring gate into CI config (docs may mention the one-liner; the workflow file is untouched this change).
- Judging raw-archive CONTENT authenticity (that is P8's/the human's job — C5 checks existence only).
- Environment/onboarding checks (roadmap item 4, `apriori doctor`).
- Any write action, any auto-fix.
- Gate for multiple changes at once (`gate` takes exactly one `--change`).

## Decisions proposed (for review)

- D1. Raw-naming convention becomes normative going forward: a review doc with stem S archives its raw as `apriori/review/S-raw.*` (the runbook's R2 wording gets this precision; older changes with divergent names simply predate the rule — gate is for current/future changes).
- D2. C6's module mapping (`suffix top segment` → `lib/<m>.js`) is convention-based and degrades to `–` when the convention doesn't hold, never to a false block.
- D3. The `open` status rule is `/^open\b/i` — byte-compatible with the status module's parser (one rule, two consumers).
