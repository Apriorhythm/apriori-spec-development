# Design — gate-command

## Module layout

New `lib/gate.js`; consumes `./status` (parseFlowState, parseLedger), `./spec-runner` (verify, configTestCmd), `./archive-merge` (CHANGE_NAME_RE, containsReal). No module requires gate (leaf). `bin/apriori.js` adds the `gate` case + USAGE line.

## Core function

`runGate({ cwd, change, testCmd })` → `{ code, stage, checks: [{id, status: 'pass'|'blocked'|'n/a', detail}], result, blocked, errors }` — pure return; `cli(argv)` maps flags, prints text or JSON, returns `code`. Everything below happens inside runGate:

1. **Validate:** change present + CHANGE_NAME_RE, else `{code:2, stage:null, result:'ERROR'}`.
2. **Resolve stage:** in-flight dir `<cwd>/apriori/changes/<name>` (with `containsReal(<cwd>/apriori/changes, dir)`); else archived: `readdirSync(<cwd>/apriori/changes/archive)` filtered by `^\d{4}-\d{2}-\d{2}T\d{4}-<name>$`, sorted, last (containment likewise). Neither → code 2 naming both.
3. **Flow-state:** read `<dir>/flow-state.md`; unreadable → code 2. `parseFlowState` → C3 rules (required keys, placeholders `<`/`>`, exact enums, change==--change). tier drives C2/C4 applicability.
4. **C1:** testCmd = opts.testCmd || configTestCmd(cwd); missing → code 2 (usage). In-flight: `verify({change, cwd, testCmd})`; archived: `verify({specs:[<cwd>/apriori/specs], cwd, testCmd})`. Consume the run OBJECT: `run.errors.length` → code 2, errors surfaced; else clean → pass (detail GREEN), else blocked with counts (red/unbound/orphan/unidentified/duplicates).
5. **C2:** `<dir>/tasks.md`; absent → tier==trivial ? n/a : blocked; else count `/^\s*-\s\[\s\]/m` matches (checked = `[xX]`).
6. **C4:** ledger `<cwd>/apriori/review/<name>-issues.md`; absent → trivial ? n/a : blocked; rows via parseLedger; block on `/^open\b/i`; block on `/^rejected\b/i` rows failing the reason rule (status must contain a word character beyond `rejected`, i.e. `/^rejected\b\s*\S/i` — where the `\S` begins actual reason text, punctuation-then-text accepted).
7. **C5:** doc set = glob `apriori/review/<name>-*.md` + `apriori/design/<name>-review-v*.md`, minus `<name>-issues.md`, minus stems ending `-raw`; lstat: symlink → blocked; regular file with `/^VERDICT:/m` → require ≥1 regular file `apriori/review/<stem>-raw.*` (realpath inside apriori/review). 
8. **C6:** modules = first segments of `.md` suffixes under `<dir>/specs/`; per module the precondition ladder (truth doc, source-commit line, lib/<m>.js, git spawn) → n/a reasons; `spawnSync('git', ['-C', cwd, 'log', '--oneline', `${c}..HEAD`, '--', `lib/${m}.js`])`; status 0 + empty → pass; status 0 + output → blocked (count); non-zero → n/a with first stderr line.
9. **Aggregate:** any blocked → result BLOCKED, code 1; else PASS, code 0. Checks that returned n/a don't affect either. Text output: one line per check, final `GATE: PASS — mechanical checks only; human gates remain human` / `GATE: BLOCKED (n item(s))`.

JSON: exactly the req-final shape; in text mode errors go to stderr.

## Read-only discipline

gate performs zero writes: no temp files (verify's projection is in-memory), no mkdir. Test asserts a full before/after tree fingerprint (path+size+mtime) is unchanged, C1's test command being a `node -e` echo (side-effect-free).

## Tests (test/gate.test.js)

Fixture builder mkProject as in archive-change.test.js; tapCmd helper. In-process `runGate` for most checks (fast, inspectable); spawn BIN for CL-09 and exit codes/usage/JSON purity. Git-dependent GT-10: build a throwaway git repo in the fixture (git init + commits); skip-guard ONLY the git-unavailable branch — the n/a branches (no truth doc / no lib file) need no git at all and always run.

## Docs

README/README_cn cheat-sheet row for `gate`. RUNBOOK §1 enforcement-layers: the "verdict-evidence check" clause can now name `apriori gate --change` as the deterministic implementation (EN+CN, one clause each). No prompt changes.

## Background — the problem (current state A)

The runbook's exit conditions for a change are individually machine-checkable — `verify` GREEN, tasks.md all `[x]`, a legal flow-state, a ledger with no open rows, every `VERDICT:` line backed by a raw archive (§1 enforcement layer ①), fresh KB stamps — but no command aggregates them. Today an agent (or a CI job, or a human at gate ④) assembles the picture by hand from five artifact formats. The verdict-evidence check in particular ("every verdict line must have a matching raw archive — a mechanical backstop against simulated reviews") exists only as prose; nothing enforces it.

Since 3.1.0, the binding gate has two forms (projected `verify --change` mid-change, plain `verify --specs` post-archive) — picking the right one is itself a rule an aggregator should encode.

## Goal (target state B)

`apriori gate --change <name>` — one read-only command, one exit code, aggregating the machine-checkable gate conditions for one change. It reuses the existing parsers and gates (status's flow-state/ledger parsers, spec-runner's verify, archive-merge's discovery) — it invents no new semantics.

**Explicitly NOT a human-gate substitute:** `GATE: PASS` means the mechanical face is clean; protected human gates (KB sign-off, shrink, intent-card) remain human. The output states this in one line.

## The checks

**Validation first (GREQ-4):** `--change` must match `CHANGE_NAME_RE` (bare kebab-case) — else exit 2; the resolved change dir must satisfy realpath containment inside its root (`apriori/changes/` for in-flight, `apriori/changes/archive/` for archived — `containsReal` semantics) — an escaping resolution exits 2 and reads nothing further.

**Stage resolution (GREQ-1):** the change dir is looked up at `apriori/changes/<name>/` (**in-flight**) or, failing that, among directories under `apriori/changes/archive/` whose basename matches EXACTLY `/^\d{4}-\d{2}-\d{2}T\d{4}-<name>$/`; candidates are sorted by full basename lexicographically (the stamp prefix makes that chronological) and the LAST is taken (**archived** — the gate-④-pending window; identical basenames cannot coexist in one directory, so there are no ties). Found in neither → exit 2 naming both searched locations. Flow-state and tasks.md are read from the resolved dir; the ledger is ALWAYS `<cwd>/apriori/review/<name>-issues.md` regardless of stage (GREQ-7).

### C1 spec — binding gate (GREQ-6)

- Test command: `--test-cmd` if given, else the process-config `test-cmd` row (`configTestCmd(cwd)`); neither → usage error, exit 2 (same rule as `verify`).
- In-flight: internally the equivalent of `verify({ change: <name>, cwd: <cwd>, testCmd })` — projected verify, same code path incl. CAS and hygiene guards; default id-pattern only (`--id-pattern` is NOT exposed on gate this change — out of scope, documented).
- Archived: the equivalent of `verify({ specs: [<cwd>/apriori/specs], cwd: <cwd>, testCmd })` — the deltas are already merged.
- Classification: verify clean (exit-0 equivalent) → `✓` with `GREEN`; gaps (exit-1 equivalent) → blocked, detail counts red/unbound/orphan/unidentified/duplicates; untrustworthy (exit-2 equivalent: infra errors, projection failures, CAS mismatch) → **gate exit 2**, the verify errors printed as the check detail.

### C3 spec — flow-state legality (GREQ-2, ADV-G1)

- The flow-state file missing or unreadable at the resolved dir → **exit 2** (tier-aware checks are impossible without it).
- Parsing = the status module's `parseFlowState` semantics (inline `# comment` stripped from values).
- Required keys: `change`, `tier`, `track`, `lineage`, `current-step`. A missing required key → blocked naming it. `round`/`next-action` are not required by gate.
- `change` must equal the `--change` argument → else blocked (wrong file in the dir).
- Placeholder rule: a required value containing `<` or `>` is unfilled → blocked.
- `current-step` must be EXACTLY one of (case-sensitive, after comment stripping): `STEP0 STEP1 STEP2 STEP3 STEP4 STEP5 STEP6 INTENT-CARD SPIKE EXTRACTION DONE ABANDONED` → else blocked.
- `tier` must be one of `trivial medium large` (this value drives C2/C4 applicability) → else blocked.

### C5 spec — verdict evidence (GREQ-3)

- Doc set: files matching `apriori/review/<name>-*.md` and `apriori/design/<name>-review-v*.md`, excluding `<name>-issues.md` and any file whose stem ends `-raw`. Only REGULAR files count; a symlink matching the doc globs → C5 blocked naming it (an excluded-by-type verdict doc must never silently drop out of the evidence check).
- VERDICT detection: any line matching `/^VERDICT:/` (line start, exact case).
- Raw rule: for a VERDICT-bearing doc with stem S (basename minus `.md`), at least one REGULAR file must exist matching `apriori/review/S-raw.*` whose realpath is inside `apriori/review/`. Multiple matching raws are allowed (any one satisfies). Missing → blocked naming the doc.

### C6 spec — KB freshness (GREQ-5)

- Module set: `<m>` = first path segment of each delta-spec suffix under the resolved change dir's `specs/` (`.md` files only). No specs dir / no files → C6 `–` ("no delta specs to map").
- Preconditions per module, each failing → `–` with the reason (never a block): `apriori/truth/<m>.md` exists; it carries a `source-commit: <c>` line; `lib/<m>.js` exists; the `git` binary is invocable.
- Check: `git -C <cwd> log --oneline <c>..HEAD -- lib/<m>.js` (no timeout; local). Exit 0 + empty stdout → `✓` for that module. Exit 0 + non-empty stdout → **blocked**, detail = the commit count and `<m>`. Non-zero exit (invalid commit, shallow history, not a repo, detached oddities) → `–` with git's first stderr line — an infra failure must never fabricate a block.
- C6 overall: blocked if any module blocked; `✓` if ≥1 module checked clean and none blocked; `–` otherwise.

## Output & CLI contract

- One line per check: `✓` / `✗ (reason)` / `– (why not applicable)`; final line `GATE: PASS — mechanical checks only; human gates remain human` or `GATE: BLOCKED (<n> item(s))`.
- `apriori gate --change <name> [--test-cmd "<cmd>"] [--cwd <dir>] [--json]`. `--json` → `{ change, stage, checks: [{id, status: "pass"|"blocked"|"n/a", detail}], result: "PASS"|"BLOCKED"|"ERROR", blocked: <n>, errors: [] }` where `stage` is `"in-flight"`, `"archived"`, or `null` (exit-2 outcomes before stage resolution). Exit-2 outcomes (GREQ-8): `result: "ERROR"`, `errors[]` carries the messages (same text as non-json stderr), `checks` lists whatever checks completed (possibly `[]`), `blocked` = count of blocked checks, `change` = the requested name or `null` when `--change` was missing entirely. Stdout is pure JSON in EVERY outcome when `--json` is given, usage errors included.
- Exit: **0** PASS · **1** BLOCKED · **2** change not found in either location / flow-state file unreadable / C1's verify itself exits 2 / usage error (`--change` missing).
- Read-only: gate writes nothing, ever.
- `gate` joins the subcommand list in `apriori --help` and the CLI spec.

## Acceptance criteria (testable)

- A1. In-flight change, all conditions met → every check `✓`, `GATE: PASS`, exit 0.
- A2. One unchecked task → C2 `✗`, `GATE: BLOCKED (1 item(s))`, exit 1; the failing check names the file.
- A3. Ledger with an `open` row → C4 blocked naming the row ID; a `rejected` row with a reason does not block; a bare `rejected` row blocks.
- A4. Placeholder tier (`<trivial | medium | large>`) in flow-state → C3 blocked; a legal filled flow-state passes.
- A5. A VERDICT-bearing review doc whose `S-raw.*` sibling is missing → C5 blocked naming the doc; adding the raw file flips it to `✓`; a symlinked doc-glob match blocks naming the symlink.
- A6. In-flight stage runs the projected verify (a delta-only scenario with a bound test passes C1 in-flight; the same store WITHOUT projection would report it unbindable); archived stage (change dir only under `changes/archive/`) runs plain verify and resolves flow-state/tasks from the archived path.
- A7. Change found nowhere → exit 2 naming both searched locations; invalid name (`../x`) → exit 2 before any read; two archived dirs for the same name → the lexicographically last basename is used (deterministic).
- A7b. Missing/unreadable flow-state at the resolved dir → exit 2; flow-state whose `change` key mismatches `--change` → C3 blocked.
- A8. Trivial tier without tasks.md and without ledger → C2 and C4 report `–`, not blockers.
- A9. C6: a truth doc whose `source-commit` predates a later commit touching `lib/<m>.js` → blocked with the commit count; up-to-date stamp → `✓`; no git / bad commit (non-zero git exit) / no truth doc / no lib file → `–` with the reason, never a block.
- A10. `--json` parses as JSON for PASS, BLOCKED, AND every exit-2 outcome class (usage error / invalid name / not found / unreadable flow-state / verify-untrustworthy) — `result: "ERROR"`, `stage: null` where resolution never happened; shape as contracted above.
- A11. Zero-dep constraint holds; no behavior change to any existing subcommand.

 * apriori status — answer "where am I / what's left" for a change.

const fs = require('fs');

// parse `key: value` lines from a flow-state file → object; plus the last gate line
function parseFlowState(text) {
  const out = {};
  for (const key of ['change', 'tier', 'track', 'current-step', 'round', 'next-action', 'lineage']) {
    const m = text.match(new RegExp('^' + key + ':\\s*(.+)$', 'm'));
    if (m) out[key] = m[1].replace(/\s*#.*$/, '').trim();
  }
  const gates = [...text.matchAll(/^\s*-\s*(\d{4}-\d{2}-\d{2}\S*\s+.+)$/gm)].map((m) => m[1].trim());
  out.lastGate = gates.length ? gates[gates.length - 1] : null;
  return out;
}

// parse a P0 ledger markdown table → rows with {id, status}
function parseLedger(text) {
  const rows = [];
  for (const line of text.split('\n')) {
    const m = line.match(/^\|\s*([^|]+?)\s*\|.*\|\s*([^|]+?)\s*\|\s*$/);
    if (!m) continue;
    const id = m[1].trim(), status = m[2].trim();
    if (id === 'ID' || /^-+$/.test(id)) continue;         // header / separator
    rows.push({ id, status });
  }
  return rows;
}

function activeChanges(root) {
  const dir = path.join(root, 'apriori', 'changes');
  if (!fs.existsSync(dir)) return [];
  return fs.readdirSync(dir, { withFileTypes: true })
    .filter((e) => e.isDirectory() && e.name !== 'archive')
    .map((e) => e.name).sort();
}

function changeStatus(root, change) {
  const fsPath = path.join(root, 'apriori', 'changes', change, 'flow-state.md');
  const state = fs.existsSync(fsPath) ? parseFlowState(fs.readFileSync(fsPath, 'utf8')) : null;
  const ledgerPath = path.join(root, 'apriori', 'review', `${change}-issues.md`);
  const rows = fs.existsSync(ledgerPath) ? parseLedger(fs.readFileSync(ledgerPath, 'utf8')) : [];
  const open = rows.filter((r) => /^open\b/i.test(r.status));

}

  const lines = [];
  if (!s.state) { lines.push(`change: ${s.change} (no flow-state file found)`); }
  else {
    lines.push(`change:       ${s.state.change || s.change}`);

/*
 * archive-merge — plain-files native implementation of the archive action (§4).
 * Zero deps — pure Node stdlib. Consumes the same delta format the OpenSpec adapter used
 * (## ADDED/MODIFIED/REMOVED/RENAMED Requirements), so it is the adapter-free path.

const fs = require('fs');
const path = require('path');
const crypto = require('crypto');

const REQ_RE = /^###\s+Requirement:\s+(.+?)\s*$([\s\S]*?)(?=^###\s+Requirement:|$(?![\s\S]))/gm;
const SECTION_SPLIT_RE = /^##\s+(ADDED|MODIFIED|REMOVED|RENAMED)\s+Requirements\s*$/m;
// the exact marker merge() injects on REMOVED; heading LINE of a deprecated block
const DEPRECATED_RE = /^###\s+Requirement:.*_deprecated \(superseded by [^)]*\)_/;
// a whole deprecated block (heading line + body up to the next requirement)
const DEPRECATED_BLOCK_RE = /^###[ \t]+Requirement:[^\n]*_deprecated \(superseded by [^)]*\)_[^\n]*$[\s\S]*?(?=^###[ \t]+Requirement:|$(?![\s\S]))/gm;

function stripDeprecatedBlocks(text) { return text.replace(DEPRECATED_BLOCK_RE, ''); }

// name -> full block (heading + body), in document order; duplicates reported (first block wins)
function parseRequirementsStrict(text) {
  const map = new Map();
  const duplicates = [];
  let m;
  REQ_RE.lastIndex = 0;
  while ((m = REQ_RE.exec(text)) !== null) {
    const name = m[1].trim();
    if (map.has(name)) duplicates.push(name);
    else map.set(name, m[0].replace(/\s+$/, '') + '\n');
  }
  return { map, duplicates };
}

function parseRequirements(text) { return parseRequirementsStrict(text).map; }

// ---- CAS base stamps -------------------------------------------------------

// sha256 over content with line endings normalized — a delta authored on Windows
// must fingerprint identically to the same store checked out with LF
function fingerprint(text) {
  const norm = text.replace(/\r\n/g, '\n').replace(/\r/g, '\n');
  return 'sha256:' + crypto.createHash('sha256').update(norm, 'utf8').digest('hex');
}

const STAMP_LINE_RE = /^<!--\s*apriori-base:\s*(\S+)\s*-->\s*$/gm;
// any standalone comment line ATTEMPTING to be a stamp — a malformed attempt must be an error,
// never silently treated as "unstamped" (that would quietly disable CAS)
const STAMP_ATTEMPT_RE = /^\s*<!--(?=[^>]*apriori-base)[^>]*-->\s*$/gm;

// → { stamp: 'sha256:<hex>' | 'new' | null, problems: [] }
// Exactly one stamp line, before the first delta section, well-formed digest.
function parseStamp(text) {
  const problems = [];
  const sectionIdx = text.search(SECTION_SPLIT_RE);
  STAMP_ATTEMPT_RE.lastIndex = 0;
  let m;
  while ((m = STAMP_ATTEMPT_RE.exec(text)) !== null) {
    STAMP_LINE_RE.lastIndex = 0;
    if (!STAMP_LINE_RE.test(m[0].trim())) problems.push(`malformed apriori-base stamp line: ${m[0].trim()}`);
  }
  const found = [];
  STAMP_LINE_RE.lastIndex = 0;
  while ((m = STAMP_LINE_RE.exec(text)) !== null) found.push({ value: m[1], index: m.index });
  if (!found.length) return { stamp: null, problems };
  if (found.length > 1) problems.push('carries more than one apriori-base stamp line');
  for (const f of found) {
    if (sectionIdx >= 0 && f.index > sectionIdx) problems.push('apriori-base stamp appears after the first delta section heading');
    if (f.value !== 'new' && !/^sha256:[0-9a-f]{64}$/.test(f.value)) problems.push(`malformed apriori-base stamp '${f.value}'`);
  }
  return { stamp: problems.length ? null : found[0].value, problems };
}

// ---- delta parsing ---------------------------------------------------------

// strict form: duplicate requirement names (within a section or across sections)
// and stamp problems are surfaced instead of silently collapsed
function parseDeltaStrict(text) {
  const problems = [];
  const buckets = { ADDED: new Map(), MODIFIED: new Map(), REMOVED: new Map(), RENAMED: [] };
  const seen = new Map();   // name -> first section carrying it
  const parts = text.split(SECTION_SPLIT_RE);
  for (let i = 1; i < parts.length; i += 2) {
    const kind = parts[i];
    if (kind === 'RENAMED') {
      for (const m of parts[i + 1].matchAll(/^\s*-\s*(.+?)\s*->\s*(.+?)\s*$/gm))
        buckets.RENAMED.push([m[1].trim(), m[2].trim()]);
    } else {
      const { map, duplicates } = parseRequirementsStrict(parts[i + 1]);
      for (const d of duplicates) problems.push(`duplicate requirement '${d}' in the ${kind} section`);
      for (const [name, block] of map) {
        if (seen.has(name)) problems.push(`duplicate requirement '${name}' appears in both ${seen.get(name)} and ${kind}`);
        else seen.set(name, kind);
        buckets[kind].set(name, block);
      }
    }
  }
  const st = parseStamp(text);
  problems.push(...st.problems);
  return { delta: buckets, stamp: st.stamp, problems };
}

function parseDelta(text) { return parseDeltaStrict(text).delta; }

function deltaOpCount(delta) {
  return delta.ADDED.size + delta.MODIFIED.size + delta.REMOVED.size + delta.RENAMED.length;
}

// Pure merge. Returns { store: Map, merged, modified, deprecated, renamed, conflicts, unchanged }
function merge(storeText, delta, change) {
  const parsed = parseRequirementsStrict(storeText);
  const store = parsed.map;
  const merged = [], modified = [], deprecated = [], renamed = [], conflicts = [], unchanged = [];
  // a corrupt store (same requirement name twice) must never be silently collapsed
  for (const d of parsed.duplicates) conflicts.push(`duplicate requirement '${d}' in the store (corrupt store)`);
  const renamedTargets = new Set();   // names created by THIS run's renames — an ADDED hitting one is a same-delta collision, never a rerun no-op
  // RENAMED first: rename the store block's ID, preserving its content
  for (const [oldName, newName] of (delta.RENAMED || [])) {
    if (!store.has(oldName)) {
      // rerun signature: source already gone AND target present → this rename already happened
      if (store.has(newName)) { unchanged.push(`${oldName} -> ${newName} (already renamed)`); continue; }
      conflicts.push(`RENAMED '${oldName}' has no target in store`); continue;
    }
    if (store.has(newName)) { conflicts.push(`RENAMED target '${newName}' already exists in store`); continue; }
    const block = store.get(oldName);
    const renamedBlock = block.replace(/^###\s+Requirement:\s+.+$/m, `### Requirement: ${newName}`);
    // rebuild the map preserving order, swapping the key at the old position
    const rebuilt = new Map();
    for (const [k, v] of store) rebuilt.set(k === oldName ? newName : k, k === oldName ? renamedBlock : v);
    store.clear();
    for (const [k, v] of rebuilt) store.set(k, v);
    renamed.push(`${oldName} -> ${newName}`);
    renamedTargets.add(newName);
  }
  for (const [name, block] of delta.ADDED) {
    if (store.has(name)) {
      // idempotent rerun: identical content means this delta already merged — a no-op, not a collision.
      // But a name just created by THIS run's RENAMED is a same-delta collision, never a rerun.
      if (!renamedTargets.has(name) && store.get(name).trim() === block.trim()) unchanged.push(name);
      else conflicts.push(`ADDED '${name}' already exists in store`);
    } else { store.set(name, block); merged.push(name); }
  }
  for (const [name, block] of delta.MODIFIED) {

      const depByThis = `${name}  _deprecated (superseded by ${change})_`;
      if (store.has(depByThis)) { unchanged.push(`${name} (already deprecated)`); continue; }
      const depOther = [...store.keys()].find((k) => k.startsWith(`${name}  _deprecated (superseded by `));
      if (depOther) { conflicts.push(`REMOVED '${name}' was already deprecated by a different change ('${depOther}')`); continue; }
      conflicts.push(`REMOVED '${name}' has no target in store`);
    } else {
      const block = store.get(name);
      const nl = block.indexOf('\n');
      store.set(name, block.slice(0, nl) + `  _deprecated (superseded by ${change})_` + block.slice(nl));
      deprecated.push(name);
    }
  }
  return { store, merged, modified, deprecated, renamed, conflicts, unchanged };
}

// Realpath containment: target (followed through symlinks; not-yet-existing targets judged
// by their nearest existing ancestor) must resolve STRICTLY inside root. Fail-closed.
function containsReal(root, target) {
  let realRoot;
  try { realRoot = fs.realpathSync(root); } catch { return false; }
  let cur = path.resolve(target);
  const rest = [];
  while (!fs.existsSync(cur)) {
    const parent = path.dirname(cur);
    if (parent === cur) return false;
    rest.unshift(path.basename(cur));
    cur = parent;
  }
  let realCur;
  try { realCur = fs.realpathSync(cur); } catch { return false; }
  const full = rest.length ? path.join(realCur, ...rest) : realCur;
  return full !== realRoot && (full + path.sep).startsWith(realRoot + path.sep);
}

}

**GSPEC-1 — C4 rejected-reason validation regex accepts reasonless punctuation**

Description: `requirement/req-final.md` requires rejected ledger rows to carry a reason beyond `rejected`; bare rejected statuses block. The design says C4 should require “a word character beyond `rejected`”, but then specifies `/^rejected\b\s*\S/i`. That regex accepts `rejected:` or `rejected.` because `\S` can be punctuation, so a reasonless rejected row can pass.

Risk: Correctness failure in a release gate. A change with an unresolved/reasonless rejection could be reported clean, causing a bad promotion decision.

Suggested fix: Specify the validation against the suffix after the `rejected` word. For example: strip `/^rejected\b/i`, trim the remaining text, and require at least one word/alphanumeric character in that suffix. This should accept `rejected: duplicate`, but reject `rejected`, `rejected:`, and `rejected -`.
