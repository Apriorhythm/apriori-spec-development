# Design — gate-command

## Module layout

New `lib/gate.js`; consumes `./status` (parseFlowState, parseLedger), `./spec-runner` (verify, configTestCmd), `./archive-merge` (CHANGE_NAME_RE, containsReal). No module requires gate (leaf). `bin/apriori.js` adds the `gate` case + USAGE line.

## Core function

`runGate({ cwd, change, testCmd })` → `{ code, stage, checks: [{id, status: 'pass'|'blocked'|'n/a', detail}], result, blocked, errors }` — pure return; `cli(argv)` maps flags, prints text or JSON, returns `code`. Everything below happens inside runGate:

1. **Validate:** change present + CHANGE_NAME_RE, else `{code:2, stage:null, result:'ERROR'}`.
2. **Resolve stage:** in-flight dir `<cwd>/apriori/changes/<name>` (with `containsReal(<cwd>/apriori/changes, dir)`); else archived: `readdirSync(<cwd>/apriori/changes/archive)` filtered by `^\d{4}-\d{2}-\d{2}T\d{4}-<name>$`, sorted, last (containment likewise). Neither → code 2 naming both.
3. **Flow-state:** read `<dir>/flow-state.md`; unreadable → code 2. `parseFlowState` → C3 rules (required keys, placeholders `<`/`>`, exact enums, change==--change). tier drives C2/C4 applicability.
4. **C1:** testCmd = opts.testCmd || configTestCmd(cwd); missing → code 2 (usage). In-flight: `verify({change, cwd, testCmd})`; archived: `verify({specs:[<cwd>/apriori/specs], cwd, testCmd})`. Consume the run OBJECT: `run.errors.length` → code 2, errors surfaced; else clean → pass (detail GREEN), else blocked with counts (red/unbound/orphan/unidentified/duplicates).
5. **C2:** `<dir>/tasks.md`; absent → tier==trivial ? n/a : blocked; else count `/^\s*-\s\[\s\]/m` matches (checked = `[xX]`).
6. **C4:** ledger `<cwd>/apriori/review/<name>-issues.md`; absent → trivial ? n/a : blocked; rows via parseLedger; block on `/^open\b/i`; block on `/^rejected\b/i` rows failing the reason rule: strip the leading `/^rejected\b/i`, trim the remainder, and require at least one WORD character (`/\w/`) in it — `rejected: duplicate` passes; `rejected`, `rejected:`, `rejected -` all block (punctuation alone is not a reason).
7. **C5:** doc set = glob `apriori/review/<name>-*.md` + `apriori/design/<name>-review-v*.md`, minus `<name>-issues.md`, minus stems ending `-raw`; lstat: symlink → blocked; regular file with `/^VERDICT:/m` → require ≥1 raw at `apriori/review/<stem>-raw.*` that is a REGULAR file by lstat FIRST (symlinked raws don't count as evidence), and whose realpath sits inside apriori/review. 
8. **C6:** modules = first segments of `.md` suffixes under `<dir>/specs/`; per module the precondition ladder (truth doc, source-commit line, lib/<m>.js, git spawn) → n/a reasons; `spawnSync('git', ['-C', cwd, 'log', '--oneline', `${c}..HEAD`, '--', `lib/${m}.js`])`; status 0 + empty → pass; status 0 + output → blocked (count); non-zero → n/a with first stderr line.
9. **Aggregate:** any blocked → result BLOCKED, code 1; else PASS, code 0. Checks that returned n/a don't affect either. Text output: one line per check, final `GATE: PASS — mechanical checks only; human gates remain human` / `GATE: BLOCKED (n item(s))`.

JSON: exactly the req-final shape; in text mode errors go to stderr.

## Read-only discipline

gate performs zero writes: no temp files (verify's projection is in-memory), no mkdir. Test asserts a full before/after tree fingerprint (path+size+mtime) is unchanged, C1's test command being a `node -e` echo (side-effect-free).

## Tests (test/gate.test.js)

Fixture builder mkProject as in archive-change.test.js; tapCmd helper. In-process `runGate` for most checks (fast, inspectable); spawn BIN for CL-09 and exit codes/usage/JSON purity. Git-dependent GT-10: build a throwaway git repo in the fixture (git init + commits); skip-guard ONLY the git-unavailable branch — the n/a branches (no truth doc / no lib file) need no git at all and always run.

## Docs

README/README_cn cheat-sheet row for `gate`. RUNBOOK §1 enforcement-layers: the "verdict-evidence check" clause can now name `apriori gate --change` as the deterministic implementation (EN+CN, one clause each). No prompt changes.

## Dogfood

Before archiving: `apriori gate --change gate-command` must print `GATE: PASS` against this very change (its own review docs satisfy C5's stem rule — the STEP2 raws of THIS change are named `gate-command-review-v{N}-raw.*` accordingly; C6 reports n/a for modules gate/cli, which have no truth docs — honest degradation).

## Background — the problem (current state A)

The runbook's exit conditions for a change are individually machine-checkable — `verify` GREEN, tasks.md all `[x]`, a legal flow-state, a ledger with no open rows, every `VERDICT:` line backed by a raw archive (§1 enforcement layer ①), fresh KB stamps — but no command aggregates them. Today an agent (or a CI job, or a human at gate ④) assembles the picture by hand from five artifact formats. The verdict-evidence check in particular ("every verdict line must have a matching raw archive — a mechanical backstop against simulated reviews") exists only as prose; nothing enforces it.

Since 3.1.0, the binding gate has two forms (projected `verify --change` mid-change, plain `verify --specs` post-archive) — picking the right one is itself a rule an aggregator should encode.

## Goal (target state B)

`apriori gate --change <name>` — one read-only command, one exit code, aggregating the machine-checkable gate conditions for one change. It reuses the existing parsers and gates (status's flow-state/ledger parsers, spec-runner's verify, archive-merge's discovery) — it invents no new semantics.

**Explicitly NOT a human-gate substitute:** `GATE: PASS` means the mechanical face is clean; protected human gates (KB sign-off, shrink, intent-card) remain human. The output states this in one line.

## The checks

**Validation first (GREQ-4):** `--change` must match `CHANGE_NAME_RE` (bare kebab-case) — else exit 2; the resolved change dir must satisfy realpath containment inside its root (`apriori/changes/` for in-flight, `apriori/changes/archive/` for archived — `containsReal` semantics) — an escaping resolution exits 2 and reads nothing further.

**Stage resolution (GREQ-1):** the change dir is looked up at `apriori/changes/<name>/` (**in-flight**) or, failing that, among directories under `apriori/changes/archive/` whose basename matches EXACTLY `/^\d{4}-\d{2}-\d{2}T\d{4}-<name>$/`; candidates are sorted by full basename lexicographically (the stamp prefix makes that chronological) and the LAST is taken (**archived** — the gate-④-pending window; identical basenames cannot coexist in one directory, so there are no ties). Found in neither → exit 2 naming both searched locations. Flow-state and tasks.md are read from the resolved dir; the ledger is ALWAYS `<cwd>/apriori/review/<name>-issues.md` regardless of stage (GREQ-7).

### C1 spec — binding gate (GREQ-6)

- Test command: `--test-cmd` if given, else the process-config `test-cmd` row (`configTestCmd(cwd)`); neither → usage error, exit 2 (same rule as `verify`).
- In-flight: internally the equivalent of `verify({ change: <name>, cwd: <cwd>, testCmd })` — projected verify, same code path incl. CAS and hygiene guards; default id-pattern only (`--id-pattern` is NOT exposed on gate this change — out of scope, documented).
- Archived: the equivalent of `verify({ specs: [<cwd>/apriori/specs], cwd: <cwd>, testCmd })` — the deltas are already merged.
- Classification: verify clean (exit-0 equivalent) → `✓` with `GREEN`; gaps (exit-1 equivalent) → blocked, detail counts red/unbound/orphan/unidentified/duplicates; untrustworthy (exit-2 equivalent: infra errors, projection failures, CAS mismatch) → **gate exit 2**, the verify errors printed as the check detail.

### C3 spec — flow-state legality (GREQ-2, ADV-G1)

- The flow-state file missing or unreadable at the resolved dir → **exit 2** (tier-aware checks are impossible without it).
- Parsing = the status module's `parseFlowState` semantics (inline `# comment` stripped from values).
- Required keys: `change`, `tier`, `track`, `lineage`, `current-step`. A missing required key → blocked naming it. `round`/`next-action` are not required by gate.
- `change` must equal the `--change` argument → else blocked (wrong file in the dir).
- Placeholder rule: a required value containing `<` or `>` is unfilled → blocked.
- `current-step` must be EXACTLY one of (case-sensitive, after comment stripping): `STEP0 STEP1 STEP2 STEP3 STEP4 STEP5 STEP6 INTENT-CARD SPIKE EXTRACTION DONE ABANDONED` → else blocked.
- `tier` must be one of `trivial medium large` (this value drives C2/C4 applicability) → else blocked.

### C5 spec — verdict evidence (GREQ-3)

- Doc set: files matching `apriori/review/<name>-*.md` and `apriori/design/<name>-review-v*.md`, excluding `<name>-issues.md` and any file whose stem ends `-raw`. ### C6 spec — KB freshness (GREQ-5)

- Module set: `<m>` = first path segment of each delta-spec suffix under the resolved change dir's `specs/` (`.md` files only). No specs dir / no files → C6 `–` ("no delta specs to map").

## Output & CLI contract

- One line per check: `✓` / `✗ (reason)` / `– (why not applicable)`; final line `GATE: PASS — mechanical checks only; human gates remain human` or `GATE: BLOCKED (<n> item(s))`.
- `apriori gate --change <name> [--test-cmd "<cmd>"] [--cwd <dir>] [--json]`. `--json` → `{ change, stage, checks: [{id, status: "pass"|"blocked"|"n/a", detail}], result: "PASS"|"BLOCKED"|"ERROR", blocked: <n>, errors: [] }` where `stage` is `"in-flight"`, `"archived"`, or `null` (exit-2 outcomes before stage resolution). Exit-2 outcomes (GREQ-8): `result: "ERROR"`, `errors[]` carries the messages (same text as non-json stderr), `checks` lists whatever checks completed (possibly `[]`), `blocked` = count of blocked checks, `change` = the requested name or `null` when `--change` was missing entirely. Stdout is pure JSON in EVERY outcome when `--json` is given, usage errors included.
- Exit: **0** PASS · **1** BLOCKED · **2** change not found in either location / flow-state file unreadable / C1's verify itself exits 2 / usage error (`--change` missing).
- Read-only: gate writes nothing, ever.
- `gate` joins the subcommand list in `apriori --help` and the CLI spec.
