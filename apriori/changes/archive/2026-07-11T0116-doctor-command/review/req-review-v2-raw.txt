## Background — the problem (current state A)

Onboarding failures surface piecemeal: `verify` hints zero-TAP only after a full run, `check` errors on a missing store, a stale runbook is a warn-line inside `check`, tool pointers silently vanish when a rules file is rewritten, and nothing at all checks the Node floor or reports half-initialized projects. The legacy-project lab logged this class of friction repeatedly: each command reports only the corner it can see. Roadmap item 4 (owner-ordered "先5后4"): one command that inspects the whole seam between a project and apriori, and says what is wrong and which existing command fixes it.

## Goal (target state B)

`apriori doctor` — a diagnosis command: seven read-only checks (plus ONE declared side effect: actually running the project's test command to probe TAP plumbing, skippable), each reporting `✓ / ✗ (finding, with the fix) / – (not applicable, with why)`, aggregated into one exit code. Doctor only diagnoses and points at the fixer (`apriori init` / `apriori update` / the human); it never repairs anything itself.

## Output & CLI contract

- `apriori doctor [--test-cmd "<cmd>"] [--no-run] [--cwd <dir>] [--json]`. No positional args; unknown flags follow the repo-wide convention (silently ignored — strictness is roadmap item 6).
- Text: one line per check; final line `DOCTOR: HEALTHY` / `DOCTOR: <n> finding(s)` / `DOCTOR: UNUSABLE (see errors)`.
- Exit: **0** healthy (findings = 0) · **1** ≥1 finding · **2** unusable (D1 below floor, D2 apriori/ missing entirely) — the exit-2 classes still print whatever checks already ran.
- `--json` (pure JSON stdout in EVERY outcome class): `{ result: "HEALTHY"|"FINDINGS"|"UNUSABLE", findings: <n>, checks: [{id, status: "ok"|"finding"|"n/a", detail, fix?}], errors: [] }` — `errors` carries the exit-2 messages; `checks` lists whatever ran before the abort.
- Read-only guarantee: doctor never creates/modifies/deletes any file; its ONLY side effect is executing the user's test command for D5, and `--no-run` removes even that.
- `doctor` joins `apriori --help` usage and the CLI spec's subcommand list.

## Acceptance criteria (testable)

- A1. A fully healthy initialized project (fresh `init` + valid test-cmd) → every applicable check `✓`/`–`, `DOCTOR: HEALTHY`, exit 0.
- A2. `apriori/` absent → exit 2, message contains `apriori init`, JSON `result: "UNUSABLE"` with D1 already listed in `checks`.
- A3. Missing runbook copy / missing `apriori/specs/` / missing `.gitignore` / missing `tmp/` dir → D2 findings naming each; a missing process-config → `–`, not a finding; with the runbook missing, D3 reports `–` (never a contradictory ✓).
- A4. A runbook copy differing from the packaged one by one byte → D3 finding naming `apriori update`.
- A5. A detected tool whose rules file lost its pointer, or a command-level tool missing its command file → D4 findings naming the tool and file; a project with no tool markers → D4 `–`.
- A6. D5, one case per classification: no test-cmd → `–`; `--no-run` → `–`; spawn failure → finding; signal kill → finding; `Bail out!` → finding; empty output → finding; non-TAP output → finding naming `--test-reporter=tap`; exit 7 with all-green TAP → finding ("unexplained"); failing TAP tests with matching non-zero exit → `✓`; `1..0` plan → `✓`.
- A7. D6: empty store → `–`; an ID-less scenario → finding listing it; a duplicate ID across files → finding listing it.
- A8. D7, concrete inputs (DREQ-5): an active change dir with NO flow-state.md → finding; one whose flow-state lacks a `change:` key → finding; one whose `change:` mismatches the dir name → finding; a healthy active change → no finding; an archived not-DONE change → informational mention only, never a finding.
- A9. `--json` parses as JSON for HEALTHY, FINDINGS, and UNUSABLE classes with the contracted shape.
- A10. Read-only: a doctor run (with `--no-run`) leaves the project tree byte-identical; with a `node -e` test command, the only executed side effect is that command itself.
- A11. Zero-dep constraint holds; no behavior change to any existing subcommand (doctor REUSES `checkRunbookFreshness`, `collectScenarios`, `zeroTapParsed`, `runTestCommand`, `configTestCmd`, `TOOLS`, `detectTools`, `activeChanges` — it duplicates none of them).

## Out of scope (won't do)

- Any repair/auto-fix action (each finding names its fixer; doctor never writes).
- Gate-style per-change verdicts (ledger/verify/evidence are `apriori gate`'s job — doctor stops at "flow-state parseable").
- check's handbook self-checks (`--self` remains check's).
- Node floor enforcement anywhere else (bin stays as-is; doctor only reports).
- `--id-pattern` for D6 (default pattern only; custom-pattern projects read D6's `–`/finding details accordingly — documented limitation, same stance as gate).
- CI wiring, engines field in package.json (release decision, not doctor's).

- D-DR-2: D7 never blocks on gate-④-pending archived changes — that state is legitimate (the §4 archive sequencing), so it is information, not a finding.

# TRUTH — status (`lib/status.js`, CLI subcommand `status`)

## Contract (code-is-truth)

source-commit: bd8aaec

**Responsibility.** Answer "where am I / what's left" for a change: read the flow-state file + the issue ledger, report step/next-action/open items. Read-only; zero deps.

**Public interface (module exports).**
- `parseFlowState(text)` → object with keys `change, tier, track, current-step, round, next-action, lineage` (each from a `key: value` line, inline `#` comment stripped, missing keys absent) plus `lastGate` = the last `- <YYYY-MM-DD…> …` bullet's text, or null.
- `parseLedger(text)` → `[{id, status}]` from P0 markdown table rows (header/separator rows skipped; id = col 1, status = LAST col).
- `activeChanges(root)` → sorted dir names under `<root>/apriori/changes/`, excluding `archive`; [] when the dir is missing.
- `changeStatus(root, change)` → `{ change, state (parsed flow-state or null), open (ledger rows with status starting "open", case-insensitive), hasFlowState }`. Flow-state read from `<root>/apriori/changes/<change>/flow-state.md`; ledger from `<root>/apriori/review/<change>-issues.md`.
- `formatOne(s)`, `toJson(s)` — human/machine shapes.
- `cli(argv)`: `[--change <name>] [--json]`; root = process.cwd(). Without `--change`: list actives. Always exit 0 (status never fails the build).

**Pitfalls.**
- `changeStatus` looks ONLY under `apriori/changes/<name>` — it does NOT find archived changes under `changes/archive/<stamp>-<name>/` (relevant while gate ④ is pending post-move).
- `parseFlowState` strips ` # comment` from values — a next-action containing a literal `#` would be truncated.
- `parseLedger` matches any `| a | … | b |` row shape — prose tables in the same file would be picked up too (ledger files carry only the one table by convention).
- Placeholder values (`<trivial | medium | large>`) parse as ordinary strings — callers must detect unfilled skeletons themselves.

- D-ST-1 (active): status is read-only and always exits 0 — it reports, never gates (gating is `apriori gate`'s job, shipped in gate-command 2026-07-11).

**Responsibility.** Bind spec scenario IDs to a TAP-emitting test run; report per-scenario red/green; act as STEP5's deterministic gate. Fail-closed: a broken or vacuous run is never GREEN. 3.1: `--change <name>` verifies against the in-memory PROJECTED store (archive's merge() applied to the living store) — the mid-change form.

- `leadId(text, idRe)` → leading ID or null. Word-boundary strict: `XX-01b`, `XX-01_x` are NOT `XX-01`.

- `mdFiles` is internal; `collectScenarios(specTargets, idRe)` → `{ byId, unidentified:[[file,title]], files, missingTargets, duplicates:[{id,files}] }`. A target may be a dir (recursed for `*.md`, sorted) or a single file (accepted as-is, ANY extension); dedupes overlapping targets. Scenario discovery matches exact h4 lines `#### Scenario: …` only. Scenarios inside DEPRECATED requirement blocks (heading carries `_deprecated (superseded by …)_`) are excluded in EVERY form — not demanded, not listed; their lingering tests turn ORPHAN.

Only lines shaped exactly `ok|not ok <n> - <name>` parse — a TAP result line without the ` - ` separator is ignored. `# SKIP`/`# TODO` counts as skip (proves nothing); untagged `not ok` without directive increments `untaggedFails`; `Bail out!` line captured.

**Issues By Dimension**

**1. Target State B Clarity**

DREQ-1 — D5 taxonomy still omits TAP version / nonzero-plan output with zero parsed results.

Description: D5 says it classifies every `runTestCommand` / TAP edge, but only blesses `1..0` as “empty suite — plumbing OK.” It does not classify `TAP version 13` with no plan/results, or `1..3` with no result lines. State A’s `zeroTapParsed` returns false for any TAP version or plan line, so this edge will not naturally fall into the existing non-TAP finding path.

Risk: A truncated or malformed TAP stream can be reported healthy by one implementation and as a finding by another.

Suggested fix: Add an explicit rule: `1..0` with zero parsed results is `✓`; any other TAP version/plan output with zero parsed results is a finding unless a specific alternative classification is intended.

DREQ-6 — Positional arguments are forbidden but not classified.

Description: The CLI contract says `apriori doctor [--test-cmd ...] [--no-run] [--cwd <dir>] [--json]` and “No positional args,” but it only defines behavior for unknown flags, which are silently ignored. It does not say whether `apriori doctor foo` is a usage error, silently ignored, or a finding.

Risk: CLI behavior and tests can diverge; accidental extra arguments may be ignored in one implementation and fail in another.

Suggested fix: Define an if/then rule for positional args, preferably exit 2 usage error with pure JSON under `--json`, or explicitly say positional args are silently ignored like unknown flags.
