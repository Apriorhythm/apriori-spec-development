## Background — the problem (current state A)

Onboarding failures surface piecemeal: `verify` hints zero-TAP only after a full run, `check` errors on a missing store, a stale runbook is a warn-line inside `check`, tool pointers silently vanish when a rules file is rewritten, and nothing at all checks the Node floor or reports half-initialized projects. The legacy-project lab logged this class of friction repeatedly: each command reports only the corner it can see. Roadmap item 4 (owner-ordered "先5后4"): one command that inspects the whole seam between a project and apriori, and says what is wrong and which existing command fixes it.

## Goal (target state B)

`apriori doctor` — a diagnosis command: seven read-only checks (plus ONE declared side effect: actually running the project's test command to probe TAP plumbing, skippable), each reporting `✓ / ✗ (finding, with the fix) / – (not applicable, with why)`, aggregated into one exit code. Doctor only diagnoses and points at the fixer (`apriori init` / `apriori update` / the human); it never repairs anything itself.

## The checks

| D2 | Init state | `apriori/` dir missing → **exit-2 class** with `run 'apriori init'`. Present: `apriori/runbook.md` present (✗ if missing); **`apriori/specs/` dir present (✗ if missing — half-initialized scaffold, DREQ-3)**; `apriori/process-config.md` present (– if missing: optional, defaults apply); `apriori/.gitignore` containing a `tmp/` line AND the `apriori/tmp/` dir existing (✗ if either missing) | `apriori init` / `apriori update` |

## Output & CLI contract

- `apriori doctor [--test-cmd "<cmd>"] [--no-run] [--cwd <dir>] [--json]`. Any POSITIONAL argument → usage error, exit 2 (pure JSON under `--json`) — doctor's audience is newcomers, a stray argument is a typo to surface, not to swallow (DREQ-6). Unknown `--flags` follow the repo-wide convention (silently ignored — strictness is roadmap item 6).
- Text: one line per check; final line `DOCTOR: HEALTHY` / `DOCTOR: <n> finding(s)` / `DOCTOR: UNUSABLE (see errors)`.
- Exit: **0** healthy (findings = 0) · **1** ≥1 finding · **2** unusable (D1 below floor, D2 apriori/ missing entirely, positional-arg usage error) — the exit-2 classes still print whatever checks already ran.
- `--json` (pure JSON stdout in EVERY outcome class): `{ result: "HEALTHY"|"FINDINGS"|"UNUSABLE", findings: <n>, checks: [{id, status: "ok"|"finding"|"n/a", detail, fix?}], errors: [] }` — `errors` carries the exit-2 messages; `checks` lists whatever ran before the abort.
- Read-only guarantee: doctor never creates/modifies/deletes any file; its ONLY side effect is executing the user's test command for D5, and `--no-run` removes even that.
- `doctor` joins `apriori --help` usage and the CLI spec's subcommand list.

## Acceptance criteria (testable)

- A1. A fully healthy initialized project (fresh `init` + valid test-cmd) → every applicable check `✓`/`–`, `DOCTOR: HEALTHY`, exit 0.
- A2. `apriori/` absent → exit 2, message contains `apriori init`, JSON `result: "UNUSABLE"` with D1 already listed in `checks`.
- A3. Missing runbook copy / missing `apriori/specs/` / missing `.gitignore` / missing `tmp/` dir → D2 findings naming each; a missing process-config → `–`, not a finding; with the runbook missing, D3 reports `–` (never a contradictory ✓).
- A4. A runbook copy differing from the packaged one by one byte → D3 finding naming `apriori update`.
- A5. A detected tool whose rules file lost its pointer, or a command-level tool missing its command file → D4 findings naming the tool and file; a project with no tool markers → D4 `–`.
- A6. D5, one case per classification: no test-cmd → `–`; `--no-run` → `–`; spawn failure → finding; signal kill → finding; `Bail out!` → finding; empty output → finding; non-TAP output → finding naming `--test-reporter=tap`; exit 7 with all-green TAP → finding ("unexplained"); failing TAP tests with matching non-zero exit → `✓`; `1..0` plan → `✓`; `TAP version 13` (or `1..3`) with zero result lines → finding ("truncated or malformed").
- A6b. `apriori doctor extra-arg` → exit 2 usage; with `--json` → pure JSON `result: "UNUSABLE"`.
- A7. D6: empty store → `–`; an ID-less scenario → finding listing it; a duplicate ID across files → finding listing it.
- A8. D7, concrete inputs (DREQ-5): an active change dir with NO flow-state.md → finding; one whose flow-state lacks a `change:` key → finding; one whose `change:` mismatches the dir name → finding; a healthy active change → no finding; an archived not-DONE change → informational mention only, never a finding.
- A9. `--json` parses as JSON for HEALTHY, FINDINGS, and UNUSABLE classes with the contracted shape.
- A10. Read-only: a doctor run (with `--no-run`) leaves the project tree byte-identical; with a `node -e` test command, the only executed side effect is that command itself.
- A11. Zero-dep constraint holds; no behavior change to any existing subcommand (doctor REUSES `checkRunbookFreshness`, `collectScenarios`, `parseTap`, `zeroTapParsed`, `runTestCommand`, `configTestCmd`, `TOOLS`, `detectTools`, `activeChanges` — it duplicates none of them).

## Out of scope (won't do)

- Any repair/auto-fix action (each finding names its fixer; doctor never writes).
- Gate-style per-change verdicts (ledger/verify/evidence are `apriori gate`'s job — doctor stops at "flow-state parseable").
- check's handbook self-checks (`--self` remains check's).
- Node floor enforcement anywhere else (bin stays as-is; doctor only reports).
- `--id-pattern` for D6 (default pattern only; custom-pattern projects read D6's `–`/finding details accordingly — documented limitation, same stance as gate).
- CI wiring, engines field in package.json (release decision, not doctor's).

# Design — doctor-command

## Module layout

New `lib/doctor.js` (leaf; nothing requires it); consumes `./init` (TOOLS, detectTools), `./check` (checkRunbookFreshness), `./spec-runner` (collectScenarios, parseTap, zeroTapParsed, runTestCommand, configTestCmd, DEFAULT_ID), `./status` (activeChanges, parseFlowState). `bin/apriori.js` adds the `doctor` case + USAGE line.

## Core function

`runDoctor({ cwd, testCmd, noRun })` → `{ code, result: 'HEALTHY'|'FINDINGS'|'UNUSABLE', findings, checks: [{id, status: 'ok'|'finding'|'n/a', detail, fix?}], errors }`; `cli(argv)` parses flags (positional arg anywhere → usage exit 2 BEFORE running), prints text or JSON, returns code. Check order D1→D7; the two exit-2 aborts (D1 floor, D2 apriori/ missing) push their own check entry first, then return with whatever ran (A2).

- **D1:** major = `parseInt(opts.nodeVersion || process.versions.node)` (injectable — DR-12's test seam) ≥ 18 → ok; else finding entry + UNUSABLE abort.
- **D2:** `apriori/` missing → finding entry + UNUSABLE abort naming `apriori init`. Else one sub-finding each: runbook.md, specs/ dir, .gitignore containing `/^tmp\/$/m`, tmp/ dir. process-config absent → part of the n/a detail.
- **D3:** runbook absent → n/a ("see D2"); else `checkRunbookFreshness(cwd)` → [] = ok, warn string = finding (fix `apriori update`).
- **D4:** `detectTools(cwd)`; none → n/a. Per tool: rules file exists AND contains `apriori/runbook.md` (init's own dedupe key); command-level: command file exists. Findings name tool + file, fix `apriori init`.
- **D5:** resolve testCmd (opts → configTestCmd); none → n/a hint; noRun → n/a "probe skipped". Else `runTestCommand(cmd, cwd)` then classify IN ORDER: exec.error → finding · exec.signal → finding · `Bail out!` (parseTap bailout) → finding · `!out.trim()` → finding "produced no output" · zeroTapParsed(...) → finding naming --test-reporter=tap · non-zero exit with parsed failCount 0 → finding "exit N unexplained by TAP" (classified BEFORE any ok branch — a non-zero `1..0` run is caught here, DSPEC-3) · TAP version/plan present but zero parsed results: plan `1..0` (exit 0) → ok "empty suite"; else → finding "truncated or malformed" · else ok with `${pass}p/${fail}f` info. (This ladder mirrors verify's infraErrors semantics via the same primitives — no reimplementation.)
- **D6:** specs dir missing → n/a "see D2"; `collectScenarios([specsDir], DEFAULT_ID_re)`: zero files/scenarios → n/a "empty store"; unidentified → finding listing (detail names DEFAULT_ID); duplicates → finding listing.
- **D7:** `activeChanges(cwd)`; per change: flow-state exists+readable, parseFlowState().change non-empty, === dir → info; else finding (failed clause named). Archived: dirs under changes/archive matching the stamp basename pattern, directories only (stat through symlinks), AND `containsReal(archRoot, dir)` before ANY read — an escaping symlinked entry becomes an info note and is never read (DSPEC-4); contained ones whose flow-state parses with current-step ∉ {DONE, ABANDONED} → appended to D7's detail as info. D7 status: finding if any clause failed, else ok (n/a when zero active changes and zero archived notes — "no changes yet").

Aggregate: `checks` may carry MULTIPLE entries with the same D-id (D2 emits one entry per gap; D4 one per broken tool); `findings` = count of finding-status entries — one model everywhere (spec DR-03, JSON contract, text output), per DSPEC-1.

### Requirement: doctor diagnoses the project-apriori seam
`apriori doctor` SHALL run seven read-only checks (D1 Node floor · D2 init scaffold · D3 runbook freshness · D4 tool pointers · D5 TAP probe · D6 store health · D7 changes overview), each reporting ok/finding/not-applicable with a fix hint on findings, and SHALL encode the aggregate in its exit code: 0 = zero findings (`DOCTOR: HEALTHY`), 1 = ≥1 finding (`DOCTOR: <n> finding(s)`), 2 = unusable (Node below floor, `apriori/` missing entirely, positional-arg usage error) — printing whatever checks already ran. Doctor never repairs and never writes; its ONLY side effect is D5 executing the project's test command once, removed by `--no-run`.

#### Scenario: DR-01 a healthy initialized project reports HEALTHY
- WHEN every applicable check passes on a freshly initialized project with a valid TAP test command
- THEN each check reports ok or not-applicable, the final line is `DOCTOR: HEALTHY`, and the exit code is 0

#### Scenario: DR-02 an uninitialized project is unusable, with guidance
- WHEN `apriori/` does not exist under the target root
- THEN doctor exits 2, the message names `apriori init`, and `--json` reports `result: "UNUSABLE"` with the already-run checks (D1) listed

#### Scenario: DR-04 runbook freshness points at update, and never contradicts D2
