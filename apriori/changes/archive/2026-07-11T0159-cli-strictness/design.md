# Design — cli-strictness

lib/args.js: `parseStrict(argv, {sub, usage, flags, positionals, aliases})` per the req contract — pure, returns `{ok:true, flags, positionals}` or `{ok:false, code:0|2, message}`. Kinds: 'value' | 'multi' | 'flag'. Alias map resolves before lookup ('-h'→'--help' built in, '-y' passed by init).

Migration per cli(): build its spec table (from req §Flag table), call parseStrict FIRST; code 0 → print usage stdout, return 0; code 2 → print message+usage stderr, return 2; ok → map parsed flags onto the existing local `a` object and proceed unchanged. Usage strings: each cli's existing usage text becomes a module-level const used by BOTH --help and error paths (DS-2). init: interactive branch decision unchanged (flags.tools absent && TTY). bin/apriori.js: no dispatch change (subcommands own their parsing); top-level behaviors untouched.

Tests (test/args.test.js): unit tests on parseStrict edges + spawn-BIN loops over all ten subs. CL-11 exercises BOTH `--help` and `-h`. CL-12: bare-tmp loop for all ten, PLUS sentinel fixtures for verify/gate/doctor — a valid project whose config test-cmd is `node -e "require('fs').writeFileSync('SENTINEL','x')"`; invoke with an unknown flag AND valid inputs, assert exit 2 + no SENTINEL (SSPEC-1). CL-17: spawn `apriori init` with no args non-TTY → its own `--tools` usage exit 2 (proving parseStrict passed through); the TTY picker itself is IN-10's existing binding. stampCli migrates like the rest: table {flags:{}, positionals:1} — `--foo` now dies as unknown flag before positional counting. Existing suite stays green (S5).
