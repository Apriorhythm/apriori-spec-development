# Requirement — cli-strictness (v1)

change: cli-strictness
target lineage: **v3 branch** (never merge to main or v2). Ships in the next minor (expected **3.3.0**) — it changes ERROR-path behavior only (what was silently ignored now fails loudly), which is the fail-closed direction; success-path behavior of every documented invocation is unchanged.

## Background — the problem (current state A)

Every subcommand parses argv with an ad-hoc loop that silently ignores anything it doesn't recognize. Consequences, all real today: `apriori verify --sepcs x` (typo) silently falls back to the config test-cmd and can verify the WRONG spec set while exiting green — fail-open in the one place the toolchain promises fail-closed; `apriori gate --hcange x` runs an unusable evaluation; no subcommand answers `--help` (users get usage only by triggering an error, exit 2). The top-level dispatcher handles `apriori --help`/`-h`/bare (usage, exit 0) and unknown SUBCOMMANDS (exit 2) correctly — the gap is inside the subcommands. `doctor` (3.2.0) already rejects stray positionals; nothing else does.

## Goal (target state B)

One shared argv-parsing helper; every subcommand gets three uniform behaviors:

1. **`--help` (and `-h`) → that subcommand's usage on stdout, exit 0** — checked before any other validation, works even where required args are missing.
2. **Unknown `--flag` (or `-x`) → stderr `unknown flag '<flag>' for 'apriori <sub>'` + that usage, exit 2.** Nothing silently ignored anymore.
3. **Positional arity enforced**: `new` and `stamp` take exactly one positional (existing behavior for count violations preserved/unified at exit 2); every other subcommand takes zero — a stray positional → stderr naming it + usage, exit 2 (doctor's existing rule generalized).

Known-flag behavior is byte-identical to 3.2.0 (same flags, same value consumption — including `verify --specs` consuming multiple values until the next `--` token, and `init`'s interactive path when `--tools` is absent).

## The helper (concrete contract)

`parseStrict(argv, spec)` where `spec = { sub: '<name>', usage: '<text>', flags: { '--name': 'value' | 'multi' | 'flag' }, positionals: 0 | 1, aliases?: {'-y': '--yes'} }` →
`{ ok: true, flags: {...}, positionals: [...] }` or `{ ok: false, code: 0|2, message }` (code 0 = help requested; the caller prints usage to stdout and returns 0; code 2 = the caller prints message + usage to stderr and returns 2).
- `'value'` consumes exactly the next token (missing value → exit 2 naming the flag); `'multi'` consumes tokens until the next `--`-prefixed token (verify `--specs` semantics); `'flag'` consumes nothing.
- `--help`/`-h` anywhere → `{ok:false, code:0}` immediately.
- The helper lives in one new file (`lib/args.js`), zero-dep, required by every cli().

## Acceptance criteria (testable)

- S1. For EVERY subcommand in {new, status, verify, archive, check, init, update, stamp, gate, doctor}: `apriori <sub> --help` prints usage containing `apriori <sub>` on stdout and exits 0 — a single loop-test over the full list.
- S2. For EVERY subcommand: `apriori <sub> --no-such-flag` exits 2 and stderr names `--no-such-flag` — same loop, and no subcommand performs its action (nothing written; verify/doctor run no test command).
- S3. Stray positional on a zero-positional subcommand (e.g. `apriori status extra`, `apriori verify extra`) → exit 2 naming `extra`; `new`/`stamp` keep their exactly-one rule (zero or two → exit 2).
- S4. A `'value'` flag at end of argv with no value (`apriori verify --test-cmd`) → exit 2 naming the flag, never consuming `undefined`.
- S5. Success paths unchanged: the existing full test suite (142 tests) passes unmodified EXCEPT tests that themselves relied on silent-ignore or count-mismatch semantics — each such modification listed in the delta. `verify --specs a b c --test-cmd x` still consumes three spec targets.
- S6. `--help` wins over other errors: `apriori verify --help` exits 0 even though `--specs`/`--test-cmd` are absent.
- S7. `init` with no flags on a TTY still enters the interactive multiselect (parseStrict passes empty flags through); `init --tools` at end of argv without a value → exit 2.
- S8. Zero new dependencies; the dispatcher's existing top-level behaviors (`apriori`, `apriori --help`, `apriori -v`, unknown sub) are unchanged.

## Out of scope (won't do)

- `--json` for subcommands that lack it; any new flags.
- Long-form docs (item 7's job); this change only guarantees every usage string is reachable via `--help`.
- Shell completion.
- Changing any KNOWN flag's semantics.

# TRUTH — archive-merge (`lib/archive-merge.js`, CLI subcommand `archive`)

## Contract (code-is-truth)

source-commit: 024ee2c

**Responsibility.** Merge a change's delta spec into the living store by stable Requirement ID (STEP6 archive action); move the change dir to `changes/archive/`. Zero deps. 3.1: also the home of the merge-family pure helpers shared with `verify --change` — delta discovery, projection building, CAS base stamps, realpath containment — plus the high-level `archive --change` transaction and the `stamp` subcommand.

**Delta format.** `## ADDED|MODIFIED|REMOVED|RENAMED Requirements` (h2 sections) containing `### Requirement: <name>` blocks (h3); RENAMED carries `- Old -> New` lines; optionally ONE CAS stamp line `<!-- apriori-base: sha256:<64hex> | new -->` before the first section. Parsing: `parseDeltaStrict(text)` → `{ delta, stamp, problems[] }` — duplicate requirement names (within/across sections) and stamp problems surface as problems; `parseDelta(text)` = its delta only; `parseRequirementsStrict(text)` → `{ map, duplicates[] }` (first block wins, duplicates reported); `parseRequirements` = its map; `deltaOpCount(delta)` → total parsed ops (0 = no recognized section OR recognized sections with no parseable requirement/rename lines). `parseStamp(text)` → `{ stamp, problems }` — any standalone comment line ATTEMPTING apriori-base that fails the strict form is a problem, never silently 'unstamped'. `fingerprint(text)` → `sha256:<64hex>` over CRLF/CR→LF-normalized content.

**Public interface.**
- `merge(storeText, delta, change)` — PURE. → `{ store:Map, merged, modified, deprecated, renamed, conflicts, unchanged }`. Duplicate requirement names in the STORE text → conflicts (corruption guard). Order of application: RENAMED first (in-place key swap preserving document order), then ADDED, MODIFIED, REMOVED.
  - ADDED on existing name: identical trimmed content → `unchanged` (idempotent rerun no-op) UNLESS the name was created by this run's RENAMED (`renamedTargets`) → conflict.
  - MODIFIED replaces the whole block; missing target → conflict.
  - REMOVED keeps the block, injects `_deprecated (superseded by <change>)_` into the heading line.
  - RENAMED with source gone + target present → `unchanged` ("already renamed" rerun signature); source gone + target absent → conflict; target already exists → conflict.
  - REMOVED with target gone but `<name>  _deprecated (superseded by <THIS change>)_` present → `unchanged` ("already deprecated" rerun signature); deprecated by a DIFFERENT change → conflict.
  - ANY conflict → nothing written (CLI exit 1).
- `renderStore(storeText, store)` — preserves the store's header (text before the first `### Requirement:`), then blocks joined with `\n`.
- `archiveStamp(d)` → `YYYY-MM-DDThhmm` (colon-free, CLI clock).
- `CHANGE_NAME_RE` = `/^[a-z0-9]+(-[a-z0-9]+)*$/` (same rule as `apriori new`).
- `archiveChangeDir(changesDir, name, now, ops?)` — validates name; realpath containment on BOTH source and destination (a symlinked `archive/` pointing outside is rejected before any move); `renameSync` (via ops when given) to `changes/archive/<stamp>-<name>/`; returns dest or null when source missing; throws on invalid name/escape.
- `containsReal(root, target)` — realpath containment; not-yet-existing targets judged by nearest existing ancestor; STRICT (root itself is not inside root); fail-closed on unreadable paths.
- `discoverDeltas(changesDirAbs, name)` → `{ files:[{abs,suffix}], errors[] }` — validates name (CHANGE_NAME_RE), change-dir existence + containment, specs/ itself containment-checked before becoming a root (symlinked specs/ rejected); walk follows symlink dirents explicitly (escaping links = errors, never silent skips). Errors are VALIDATION class → exit 2 on both surfaces.
- `buildProjection(storeRoot, deltaFiles, change)` → `{ texts:Map<suffix,text>, modules, perModule, conflicts, casMismatches, hygiene, validation }` — all store files pass through; each delta strict-parsed, CAS-checked, merged in memory; nothing touches disk.
- `archiveChange({cwd, change, changesDir, changesDirExplicit, write, ops})` → `{ code, out[], err[] }` — four phases: preflight (discovery+hygiene+CAS+merges+pre-existing-temp guard+destination containment; any failure → nothing written), stage (`<store>.tmp-archive`, this-run cleanup on failure), commit (sorted per-file atomic renames; mid-commit failure → exact committed/not-committed/temps report, NO rollback), move (only changesDirExplicit, only after all commits). `ops` ({writeFileSync,renameSync,rmSync}) is the fault-injection seam.
- `stampCli(argv)` — exactly one argv entry; absent file → `new` form; directory/unreadable → exit 2.
- `cli(argv)`: high-level form `--change <name> [--write] [--changes-dir <dir>]` (no --store/--delta) → archiveChange; single-file form `--store <FILE> --delta <FILE> --change <name> [--write] [--changes-dir <dir>]` unchanged from 3.0.1 EXCEPT it now checks a present CAS stamp (mismatch → exit 1, nothing written) and rejects malformed deltas via parseDeltaStrict problems. Mixing --change with only one of --store/--delta → exit 2. Exit: 0 merged/no-op · 1 conflict/CAS/hygiene/zero-op/stage/commit/move-failure/pre-existing-temp · 2 usage/invalid name/missing change dir/containment.

**Transactional write ordering (`--write`).** store staged to `<store>.tmp-archive` → dir move (atomic rename) → store committed via `renameSync(tmp, store)`. Move failure → tmp discarded, store byte-for-byte untouched. Limits: (a) tmp+rename gives single-file replace atomicity, NOT crash durability (no fsync on file or dir) — do not claim crash-durable; (b) the final `renameSync(tmp, store)` is NOT guarded — if it throws AFTER the change dir moved, the store is unchanged but the change dir is already archived and the tmp file is left behind (the "all or nothing" claim covers move failure, not store-commit failure after the move).

**Three moments.** The store file is the shared state: init = created on first `--write`; update = full rewrite via temp+rename; cleanup = none (grows monotonically; REMOVED deprecates, never deletes).

**Pitfalls.**
- `merge` compares ADDED blocks with `.trim()` equality — whitespace-only differences count as conflicts, not no-ops.
- `parseRequirementsStrict` keeps the FIRST duplicate block (previously last-wins) — visible only on invalid input, which now conflicts anyway.
- `renderStore` drops anything BETWEEN requirement blocks that isn't part of a block (inter-block prose is not preserved — only the pre-first-block header is). Needs human confirmation whether any store relies on inter-block prose (repo's own stores do not).
- CAS stamps are OPT-IN: an unstamped delta merges without any divergence check (pre-3.1 behavior preserved).
- Deprecation rewrites the heading LINE (`### Requirement: Name  _deprecated (superseded by x)_`), so on re-parse the requirement's map KEY includes the marker — MODIFIED/RENAMED can no longer address the block by its original name. (REMOVED reruns by the SAME change are now a no-op signature; see merge().) `DEPRECATED_RE`/`stripDeprecatedBlocks` exported — spec-runner uses them to exclude deprecated blocks from scenario collection.
- Unknown CLI flags silently ignored (roadmap item 6).

- D-AM-2 (superseded-by: D-AM-7): archive rerun idempotency as ratified in 3.0.1 covered two signatures — identical-content ADDED, and RENAMED source-gone+target-present.

- D-AM-4 (active): REMOVED deprecates in place (audit trail), never physically deletes.

// print the CAS stamp line for a store file's current content
function stampCli(argv) {
  if (argv.length !== 1) { console.error('usage: apriori stamp <store-file>'); return 2; }   // exactly one argument, no flags
  const p = argv[0];
  if (!fs.existsSync(p)) { console.log('<!-- apriori-base: new -->'); return 0; }
  if (fs.statSync(p).isDirectory()) { console.error(`stamp: ${p} is a directory, not a store file`); return 2; }
  let text;
  try { text = fs.readFileSync(p, 'utf8'); }
  catch (e) { console.error(`stamp: cannot read ${p}: ${e.message}`); return 2; }
  console.log(`<!-- apriori-base: ${fingerprint(text)} -->`);
  return 0;

// Scaffold apriori/changes/<name>/flow-state.md. Returns {ok, path?|error?}.
function scaffoldChange(root, name, now) {
  if (!name || !NAME_RE.test(name)) return { ok: false, error: `invalid change name '${name}' — use bare kebab-case (e.g. add-playback); dates are stamped at archive time, not here` };
  if (/^\d{4}-\d{2}/.test(name)) return { ok: false, error: `'${name}' looks date-prefixed — in-flight names are bare; dates are stamped at archive time, not here` };
  if (name === 'archive') return { ok: false, error: `'archive' is reserved for apriori/changes/archive/` };
  const dir = path.join(root, 'apriori', 'changes', name);
  if (fs.existsSync(dir)) return { ok: false, error: `change '${name}' already exists at ${path.relative(root, dir)}` };
  fs.mkdirSync(path.join(dir, 'specs'), { recursive: true });
  const flow = path.join(dir, 'flow-state.md');
  fs.writeFileSync(flow, flowStateSkeleton(name, now));
  return { ok: true, path: path.relative(root, flow) };
}

  if (!r.ok) { console.error(`  ✗ ${r.error}`); return 1; }

  return 0;
}
