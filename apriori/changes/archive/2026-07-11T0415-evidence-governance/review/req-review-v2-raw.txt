## Background — the problem (current state A)

Review raws (full reviewer transcripts at `apriori/review/*-raw.*`) are the workflow's audit evidence: `gate` C5 requires their EXISTENCE, but nothing governs their CONTENT or lifecycle. Three gaps: (1) a transcript can carry whatever the reviewer saw — including secrets from env output or config files — and lands in the repo ungoverned (SECURITY.md §Review evidence currently just warns); (2) raws carry no machine-readable provenance (provider/model/session/date live scattered in filenames and flow-state prose); (3) no retention rule exists — nothing says raws are audit evidence to keep, as opposed to `apriori/tmp/` instruments to drop.

## Goal (target state B)

1. **Secret scan as a check** — `check` (CONSUMER mode) gains CK-10 over `apriori/review/` — RECURSIVE, REGULAR FILES only (a symlink is skipped with a warn line naming it; the dir absent → the check skips): exactly three literal-format patterns, each with an airtight no-legit-match argument — AWS access keys `AKIA[0-9A-Z]{16}`, GitHub tokens `gh[pousr]_[A-Za-z0-9]{36,}`, PEM private-key headers `-----BEGIN [A-Z ]*PRIVATE KEY-----`. A hit FAILs naming file + line number + pattern class, never echoing the matched value. This is a tripwire, not a DLP product (declared limit); no fuzzy/entropy/assignment patterns — they false-positive on code discussion, which trains people to ignore the tripwire.
2. **Provenance header convention** — the runbook's R2 transcription rule gains one sentence (EN/CN) specifying the LITERAL header, prepended when the facts are known (unknown fields written `unknown`, order fixed, ISO date):

```text
<!-- provenance: provider=<name> model=<id> session=<id> date=<YYYY-MM-DD> -->
```

One line, HTML-comment form (safe in .md and .txt raws alike). Older raws grandfathered — convention, not a gate (retrofitting a hard check onto hundreds of existing raws would be noise).
3. **Retention clause** — runbook §4 artifact-interface gains one bullet (EN/CN): review raws under archived changes are AUDIT EVIDENCE — kept with the archive, never pruned; `apriori/tmp/` remains the only ephemeral space; secrets must never enter raws (point at CK-10 and the SECURITY.md guidance to sanitize BEFORE landing, since git history retains what was ever committed).

RUNBOOK.md:240:- **The spec-runner gate (`apriori verify`).** Mid-change, the gate is the **projected** form: `apriori verify --change <name> --test-cmd "<your test command>"` applies the change's delta specs to the living store in memory (the same `merge()` archive will run — MODIFIED replaces, REMOVED stops demanding, RENAMED demands the post-rename picture) and binds scenarios against that candidate store; scanning the raw store misses new scenarios, and scanning store+change double-counts MODIFIED.
