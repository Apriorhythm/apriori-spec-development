# Design — delta-consumption

Rewrite parseDeltaStrict as a line walker (replacing the split()-based body; parseStamp folds in for position-aware stamp problems):
Line normalization FIRST: split on `/\r?\n/` is NOT used — instead split on `\n` and strip one trailing `\r` from each line before matching (CRLF inputs parse identically to LF; accumulated body text keeps the normalized form, consistent with the old regexes which tolerated the trailing `\r` via `\s*$`). Fence rule: only a line whose first non-whitespace characters are ``` (three-plus backticks at line start after optional indent) toggles opacity — inline backticks never toggle. Line numbers in problems are 1-based over the split lines. (DCSPEC-3)
state = FILE_PREAMBLE | IN_SECTION(kind) | IN_REQUIREMENT(kind, title) | SKIP_UNRECOGNIZED. Per normalized line:
- fence content → skip
- legal section heading: EXACTLY `/^##\s+(ADDED|MODIFIED|REMOVED|RENAMED)\s+Requirements\s*$/` tested per normalized line (the existing SECTION_SPLIT_RE shape minus the `m` flag — the alternation stays grouped so `MODIFIED Requirements` without `## ` is NOT legal) → enter section (DCSPEC-4)
- `/^##\s/` otherwise → problems.push(`line N: unrecognized section heading '…'`), state = SKIP_UNRECOGNIZED (lines under it skipped until next legal heading; no per-line flood)
- `^### Requirement:` → FILE_PREAMBLE → problem (before any section); SKIP → covered by the section's one problem (no flood); RENAMED → problem; ADDED/MODIFIED/REMOVED → enter IN_REQUIREMENT (title dup-checked against the section's blocks). IN_REQUIREMENT accumulation reproduces the OLD grammar exactly: every subsequent line — including `#### Scenario:` headings and arbitrary prose — appends verbatim UNTIL the next `### Requirement:` heading or ANY `^##\s` line (legal or illegal section boundary: flush the current block FIRST, then process the heading) or EOF. The reassembled block (heading line + body, trailing whitespace trimmed + `'\n'` appended, matching the old `m[0].trim() + '\n'`) must be byte-identical to what REQ_RE produced for every well-formed delta; the D5 corpus test asserts parse-result equality old-vs-new over all archived deltas. (DCSPEC-2)
- `^#### Scenario:` while not inside a requirement body → problem (misplaced scenario) [file preamble or section preamble]
- RENAMED: `- Old -> New` parsed; other lines free text
- stamp lines matched in EVERY state, not just FILE_PREAMBLE. Attempt detection keeps the EXISTING broad shape — `/^\s*<!--(?=[^>]*apriori-base)[^>]*-->\s*$/` tested per normalized line (any standalone comment mentioning apriori-base, leading whitespace tolerated, missing colon included) — then validated against the strict STAMP_LINE_RE; the walker adds only line numbers and all-state detection, never narrowing what counts as an attempt (DCSPEC-5). Checked before body accumulation, outside fences: well-formed in FILE_PREAMBLE with no stamp yet → becomes the stamp; well-formed but AFTER the first section heading → problem `line N: apriori-base stamp after the first section`; second stamp anywhere → problem `line N: duplicate apriori-base stamp`; attempt that fails the strict format → problem `line N: malformed apriori-base stamp`. A late/dup/malformed stamp is consumed by its problem — never silently absorbed as preamble or requirement-body text. (DCSPEC-1)
Return shape unchanged: {delta, stamp, problems}. parseDelta/parseRequirementsStrict signatures untouched (store parsing unchanged).
Tests: AM-28..31 in test/archive-change.test.js + a corpus test iterating apriori/changes/archive/*/specs/**/*.md asserting zero problems. Existing delta tests must stay green (well-formed inputs identical).
