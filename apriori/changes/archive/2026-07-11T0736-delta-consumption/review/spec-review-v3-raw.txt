Line normalization FIRST: split on `/\r?\n/` is NOT used — instead split on `\n` and strip one trailing `\r` from each line before matching (CRLF inputs parse identically to LF; accumulated body text keeps the normalized form, consistent with the old regexes which tolerated the trailing `\r` via `\s*$`). Fence rule: only a line whose first non-whitespace characters are ``` (three-plus backticks at line start after optional indent) toggles opacity — inline backticks never toggle. Line numbers in problems are 1-based over the split lines. (DCSPEC-3)
state = FILE_PREAMBLE | IN_SECTION(kind) | IN_REQUIREMENT(kind, title) | SKIP_UNRECOGNIZED. Per normalized line:
- fence content → skip

- `/^##\s/` otherwise → problems.push(`line N: unrecognized section heading '…'`), state = SKIP_UNRECOGNIZED (lines under it skipped until next legal heading; no per-line flood)
- `^### Requirement:` → FILE_PREAMBLE → problem (before any section); SKIP → covered by the section's one problem (no flood); RENAMED → problem; ADDED/MODIFIED/REMOVED → enter IN_REQUIREMENT (title dup-checked against the section's blocks). IN_REQUIREMENT accumulation reproduces the OLD grammar exactly: every subsequent line — including `#### Scenario:` headings and arbitrary prose — appends verbatim UNTIL the next `### Requirement:` heading or ANY `^##\s` line (legal or illegal section boundary: flush the current block FIRST, then process the heading) or EOF.
