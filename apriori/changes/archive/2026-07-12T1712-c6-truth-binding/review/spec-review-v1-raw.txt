## 问题

### C6SPEC-1 — GT-19 没有完整绑定 `source-files` 的不可校验分类

**描述**：`req-final` 要求显式 `source-files` 的每个 token 都必须可校验：存在、regular file 或 directory、realpath-contained、非 symlink；任一 token 不可校验，包括 missing / malformed / escaping / dangling / symlink，都要 C6 BLOCKED。当前 GT-19 只明确覆盖 missing、symlink、escape，以及 partial/all symlink；没有绑定 malformed token、dangling symlink，也没有正向绑定 directory 是合法 source path。`design.md` 也只写“存在/常规文件或目录/realpath 收容/非 symlink”，没有给出 malformed token 的判定语法。

**风险**：实现可以漏掉 malformed 或 dangling 的 blocked 处理，或错误拒绝目录型 source path，仍通过 GT-19。这样显式声明的覆盖范围仍可能部分漏检。

**建议修复**：扩展 GT-19 和设计测试计划：加入 malformed repo-relative token（如 absolute、`..`、反斜杠等按需求定义）、dangling symlink、directory source path 的用例；设计中写明 malformed token 的判定规则和 blocked 消息要求。

### C6SPEC-2 — 设计把默认 source-files 绑到 truth 文件基名，和需求/规格冲突

**描述**：`req-final` 与 delta 正文都说 `source-files` 缺省为 `lib/<module>.js`。但 `design.md` 的 truth 索引方案写成 `source-files` 默认 `lib/<basename>.js`。这在异名 truth 场景会错：`apriori/truth/poll.md` 声明 `store-module: quick-poll` 且未声明 `source-files` 时，应检查 `lib/quick-poll.js`，不是 `lib/poll.js`。

**风险**：GT-18 要修的“truth 文件名 != store module”场景仍可能因默认路径用错而被 note/n/a 掉，C6 继续静默失效。

**建议修复**：设计改为：`parseTruthHeader()` 只返回 `storeModules` 与 `declaredSourceFiles|null`；在 per-module C6 循环里，若未显式声明 `source-files`，按当前 touched module 计算 `lib/${module}.js`。可在 GT-18 或 GT-21 加一个“异名 truth 无 source-files 声明仍默认到 store module 名”的子用例。

## Advisories

- GT-21 的“same verdict as before / byte-identical fallback”建议在设计里写清测试 oracle：用 field-less truth 的 stale/up-to-date/default-lib-missing fixture 断言旧 GT-10 的精确 C6 detail/status，而不是只断言“没有声明字段也能跑”。
- `design.md` 的 SPEC 触点写 “GT-21(冲突+回退不变)”，但冲突实际在 GT-18；建议改成 GT-18 conflict、GT-21 fallback，避免任务实现时误读。

## 核对无问题项

- Delta stamp 与 living `apriori/specs/gate/spec.md` 匹配。
- GT-01..09/11/12 在 MODIFIED 块中未见意外漂移；GT-10 改写方向与新增 C6 truth-index prose一致。
- `store-module` 索引、同 module 冲突、malformed `source-commit` 四样例、fenced exemption、missing-truth n/a、git unavailable/failure n/a-with-reason 都有场景覆盖。
