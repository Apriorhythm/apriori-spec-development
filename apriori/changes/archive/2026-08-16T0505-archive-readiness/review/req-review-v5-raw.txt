   191	### B7 — 安全读取层：archive 独有的一层，gate 一字不变（r1·REQ-1）
   192	
   193	**两层结构，职责分明：**
   194	
   195	- **基础层**（`lib/readiness.js`）：`checkFlowState` / `checkTasks` / `checkLedger` / `classifyStatus` /
   196	  `gatesEntries` / `waiveEvidence` / `reviewDirDefect` / `STEP_ENUM` / `TIER_ENUM` 原样搬入，
   197	  **行为逐字节等于状态 A 的 gate**（含裸读）。gate 改为从这里取，对外零变化。
   198	- **archive 层**（`lib/readiness.js` 的 archive-only 导出）：在调用基础层**之前**，
   199	  对每个 artifact 跑 **`artifactDefect(bundleDir, p)`**；台账另需**先**跑
   200	  **`reviewRootDefect(bundleDir)`** 再判叶子文件。
   201	  这两个函数是**本 change 新写的**，**不调用** `resolve.fileReadDefect`、也不调用基础层的
   202	  `reviewDirDefect`——理由见 B7a。

   204	#### B7a — 单趟分类，不得二次 `lstat`（r2·REQ-1 → r3·REQ-1 重写）
   205	
   206	`resolve.fileReadDefect` 与基础层 `reviewDirDefect` 的 `catch` **都不看 `e.code`**（§1.5）。
   207	**「外层先分类、再调用 helper」不成立**：helper 内部会**再 `lstat` 一次**并再次吞掉全部异常，
   208	于是 `EACCES` 仍被归成 `missing`，在 trivial 层判 `n/a`，archive 继续写——**fail-open 依旧存在**。
   209	
   210	因此 `artifactDefect` / `reviewRootDefect` SHALL 是**完整、单一**的分类路径：
   211	
   212	1. 对目标做**恰好一次** `fs.lstatSync`；
   213	2. 抛错且 **`e.code === 'ENOENT'`** → 走祖先探测（第 5 条），最终归 `{kind:'missing'}`；
   214	3. 抛错且 `e.code` **不是** `ENOENT`（`EACCES` / `EIO` / `ELOOP` / `ENOTDIR` / `ENAMETOOLONG` / …）
   215	   → `{kind:'io-error', code}`，**结构类**，不就绪，**不可 force**，诊断含原始 `e.code`；
   216	4. 不抛错 → 判 `symlink`，再按**对象类型分别判**（r4·REQ-1）：
   217	   - `artifactDefect`（`flow-state.md` / `tasks.md` / `review/issues.md`）用 **`isFile()`** → 否则 `not-file`
   218	     （规则照抄 `resolve.js:151-155`，**函数不复用**）；
   219	   - `reviewRootDefect`（`review/` 目录）用 **`isDirectory()`** → 否则 `not-dir`
   220	     （规则照抄状态 A 的 `gate.js:133`，**函数不复用**）。
   221	   **照抄文件规则到 review 根会恒定 `not-file`，拒绝每一个正常 bundle**——这是 r4 指出的第二条。
   222	   再判 `escape`（按 B7c 的分类版包含性）与 `bad-ancestor`；
   223	5. **祖先探测**（`ENOENT` 时上溯至 `bundleDir`）中的每次 `lstatSync` 适用**同一分类**：
   224	   非 `ENOENT` 的异常 → `io-error`，**不得**被吞成「继续上溯」；
   225	6. 本层若使用 `realpath`，其异常适用同一分类。
   226	
   227	**结果集**：
   228	- `artifactDefect` → `null` / `missing` / `io-error` / `symlink` / `not-file` / `escape` / `bad-ancestor`；
   229	- `reviewRootDefect` → `null` / `io-error` / `symlink` / `not-dir` / `escape`。
   230	
   231	只有 `artifactDefect` 的 **`missing`** 进入 tier 敏感分支；其余一律**结构类、不可 force**。
   232	
   233	**`review/` 目录不存在时 `reviewRootDefect` 返回 `null`**（r4·REQ-1）——与状态 A 的
   234	`reviewDirDefect`（`gate.js:132` 的 `catch { return null; }`）**一致**：
   235	review 根的缺席不是结构缺陷，它交给台账叶子的 `artifactDefect` 按 tier 规则处置。
   236	**因此本 change 不引入任何「review 根 missing」的新分类**，差分基准得以保持为状态 A。
   237	
   238	**为什么不改 `resolve.fileReadDefect`**：`lib/status.js:9` 在用它，改它会改变 `status` 的对外行为——
   239	那是本 change 的 out of scope（§五-4）。代价是约 20 行规则的重复，由 RY-08 的差分测试锁住。
   240	
   241	**基础层不做这件事**——它必须保持状态 A 的 gate 行为（RY-06）。
   242	
   243	#### B7b — 基础层的 `containsReal` 取用（r2·REQ-1）
   244	
   245	**基础层**的 `reviewDirDefect` SHALL 使用 **`require('./resolve').containsReal`**，
   246	**不得**使用 `archive-merge.js` 的那一份——后者会形成
   247	`archive-merge → readiness → archive-merge` 的环。
   248	两份实现只在 `target === root` 一格分歧，而此处 target 恒为 `<dir>/review`，
   249	故在该调用形态下行为一致（§1.5），须以差分测试证明（RY-07）。
   250	
   251	#### B7c — archive 层自带分类版包含性（r4·REQ-1）
   252	
   253	`resolve.containsReal` 的两个 `realpathSync` 都是 `catch { return false; }`（§1.5），
   254	它**无法区分** `EACCES` 与真正的逃逸，因此**产生不了** `io-error`。
   255	「先自行 realpath、再调 `containsReal`」也不是修复——那会**重新 realpath 一次**，
   256	重现 r3 指出的「第二次调用吞错」窗口。
   257	
   258	因此 archive 层 SHALL 自带一个分类版包含性判定 **`containDefect(root, target)`**：
   259	
   260	1. `realpathSync(root)` 与 `realpathSync(target)` **各调用一次**；
   261	2. 任一抛错且 `e.code === 'ENOENT'` → 交由调用点的 `missing` / 祖先探测逻辑处置；
   262	3. 任一抛错且 `e.code` **不是** `ENOENT` → `{kind:'io-error', code}`；
   263	4. 两者都成功 → `real === realRoot || real.startsWith(realRoot + path.sep)`
   264	   为真则 `null`，否则 `{kind:'escape'}`。
   265	
   266	`artifactDefect` / `reviewRootDefect` **只使用 `containDefect`**，
   267	**不得**调用 `resolve.containsReal`（RY-10 静态断言）。

   290	### B2 — 单文件形式：不再触碰 change bundle（r1·REQ-5 重写为可实现的算法）
   291	
   292	**用一句话陈述目标：单文件形式失去移动 bundle 的能力，也不再消费 bundle 内的 delta。**
   293	
   294	**B2a — `--changes-dir` 不再与单文件形式兼容。** 二者同时出现 → exit 2 + usage
   295	（与既有的「`--change` 不能只配 `--store`/`--delta` 之一」同类）。
   296	**推论：单文件形式此后永不移动任何目录**（移动本就只在 `--changes-dir` 显式给出时发生）。
   297	
   298	**B2b — `--delta` 落在规范 changes root 内 → 拒绝。** 算法（穷举、可直接实现）：
   299	
   300	1. `deltaAbs = path.resolve(cwd, <--delta 实参>)`（`path.resolve` 已规范化 `.` 与 `..`）。
   301	2. `rootAbs = path.resolve(cwd, 'apriori', 'changes')`。**只有规范 root**——显式 root 已被 B2a 吃掉。
   302	3. **词法量度**：`deltaAbs === rootAbs || deltaAbs.startsWith(rootAbs + path.sep)`。
   303	   用**路径段边界**，不用裸字符串前缀 → `apriori/changes-other/...` **不命中**。
   304	4. **realpath 量度**：对 `rootAbs` 与 `deltaAbs` 各取 `fs.realpathSync`；
   305	   - 任一取 realpath 失败（不存在 / 悬空 / 权限）→ **该量度不产生命中**（不是命中，也不是免罪），
   306	   - 两者都成功 → 按第 3 步同样的段边界判定。
   307	5. **两个量度任一命中即拒绝。** 皆不命中 → 落入既有行为（若 delta 本就不存在，仍由既有的
   308	   「delta 文件读不到」错误按状态 A 报，退出码不变）。
   309	
   310	**词法量度必须保留**：root 自身是 symlink 而调用方用词法路径书写时，realpath 量度会失配。
   311	**realpath 量度必须保留**：外部 symlink 指向 bundle 内 delta 时，词法量度会失配。
   312	
   313	**时机措辞（r1·REQ-5）**：判定发生在**读取 store 或 delta 的内容之前**；
   314	作用域判定本身所需的路径元数据读取（`path.resolve` / `realpathSync` / `lstat`）**不在此限**。
   315	
   316	**诊断必须给出替代命令**：`use the high-level form: apriori archive --change <name> [--changes-dir <dir>] [--write]`。
   317	
   318	**不落在 changes root 内的 `--delta`**（真正的单模块手术）——除 B2a 外行为不变（见 B5 的精确表述）。
   319	
   320	### B3 — `--force`：可 force 的类别是穷举的，且需要预存的人类证据（r1·REQ-2 / REQ-3）
   321	
   322	**可 force（进度类，穷举）：**
   323	
   324	- R2：`tasks.md` 存在且有 N 个未勾选框；
   325	- R3：台账行 status 为 `open`、`fixed`、或**带理由的** plain `rejected`（即 `classifyStatus` 判 `legal && hasReason`）。
   326	
   327	**不可 force（穷举）：**
   328	
   329	- **R1 的任何情形**（含 `ABANDONED`——RUNBOOK §283 的硬规则在代码层**没有旁路**）；
   330	- 任何**结构类**（B7 表中的 symlink / not-file / escape / bad-ancestor / 守卫后读取异常）；
   331	- **artifact 缺失**：medium/large 层缺 `tasks.md` 或缺台账；
   332	- 台账行 status **不在词汇表内**（格式问题，不是进度问题）；
   333	- `rejected` / `rejected-verified` / `waived` **缺理由**；
   334	- `waived` **缺 `gates:` 人类记录**——`--force` **不能**代替 waive 证据。
   335	
   336	**人类证据协议（r2·REQ-2 重写——按类绑定，且如实命名其有效期）**：
   337	
   338	`--force` 对某一类失败生效的前提是，bundle 的 `flow-state.md` 的 `gates:` 段里**预先存在**
   339	一条**按类具名**的记录：
   340	
   341	**锚定语法（r3·REQ-2 重写——完全消费、一条一类）**：一条记录的形态恰为
   342	
   343	```
   344	archive-force <class> <reason>
   345	archive-force-revoke <class> <reason>
   346	```
   347	
   348	- `<class>` 是**紧跟在 `archive-force` / `archive-force-revoke` 之后的那一个 token**，
   349	  且必须**恰好等于** `tasks` 或 `ledger`。**位置是锚定的**——不在这个位置的 `tasks`/`ledger` 一律不授权。
   350	- `<reason>` 是该 class token **之后的全部剩余文本**，必须含至少一个 `\w` 字符。
   351	- **一条记录只授权一个类。** 要同时越过 R2 与 R3，**必须写两条**。
   352	  → `archive-force tasks — ledger cleanup deferred` **只授权 `tasks`**；
   353	  理由正文里的 `ledger` 一词**不授予** ledger 类，也**不**被当作第二个类名（歧义消除）。
   354	- token 边界仍按 `(^|[^A-Za-z0-9-])<tok>([^A-Za-z0-9-]|$)`
   355	  （`archive-force-2 tasks` 不命中前缀；`archive-force tasks2` 的 class token 是 `tasks2` ≠ `tasks`，不命中）。
   356	
   357	**撤销：追加，不删除（r3·REQ-2 — `gates:` 是 append-only）**
   358	RUNBOOK `:212` 明写 `gates:` 是 **append-only log of human decisions**，
   359	因此「删除记录」不是合法的流程动作。撤销 SHALL 通过**追加**一条
   360	`archive-force-revoke <class> <reason>` 完成。
   361	
   362	- **同类以最后一条决定为准**：按 `gatesEntries()` 返回的顺序（= 文件中的出现顺序）
   363	  取该类的最后一条 `archive-force` / `archive-force-revoke`；
   364	  若最后一条是 revoke，则该类**未获授权**。
   365	- 只有 revoke 而无 grant → 未授权（无害）。
   366	
   367	- **有效期，如实陈述**：该记录是**该类在本 bundle 生命周期内持续有效的授权**（standing），
   368	  **不是**「本次运行」的证据——文件内容无法证明「本次」。
   369	  记录写下之后新出现的同类失败**会被同一条记录覆盖**，直到追加一条同类的 revoke。
   370	  **这是本协议已知的产品代价，须在 gate④ 如实呈报**；不把它包装成 per-run 证据。
   371	- **来源的准确表述**：该条目**记录一项先前的人类决定**（RUNBOOK 的机制是人类作决定、
   372	  agent 把其原话记进 flow-state）；文件本身**无法证明作者身份**。
   373	  它的作用是让 force 需要一次**独立于本次运行的、可审计的书面动作**，而不是身份证明。
   374	- 证据缺失时 `--force` **无效果**，archive 仍拒绝，并打印一段**可复制的模板**
   375	  （形如 `  - <date> gate⑤ (owner): archive-force tasks — <your reason>`）——
   376	  **不声称**打印人类尚未写下的理由全文。
   377	
   378	**输出格式**：force 生效时逐条打印被越过的项，一项一行，前缀 `forced: `；
   379	随后打印所引用的每条 `gates:` 记录的 **原始首行**（`flow-state.md` 中的字面文本，
   380	**不是** `gatesEntries()` 拼接续行后的规范化文本）。**不打印笼统的一句 "forced"。**
   381	
   382	**dry-run 与 write 的关系（r1·REQ-2 的矛盾修正）**：
   383	`--force` 在 dry-run 与 `--write` 中**同样改变就绪度结论**；**只有 `--write` 产生磁盘副作用**。
   384	
   385	**单文件形式与 `--force`（r1·REQ-3）**：`--force` **只出现在高层 usage**；
   386	单文件形式收到 `--force` → **exit 2 + usage**。这是 B5 的**唯一一处**兼容性例外，见 B5。
   387	
   388	### B4 — dry-run 说的就是 `--write` 会做的
   389	
   390	未就绪时 dry-run **不得**打印 `RESULT: MERGED (dry-run…)`，退出码 1，零写入。
   391	
   392	### B5 — 零变化的精确边界（r1·REQ-4 / REQ-3）
   393	
   394	- **既有 preflight 失败**（`discoverDeltas` 错误 / `buildProjection` validation / CAS 拒绝 / hygiene /
   395	  base 失配 / 同 ID 冲突 / `--write` 的预存温存文件 / 显式 root 的归档目的地包含性）时：
   396	  诊断与退出码**一字不变**，且就绪度**不被求值**。
   397	- **就绪的 bundle** 的成功输出（逐模块报告、MODIFIED 完整性报告、`RESULT: MERGED…`、移动路径）**一字不变**。
   398	- **单文件形式、delta 在 changes root 之外**：行为不变，**唯二例外**是
   399	  ① 同时传 `--changes-dir` → exit 2（B2a）；② 传 `--force` → exit 2（B3）。
   400	  两者在状态 A 分别是「合法组合」与「unknown flag exit 2」，本版把前者改为 exit 2、
   401	  后者保持 exit 2 但**改变诊断文本**。这两处例外**必须逐条写进 CHANGELOG**。
   402	
   403	### B6 — 精确调用序（r1·REQ-4，按源码事实书写）
   404	
   405	```
   406	cli 参数校验（含 B2a：单文件 + --changes-dir → exit 2；单文件 + --force → exit 2）
   407	  ↓ [单文件形式]  B2b 作用域判定 → 命中即拒绝，零读取内容、零写入、零移动
   408	  ↓ [高层形式]
   409	discoverDeltas          (:676)   ── 既有
   410	buildProjection         (:678)   ── 既有；**内存合并在此完成**
   411	逐模块报告 / CAS 拒绝集 (:681)   ── 既有
   412	preflightFailures 判定  (:702)   ── 既有；失败即 FAILED PREFLIGHT
   413	jobs 构造               (:708)   ── 既有
   414	--write 温存文件守卫    (:713)   ── 既有
   415	--write 归档目的地守卫  (:721)   ── 既有
   416	**readiness（R1 → R2+R3）**      ── 新增，插在这里
   417	pushIntegritySection    (:733)   ── 既有；未就绪时**不打印**
   418	dry-run 出口 / stage / commit / move ── 既有
   419	```
   420	
   421	「合并」一词在本文件中一律指 **`buildProjection` 的内存投影**；落盘只在 commit 阶段发生。
   422	把 readiness 放在两个 `--write` 守卫之后、integrity report 之前，
   423	是为了让 dry-run 与 `--write` 在**同一个逻辑点**求值就绪度（B4），同时保住 B5 的字节不变。

   429	### 3.1 就绪度结论（**有序**；先命中者先报）
   430	
   431	顺序：**读取/结构失败 → C3 基础合法性 → STEP6 overlay → R2/R3 进度**（r1·REQ-7）。

   533	### `--force`（r1·REQ-2 / REQ-3）
   534	
   535	- **AM-86** 可 force 类逐项：未勾任务、`open`、`fixed`、带理由的 `rejected` → 有证据时放行。
   536	- **AM-87** 不可 force 类逐项：R1 全部五种、结构类全部、medium/large 的 artifact 缺失、
   537	  非法 status、缺理由、`waived` 缺人类记录 → 带 `--force` 仍 refuse。
   538	- **AM-88**（r2·REQ-2）人类证据协议：无 `archive-force <class>` 条目 → `--force` 无效果，
   539	  且打印**可复制的模板**（断言输出含模板骨架，**不**断言含任何人类理由文字）；
   540	  有条目但理由不含 `\w` → 同样无效果；token 边界正确
   541	  （`archive-force-2 tasks` / `archive-force tasks2` 均不命中）。
   542	- **AM-89**（r2·REQ-2 → r3·REQ-2 收紧）**按类绑定、一条一类**：
   543	  只有 `archive-force tasks` 时 R2 被越过而 R3 仍 refuse；只有 `archive-force ledger` 时反之；
   544	  **两条**记录时两者皆过。
   545	- **AM-110**（r3·REQ-2）**锚定与消歧**：`archive-force tasks — ledger cleanup deferred`
   546	  **只授权 tasks**，R3 仍 refuse（理由正文里的 `ledger` 不授权、也不被当作第二个类名）；
   547	  `archive-force tasks2 …` 与 `archive-force-2 tasks …` **都不授权**；
   548	  `archive-force tasks` 后无 `\w` 理由 → 不授权。
   549	  **前置否定控制（r4·A-7）**：`do not archive-force tasks — 还没做完` **不授权**——
   550	  记录的形态是「恰为」而非「包含」，实现**不得**对整条 `gatesEntries()` 字符串做无锚点 substring 搜索。
   551	- **AM-111**（r3·REQ-2）**append-only 撤销**：`archive-force tasks …` 之后追加
   552	  `archive-force-revoke tasks …` → 该类**未获授权**，R2 refuse；
   553	  再追加一条 `archive-force tasks …` → 又获授权（**同类以最后一条为准**，顺序取自 `gatesEntries()`）；
   554	  只有 revoke 而无 grant → 未授权。
   555	- **AM-109** 输出逐条 `forced: …`，并打印所引用记录的**原始首行**——
   556	  控制：构造一条**跨行**的 `gates:` 记录，断言打印的是首行字面文本，
   557	  **不是** `gatesEntries()` 拼接后的规范化文本。
   558	- **AM-90** `--force` 在 dry-run 与 `--write` 中同样改变结论；dry-run 下**零磁盘副作用**。
   559	- **AM-91** 单文件形式 + `--force` → exit 2 + usage。

   625	## 六、已知后果与风险
   626	
   627	1. **TOCTOU 窗口存在（r1·A-1，本版给出精确前置条件）**：
   628	   本 change 保证的区间是「**从第一次读取 readiness artifact 开始，到 dry-run 返回、
   629	   或（无 move 的）commit 结束、或 move 尝试结束为止，调用方不得并发修改 bundle**」。
   630	   实现**不声称**能检测该竞态。机械化表述（r2·A-2）：`--write` 路径须提供一个 hook，
   631	   **在就绪度全部判完之后、第一次写 store 之前**触发；测试在该 hook 内修改 bundle，
   632	   并断言 archive **不重新读取 readiness artifact、也不检测该修改**。
   633	   「看守一次」**不等于**提交时刻的状态保证。**须在 gate④ 如实呈报。**
   634	2. **三项对外可见的破坏性变更**（AM-104 已具名）。其中「单文件形式失去移动能力」

   246	**不得**使用 `archive-merge.js` 的那一份——后者会形成
   247	`archive-merge → readiness → archive-merge` 的环。
   248	两份实现只在 `target === root` 一格分歧，而此处 target 恒为 `<dir>/review`，
   249	故在该调用形态下行为一致（§1.5），须以差分测试证明（RY-07）。
   250	
   251	#### B7c — archive 层自带分类版包含性（r4·REQ-1）
   252	
   253	`resolve.containsReal` 的两个 `realpathSync` 都是 `catch { return false; }`（§1.5），
   254	它**无法区分** `EACCES` 与真正的逃逸，因此**产生不了** `io-error`。
   255	「先自行 realpath、再调 `containsReal`」也不是修复——那会**重新 realpath 一次**，
   256	重现 r3 指出的「第二次调用吞错」窗口。
   257	
   258	因此 archive 层 SHALL 自带一个分类版包含性判定 **`containDefect(root, target)`**：
   259	
   260	1. `realpathSync(root)` 与 `realpathSync(target)` **各调用一次**；
   261	2. 任一抛错且 `e.code === 'ENOENT'` → 交由调用点的 `missing` / 祖先探测逻辑处置；
   262	3. 任一抛错且 `e.code` **不是** `ENOENT` → `{kind:'io-error', code}`；
   263	4. 两者都成功 → `real === realRoot || real.startsWith(realRoot + path.sep)`
   264	   为真则 `null`，否则 `{kind:'escape'}`。
   265	
   266	`artifactDefect` / `reviewRootDefect` **只使用 `containDefect`**，
   267	**不得**调用 `resolve.containsReal`（RY-10 静态断言）。
   268	
   269	**artifact × 缺陷类 × tier 判定表**（穷举）：
   270	
   271	| artifact | `artifactDefect` / `reviewRootDefect` 结果 | trivial | medium / large |
   272	|---|---|---|---|
   273	| `flow-state.md` | `null`（干净） | 继续判 C3 + STEP6 | 同左 |
   274	| `flow-state.md` | `missing` | **不就绪·R1·结构类** | 同左 |
   275	| `flow-state.md` | `symlink` / `not-file` / `escape` / `bad-ancestor` | **不就绪·R1·结构类** | 同左 |
   276	| `tasks.md` | `null` | 继续判 R2 | 同左 |
   277	| `tasks.md` | `missing` | **R2 = n/a** | **不就绪·R2·进度类** |
   278	| `tasks.md` | `symlink` / `not-file` / `escape` / `bad-ancestor` | **不就绪·R2·结构类** | 同左 |
   279	| `review/`（目录） | `reviewRootDefect` 非 `null`（`symlink` / `not-dir` / `escape` / `io-error`） | **不就绪·R3·结构类** | 同左 |
   280	| `review/`（目录） | 不存在（真 `ENOENT`） | 交台账叶子按 tier 判 | 同左 |
   281	| `review/issues.md` | `null` | 继续判 R3 | 同左 |
   282	| `review/issues.md` | `missing` | **R3 = n/a** | **不就绪·R3·进度类** |
   283	| `review/issues.md` | `symlink` / `not-file` / `escape` / `bad-ancestor` | **不就绪·R3·结构类** | 同左 |
   284	| 任一 | `artifactDefect` / `reviewRootDefect` 返回 `io-error`（任一次 `lstat`/`realpath` 抛出非 `ENOENT`） | **不就绪·结构类**，诊断含原始 `e.code` | 同左 |
   285	| 任一 | 守卫通过后 `readFileSync` 抛错（竞态/权限） | **不就绪·结构类**，诊断含原始 `e.code` | 同左 |
   286	
   287	**结构类一律不可 force**（B3）。`flow-state.md` 缺失在 **trivial 层也是结构类**——
   288	因为无法排除这是一个 ABANDONED 的 change，而 R1 的存在理由就是这条排除。
   289	
   290	### B2 — 单文件形式：不再触碰 change bundle（r1·REQ-5 重写为可实现的算法）
   291	
   292	**用一句话陈述目标：单文件形式失去移动 bundle 的能力，也不再消费 bundle 内的 delta。**
   293	
   294	**B2a — `--changes-dir` 不再与单文件形式兼容。** 二者同时出现 → exit 2 + usage
   295	（与既有的「`--change` 不能只配 `--store`/`--delta` 之一」同类）。
   296	**推论：单文件形式此后永不移动任何目录**（移动本就只在 `--changes-dir` 显式给出时发生）。
   297	
   298	**B2b — `--delta` 落在规范 changes root 内 → 拒绝。** 算法（穷举、可直接实现）：
   299	
   300	1. `deltaAbs = path.resolve(cwd, <--delta 实参>)`（`path.resolve` 已规范化 `.` 与 `..`）。
   301	2. `rootAbs = path.resolve(cwd, 'apriori', 'changes')`。**只有规范 root**——显式 root 已被 B2a 吃掉。
   302	3. **词法量度**：`deltaAbs === rootAbs || deltaAbs.startsWith(rootAbs + path.sep)`。
   303	   用**路径段边界**，不用裸字符串前缀 → `apriori/changes-other/...` **不命中**。
   304	4. **realpath 量度**：对 `rootAbs` 与 `deltaAbs` 各取 `fs.realpathSync`；
   305	   - 任一取 realpath 失败（不存在 / 悬空 / 权限）→ **该量度不产生命中**（不是命中，也不是免罪），
   306	   - 两者都成功 → 按第 3 步同样的段边界判定。
   307	5. **两个量度任一命中即拒绝。** 皆不命中 → 落入既有行为（若 delta 本就不存在，仍由既有的
   308	   「delta 文件读不到」错误按状态 A 报，退出码不变）。
   309	
   310	**词法量度必须保留**：root 自身是 symlink 而调用方用词法路径书写时，realpath 量度会失配。
   311	**realpath 量度必须保留**：外部 symlink 指向 bundle 内 delta 时，词法量度会失配。
   312	
   313	**时机措辞（r1·REQ-5）**：判定发生在**读取 store 或 delta 的内容之前**；
   314	作用域判定本身所需的路径元数据读取（`path.resolve` / `realpathSync` / `lstat`）**不在此限**。
   315	
   316	**诊断必须给出替代命令**：`use the high-level form: apriori archive --change <name> [--changes-dir <dir>] [--write]`。
   317	
   318	**不落在 changes root 内的 `--delta`**（真正的单模块手术）——除 B2a 外行为不变（见 B5 的精确表述）。
   319	
   320	### B3 — `--force`：可 force 的类别是穷举的，且需要预存的人类证据（r1·REQ-2 / REQ-3）
   321	
   322	**可 force（进度类，穷举）：**
   323	
   324	- R2：`tasks.md` 存在且有 N 个未勾选框；
   325	- R3：台账行 status 为 `open`、`fixed`、或**带理由的** plain `rejected`（即 `classifyStatus` 判 `legal && hasReason`）。
   326	
   327	**不可 force（穷举）：**
   328	
   329	- **R1 的任何情形**（含 `ABANDONED`——RUNBOOK §283 的硬规则在代码层**没有旁路**）；
   330	- 任何**结构类**（B7 表中的 symlink / not-file / escape / bad-ancestor / 守卫后读取异常）；
   331	- **artifact 缺失**：medium/large 层缺 `tasks.md` 或缺台账；
   332	- 台账行 status **不在词汇表内**（格式问题，不是进度问题）；
   333	- `rejected` / `rejected-verified` / `waived` **缺理由**；
   334	- `waived` **缺 `gates:` 人类记录**——`--force` **不能**代替 waive 证据。
   335	
   336	**人类证据协议（r2·REQ-2 重写——按类绑定，且如实命名其有效期）**：
   337	
   338	`--force` 对某一类失败生效的前提是，bundle 的 `flow-state.md` 的 `gates:` 段里**预先存在**
   339	一条**按类具名**的记录：
   340	
   341	**锚定语法（r3·REQ-2 重写——完全消费、一条一类）**：一条记录的形态恰为
   342	
   343	```
   344	archive-force <class> <reason>
   345	archive-force-revoke <class> <reason>
   346	```
   347	
   348	- `<class>` 是**紧跟在 `archive-force` / `archive-force-revoke` 之后的那一个 token**，
   349	  且必须**恰好等于** `tasks` 或 `ledger`。**位置是锚定的**——不在这个位置的 `tasks`/`ledger` 一律不授权。
   350	- `<reason>` 是该 class token **之后的全部剩余文本**，必须含至少一个 `\w` 字符。
   351	- **一条记录只授权一个类。** 要同时越过 R2 与 R3，**必须写两条**。
   352	  → `archive-force tasks — ledger cleanup deferred` **只授权 `tasks`**；
   353	  理由正文里的 `ledger` 一词**不授予** ledger 类，也**不**被当作第二个类名（歧义消除）。
   354	- token 边界仍按 `(^|[^A-Za-z0-9-])<tok>([^A-Za-z0-9-]|$)`
   355	  （`archive-force-2 tasks` 不命中前缀；`archive-force tasks2` 的 class token 是 `tasks2` ≠ `tasks`，不命中）。
   356	
   357	**撤销：追加，不删除（r3·REQ-2 — `gates:` 是 append-only）**
   358	RUNBOOK `:212` 明写 `gates:` 是 **append-only log of human decisions**，
   359	因此「删除记录」不是合法的流程动作。撤销 SHALL 通过**追加**一条
   360	`archive-force-revoke <class> <reason>` 完成。
   361	
   362	- **同类以最后一条决定为准**：按 `gatesEntries()` 返回的顺序（= 文件中的出现顺序）
   363	  取该类的最后一条 `archive-force` / `archive-force-revoke`；
   364	  若最后一条是 revoke，则该类**未获授权**。
   365	- 只有 revoke 而无 grant → 未授权（无害）。
   366	
   367	- **有效期，如实陈述**：该记录是**该类在本 bundle 生命周期内持续有效的授权**（standing），
   368	  **不是**「本次运行」的证据——文件内容无法证明「本次」。
   369	  记录写下之后新出现的同类失败**会被同一条记录覆盖**，直到追加一条同类的 revoke。
   370	  **这是本协议已知的产品代价，须在 gate④ 如实呈报**；不把它包装成 per-run 证据。
   371	- **来源的准确表述**：该条目**记录一项先前的人类决定**（RUNBOOK 的机制是人类作决定、
   372	  agent 把其原话记进 flow-state）；文件本身**无法证明作者身份**。
   373	  它的作用是让 force 需要一次**独立于本次运行的、可审计的书面动作**，而不是身份证明。
   374	- 证据缺失时 `--force` **无效果**，archive 仍拒绝，并打印一段**可复制的模板**
   375	  （形如 `  - <date> gate⑤ (owner): archive-force tasks — <your reason>`）——
   376	  **不声称**打印人类尚未写下的理由全文。
   377	
   378	**输出格式**：force 生效时逐条打印被越过的项，一项一行，前缀 `forced: `；
   379	随后打印所引用的每条 `gates:` 记录的 **原始首行**（`flow-state.md` 中的字面文本，
   380	**不是** `gatesEntries()` 拼接续行后的规范化文本）。**不打印笼统的一句 "forced"。**
   381	
   382	**dry-run 与 write 的关系（r1·REQ-2 的矛盾修正）**：
   383	`--force` 在 dry-run 与 `--write` 中**同样改变就绪度结论**；**只有 `--write` 产生磁盘副作用**。
   384	
   385	**单文件形式与 `--force`（r1·REQ-3）**：`--force` **只出现在高层 usage**；
   386	单文件形式收到 `--force` → **exit 2 + usage**。这是 B5 的**唯一一处**兼容性例外，见 B5。
   387	
   388	### B4 — dry-run 说的就是 `--write` 会做的
   389	
   390	未就绪时 dry-run **不得**打印 `RESULT: MERGED (dry-run…)`，退出码 1，零写入。
   391	
   392	### B5 — 零变化的精确边界（r1·REQ-4 / REQ-3）
   393	
   394	- **既有 preflight 失败**（`discoverDeltas` 错误 / `buildProjection` validation / CAS 拒绝 / hygiene /
   395	  base 失配 / 同 ID 冲突 / `--write` 的预存温存文件 / 显式 root 的归档目的地包含性）时：
   396	  诊断与退出码**一字不变**，且就绪度**不被求值**。
   397	- **就绪的 bundle** 的成功输出（逐模块报告、MODIFIED 完整性报告、`RESULT: MERGED…`、移动路径）**一字不变**。
   398	- **单文件形式、delta 在 changes root 之外**：行为不变，**唯二例外**是
   399	  ① 同时传 `--changes-dir` → exit 2（B2a）；② 传 `--force` → exit 2（B3）。
   400	  两者在状态 A 分别是「合法组合」与「unknown flag exit 2」，本版把前者改为 exit 2、
   401	  后者保持 exit 2 但**改变诊断文本**。这两处例外**必须逐条写进 CHANGELOG**。
   402	
   403	### B6 — 精确调用序（r1·REQ-4，按源码事实书写）
   404	
   405	```
   406	cli 参数校验（含 B2a：单文件 + --changes-dir → exit 2；单文件 + --force → exit 2）
   407	  ↓ [单文件形式]  B2b 作用域判定 → 命中即拒绝，零读取内容、零写入、零移动
   408	  ↓ [高层形式]
   409	discoverDeltas          (:676)   ── 既有
   410	buildProjection         (:678)   ── 既有；**内存合并在此完成**
   411	逐模块报告 / CAS 拒绝集 (:681)   ── 既有
   412	preflightFailures 判定  (:702)   ── 既有；失败即 FAILED PREFLIGHT
   413	jobs 构造               (:708)   ── 既有
   414	--write 温存文件守卫    (:713)   ── 既有
   415	--write 归档目的地守卫  (:721)   ── 既有
   416	**readiness（R1 → R2+R3）**      ── 新增，插在这里
   417	pushIntegritySection    (:733)   ── 既有；未就绪时**不打印**
   418	dry-run 出口 / stage / commit / move ── 既有
   419	```
   420	
   421	「合并」一词在本文件中一律指 **`buildProjection` 的内存投影**；落盘只在 commit 阶段发生。
   422	把 readiness 放在两个 `--write` 守卫之后、integrity report 之前，
   423	是为了让 dry-run 与 `--write` 在**同一个逻辑点**求值就绪度（B4），同时保住 B5 的字节不变。

   464	## 四、验收标准
   465	
   466	### 新模块 `readiness`（store 前缀 `RY-`）
   467	
   468	- **RY-01** 基础层的三条判据与状态 A 的 gate C3 / C2 / archived-C4 **逐项一致**：
   469	  同一批 bundle 喂给两边，`{id,status,detail}` 逐条相同（差分断言）。
   470	- **RY-02** gate 改用基础层之后，`runGate()` 的返回对象与每条 detail **字节不变**；
   471	  抛错分支只比 error class / code / message，**显式排除** stack 的文件名与行号。
   472	- **RY-03** `STEP6` 是在 C3 通过**之后**追加的一条 overlay，不是替换 C3：
   473	  C3 失败时报 C3 的原始 detail，不报 STEP6 措辞。
   474	- **RY-04** 每个合法的非 `STEP6` 取值都使 archive 不就绪，而 gate 的 C3 仍 pass
   475	  （断言方向：`archive 就绪 ⇒ gate C3 pass`，反之不成立）。
   476	- **RY-05** 静态断言：`archive-merge.js` 不出现 `require('./gate')`；`gate.js` 不重实现三条判据；
   477	  `gate.js` 仍导出 `classifyStatus`。
   478	- **RY-06** 基础层**不含**任何 `fileReadDefect` 调用（安全层是 archive 独有的；
   479	  基础层若加守卫就会改变 gate 行为，与 RY-02 冲突）。
   480	- **RY-08**（r3·REQ-1 → r4·REQ-1 拆分）**`artifactDefect` 的差分基准是 `resolve.fileReadDefect`**：
   481	  在 `null` / `symlink` / `not-file` / `escape` / `bad-ancestor` / 真 `missing` **六种**输入上结论一致
   482	  （第七种 `io-error` 是状态 A 产生不了的新类，单独验收，见 AM-107）。

## 原问题处置

### REQ-1 — REOPENED

单趟 `lstat` 修复方向正确，且确实消除了 Round-3 指出的“外层检查后再调用吞错 helper”问题。但新定义仍有两处互相不能同时满足的规范。

#### 残余缺陷 1：`resolve.containsReal` 无法产生要求的 `io-error`

B7b 要求 archive 层的 `reviewRootDefect` 使用 `require('./resolve').containsReal`。实际 `resolve.containsReal()` 在 root 或 target 的 `realpathSync` 抛错时直接 `catch { return false; }`，不暴露异常或 `e.code`。

因此，review-root realpath 抛 `EACCES` 时：

- B7b 要求调用的 helper 只能返回 `false`；
- 实现只能把它归为 `escape`；
- B7a、判定表和 AM-107 却要求返回 `io-error`，并打印原始 `EACCES`。

先自行 realpath、再调用 `resolve.containsReal` 也不是完整修复：它会重新 realpath，并重现“第二次调用吞错”的同类窗口。

#### 残余缺陷 2：`reviewRootDefect` 的对象类型及差分基准不成立

B7a 同时要求 `artifactDefect` 和 `reviewRootDefect` 照抄 `resolve.js:151-155`。该规则包含：

```js
if (!st.isFile()) return { kind: 'not-file', ... };
```

这对文件 artifact 正确，但对合法的 `review/` 目录会恒定返回 `not-file`。review root 应采用 state A `reviewDirDefect` 的 `isDirectory()` 规则，而不是文件规则。

RY-08 也把两个新函数合并成同一组六类差分，但二者没有同一个 state-A 基准：

- `artifactDefect` 应对比 `resolve.fileReadDefect`；
- `reviewRootDefect` 应对比 `gate.reviewDirDefect`；
- 真正缺失的 review root 在 state A 返回 `null`，新设计则拟返回 `missing`，不能声称结果逐项相同；只能比较最终 tier-sensitive readiness 结论或明确声明这是有意的新分类。

- **维度**：目标状态清晰性、异常路径、验收可测试性、与 state A 冲突。
- **风险**：high。按字面实现可能拒绝所有具有正常 `review/` 目录的 bundle；realpath 错误的类型和诊断 AC 也无法实现。
- **建议修复**：
  - B7b 只让基础层 `reviewDirDefect` 使用 `resolve.containsReal`；
  - archive 层使用新的本地 containment classifier，直接捕获 root/target realpath 异常并返回 `{kind:'io-error', code}`，不得再调用吞错 helper；
  - 分开规定 artifact 的 `isFile()` 与 review root 的 `isDirectory()`；
  - 将 RY-08 拆成两个明确基准，并把 review-root missing 定义为有意的新分类或改测最终 readiness；
  - AM-107 增加 review-root realpath 抛错的直接控制。

#### realpath 错误分类

B7c 不再让 archive 层使用吞错的 `resolve.containsReal`：

- `containDefect` 对 root/target 各执行一次 `realpathSync`；
- 非 `ENOENT` 异常返回带原始 code 的 `io-error`；
- 成功时明确返回 `null` 或 `escape`；
- archive 的三个新函数被 RY-10 静态禁止调用 `fileReadDefect`、基础层 `reviewDirDefect` 或 `containsReal`；

- 文件 artifact 使用 `isFile()` / `not-file`；

- review root 真正缺失时返回 `null`，由 `review/issues.md` 的 artifact 检查落实 tier-sensitive 结论；

- AM-112 证明正常目录不会被误判为文件缺陷；
- AM-113 覆盖 review root 缺失时 trivial 与 medium/large 的不同结果。

### REQ-4 — VERIFIED（回归复核）

单文件路径作用域的五步算法及词法、realpath、失败回落边界均未变化。

### REQ-6 — VERIFIED（回归复核）
