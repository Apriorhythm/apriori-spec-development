# code-review — review-round-limit (round 1)

- RRL-01 — **Archive drops progress-record failures.** `lib/readiness.js:638` consumes `loop.problems`, `reviewFloor`, and family escalation states, but never `loop.progress`. GT-54 and the archive contract require evidence failures to block without an owner override. A family accepting round 3 with a missing, incomplete, uncovered-ID, or nonexistent-path progress record blocks C8 but contributes no archive R4 blocker. **Fix:** propagate every progress failure into non-forceable R4 evidence blockers; test an otherwise archive-ready round-3 accept with each failure, with and without `--force`.

- RRL-02 — **Custom change directories can bypass the project’s limit.** `lib/readiness.js:545` guesses the project root from bundle ancestry; `lib/archive-merge.js:919` does not pass its known `cwd`. With `--changes-dir changes`, the fallback resolves above the project, so archive can read the wrong config and silently use 7 despite an invalid or different project limit. GT-55 requires archive to consume the project’s configuration and refuse invalid values. **Fix:** pass the authoritative project root into `readinessOf` and use it for both config and evidence references; cover custom change-directory layouts.

- RRL-03 — **Explicit invalid config cells silently become defaults.** `lib/config.js:108` discards empty cells, and line 110 discards all-hyphen values; `resolveReviewRoundLimit` at line 185 then returns the default. Thus `| review-round-limit | |` and `| review-round-limit | - |` resolve to 7 instead of errors. The config requirement permits defaulting only for an absent row/file and requires every other non-decimal cell to fail closed. **Fix:** preserve explicit invalid values through the shared reader, distinguish them from absence, and add resolver/C8/archive coverage, including an invalid row alongside a valid duplicate.

- RRL-04 — **Evidence paths are not confined to the project.** `lib/review.js:501` calls `statSync(path.resolve(cwd, ref))` without containment validation and follows symlinks. Absolute paths, `../` traversal, and project symlinks targeting external regular files can satisfy the record. The gate contract requires an existing regular file **in the project**. This stats external paths; it does not read their contents. **Fix:** validate lexical and real-path containment against the project root before accepting evidence, and test traversal, absolute external paths, and escaping symlinks.

- RRL-05 — **Issue coverage misses ordinary Markdown list items.** `lib/review.js:443`–444 recognizes only `-`, `*`, and pipe-leading rows, with a restricted single-segment ID grammar. For example, `1. R-02 unresolved` and `+ R-02 unresolved` contribute no IDs, so `issues: none` passes. GT-54 requires coverage of every issue ID opening a list item or table row without restricting lists to those two bullet markers. **Fix:** support ordered and all unordered Markdown list markers, define the supported ID grammar consistently, and test omitted IDs across these forms.

- RRL-06 — **The progress parser accepts missing labelled parts and missing approach reasons.** `lib/review.js:442` matches field names anywhere, including the `actions:` suffix of `transactions:`. Consequently, `issues: none; transactions: updated; evidence: lib/review.js; approach: kept` supplies a fabricated actions field and passes the approach check at line 491 without the documented reason. GT-54 requires four actual labelled parts, and the contract/runbook grammar specifies `kept|changed — <reason>`. **Fix:** recognize labels at field boundaries, validate the complete approach value, and add malformed-record tests. Also explicitly document or tighten `PROGRESS_START`’s optional timestamp/actor forms so the published grammar matches acceptance.

- RRL-07 — **Derived documentation still teaches the retired stops.** `docs/operator.md:10` and `docs/operator_cn.md:10` still instruct the operator to stop after round 2 instead of opening round 3. `docs/concepts.md:352` and `docs/concepts_cn.md:352` retain both the round-2 reframe and fixed round-5 escalation; line 391 repeats the round-2 stop, and line 402 still says config contains no round number. PR-41 explicitly forbids these current-rule descriptions. **Fix:** update the recipes, explanatory paragraphs, and diagram edge at `docs/concepts.md:305`; strengthen PR-41 to catch these actual phrases and include `operator_cn.md`.

- RRL-08 — **R4 promises enforcement the implementation does not provide.** `RUNBOOK.md:122`, `:126`, and `:129`, mirrored in `RUNBOOK_cn.md`, promise that `check` reports blocked C8, that references are tied to the submitted revision, and that continuation requires a raised finite limit. However, `lib/check.js` does not consume the limit or run C8; `lib/review.js:498` checks file existence only; and line 555 onward acknowledges a reframe without requiring a changed limit. GT-52 itself permits another round and a fresh escalation at the unchanged limit. **Fix:** reconcile both runbooks with the delta contract, distinguish procedural obligations from CLI enforcement, and remove unsupported enforcement claims or implement the agreed behavior.

- RRL-09 — **Unanswered escalations are reported as forceable.** `lib/readiness.js:649` sets `forceable: true` even without an owner reframe. The modified archive requirement explicitly calls a stop without an owner decision non-forceable. Although line 652 prevents the actual bypass, readiness metadata and archive advice contradict that contract. The adaptation at `test/review-loop.test.js:633` explicitly accommodates this discrepancy. **Fix:** make forceability conditional on a valid recorded decision, retain the owner cure for unanswered stops, and assert both pending and acknowledged states.

- RRL-10 — **Resolver errors omit required diagnostic context.** `lib/config.js:184` returns shared-reader problems unchanged. An unreadable file error omits `review-round-limit` and the legal range; a conflict omits the range and offending values. The config requirement places those diagnostics on `resolveReviewRoundLimit` itself. C8’s later decoration does not repair that API contract. **Fix:** decorate resolver errors with the key and range, preserve conflicting values where available, and directly test unreadable/config-conflict resolver results.

- ADV-01 — **advisory: adapted tests no longer establish several owner-stop assertions.** `test/review-loop.test.js:385` and `:418` retain round-2 fixtures under the new default fixture limit of 5. Their blocked results now come from the unresolved-review floor, regardless of whether reframes match. Line 440 also checks absence of a retired message instead of proving acknowledgment. - ADV-02 — **advisory: numeric conversion can produce an infinite limit.** `lib/config.js:187` accepts arbitrarily long decimal strings and line 190 converts them with `Number`; sufficiently large inputs become `Infinity`, disabling count-based escalation. The documented limit is an integer, and R4 additionally calls revised limits finite. **Fix:** define supported numeric bounds and validate conversion, or preserve exact integer semantics; add overflow and precision-boundary coverage.
