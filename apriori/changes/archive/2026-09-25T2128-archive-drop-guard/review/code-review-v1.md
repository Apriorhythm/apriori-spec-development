# code-review — archive-drop-guard (round 1)

- ADG-01 **P1 — Path normalization permits authorization replay for a different deletion locator.** [lib/archive-merge.js:790](/root/terra/asd-v62-code/lib/archive-merge.js:790). **Contract:** the fingerprint binds the exact file and deletion set, without formatting collisions. **Code:** manifest fields contain raw paths, then `fingerprint(text)` normalizes CR/CRLF throughout the manifest. On Unix, `m\ra/spec.md` and `m\na/spec.md` are distinct accepted paths but become identical fingerprint input. Moving both the store and matching delta between those paths, with contents unchanged, preserves the owner fingerprint while changing the file whose scenario is deleted. **Fix:** encode manifest fields unambiguously before hashing, preserving path characters; keep content-line-ending normalization confined to content digests. Add a regression proving these distinct locators cannot share authorization.

- ADG-02 **P2 — Existing empty stores are fingerprinted as absent.** [lib/archive-merge.js:390](/root/terra/asd-v62-code/lib/archive-merge.js:390), [lib/archive-merge.js:785](/root/terra/asd-v62-code/lib/archive-merge.js:785). **Contract:** every existing touched store contributes its digest; `new` means absent. **Code:** capture collapses absence and empty text to `''`, and manifest generation tests truthiness. A change containing a dropping module plus an unstamped ADDED-only module therefore retains the same authorization when that second store changes between absent and empty; CAS does not block that ADDED-only case. **Fix:** capture store existence from `texts.has(suffix)` alongside its text and hash existing empty text. Test absent versus empty in a multi-module change.

- ADG-03 **P2 — Rewritten AM-47 contradicts the archive entry points.** [spec.md:27](/root/terra/asd-v62-code/apriori/changes/archive-drop-guard/specs/archive-merge/spec.md:27). **Contract:** missing factories degrade with a warning; invalid patterns/injected failures warn and skip, permitting scenario-free old blocks. **Code:** the archive supplies a default factory, and structural preflight refuses matcher errors before integrity evaluation ([lib/archive-merge.js:937](/root/terra/asd-v62-code/lib/archive-merge.js:937)). The existing AM-47 test explicitly expects those behaviors. **Fix:** reconcile the rewritten scenario with mandatory structural preflight and default factory resolution. Describe the blind-integrity fallback separately, for failures occurring after structural preflight succeeds; do not weaken that preflight.

- ADV-01 **Snapshot and refusal ordering otherwise look sound.** The manifest, comparison and staged output derive from the same captured store/delta inputs. Authorization reads readiness’s captured `flowText`. No new input re-read occurs between projection and staging. Readiness R1/R4/R5, CAS, conflicts, structural checks, high-level temp checks and declaration backstop precede the guard; staging, commit and move failures remain failures afterward. This preserves the existing snapshot semantics, not a lock against concurrent filesystem edits.

- ADV-02 **Blind matching and single-file behavior are appropriately conservative.** The blind check uses the same scenario scanner as comparison and is limited to MODIFIED old blocks containing scenarios. Single-file drops refuse before writes, and its bundle-scope and `--force` restrictions remain intact. Its ambiguous-only diagnostic could also explicitly point to the high-level form, as the new requirement requests.

- ADV-03 **Strengthen regression coverage.** Pin the full winning `forced:` entry, last matching decision, multi-module ordering, LF/CRLF equivalence for content, snapshot mutation through the existing hook, and valid drop authorization combined with other refusal classes. Assert zero staging calls and no temp artifacts on refusal; unchanged store bytes alone do not establish zero writes.

- ADV-04 **Documentation and existing behavior are otherwise aligned.** AM-05’s retained scenario is a legitimate fixture correction: that test concerns operation reporting. Pairing and `missingLines` algorithms are unchanged, and AM-84’s readiness ordering remains intact. Qualify “retitling is not dropping” as “retitling with the same ID”; explicitly include requirement-prose loss alongside scenario-body loss in the report-only wording.
