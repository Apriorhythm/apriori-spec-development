# Delta — archive-merge (archive-drop-guard)

## MODIFIED Requirements

### Requirement: the modified-block integrity engine reports replacement fidelity
A pure shared helper SHALL compare a MODIFIED operation's old store block against its replacement (both captured at the projection's own parse snapshot — `buildProjection` additionally returns the raw old/new block text pairs per MODIFIED operation; no consumer re-reads files) and report structural fidelity. The report is informative for `retained`, `titleChanged`, `added` and `missingLines`; since archive-drop-guard the `dropped` and `ambiguous` classes are CONSUMED by the archive's drop guard (see "archive never drops a store scenario without a fingerprint-bound owner decision"), so a MODIFIED replacement that drops or cannot pair a scenario is refused instead of merged. Structure scan: the requirement heading line never participates; requirement prose runs from the line after the heading to the first VALID scenario heading (state A's actual regex `/^####\s+Scenario:\s+(.*)$/m`, fence-aware exactly like `stripFences` — only lines inside CLOSED triple-backtick pairs are not delimiters; an unclosed opener is ordinary text and later headings still split); fence delimiter lines and fenced non-empty lines are compared as body lines. Pairing runs per key (scenario ID when present, normalized full title otherwise) through one cardinality truth table — o=0,n=1 added; o=1,n=0 dropped; o=1,n=1 paired (same normalized title → retained, different → titleChanged, mutually exclusive, both body-compared); any side >1 → ambiguous (side old/new/both with counts; the key skips every other class and body comparison). Line comparison is ONE algorithm: order-preserving greedy subsequence over normalized non-empty lines (CRLF/CR→LF, trailing whitespace stripped, leading whitespace stripped; duplicates consumed by count); unmatched OLD lines are `missingLines` (requirement prose misses carry scenario=null; only old-content loss is reported). An idempotent replacement takes a FAST PATH — `oldBlock.trim() === newBlock.trim()` short-circuits before any structure scan or id extraction — yielding an entry whose diff arrays are all empty (the stamped-rerun repair path included: a repaired module still contributes its equal-text pair, one entry per MODIFIED operation always). Capture points are module-level testable: `buildProjection().modifiedBlocks` carries raw text pairs — for rename-then-modify the oldBlock deep-equals the COMPLETE pre-rename block (captured before the rename key swap) and the newBlock deep-equals the delta block. The human formatter renders SAFELY: every externally-sourced field (titles, lines, requirement names, file suffixes, ambiguous keys) has C0/DEL control characters replaced with `·` BEFORE the 120-unit truncation (JSON keeps full raw text; JSON.stringify escapes there); an all-empty result renders as NOTHING (no blank line).

### Requirement: --force overrides progress only, on pre-recorded human authority

### Requirement: archive never drops a store scenario without a fingerprint-bound owner decision
When any MODIFIED replacement of the change drops a store scenario (the integrity engine's `dropped` class, paired by scenario ID — a title change under the same ID is not a drop), `apriori archive --change <name>` SHALL refuse in dry-run and `--write` alike with `RESULT: REFUSED — nothing written` (exit 1), nothing staged, nothing moved. It SHALL print a `— DROPPED SCENARIOS —` block listing every deletion as `<file> · <requirement> · <scenario id or title>` (sorted) and the manifest fingerprint, and on stderr the copyable cure `- <YYYY-MM-DDTHH:MM> owner: archive-drop <change> sha256:<fingerprint> — <reason>`. The fingerprint is the SHA-256 of a canonical manifest built from the projection's own parse snapshot (never a second read): `apriori archive-drop manifest v1`, the target change name, every touched module's store digest and delta digest (`fingerprint()` of the raw text, `new` for an absent store), and the sorted deletion locators — so editing any delta or store of the change, or dropping a different set, moves the fingerprint and voids the decision. Release requires BOTH a canonical owner entry whose target and fingerprint match exactly (same parser and strictness as the other decision verbs: real timestamp, actor `owner`, em dash, a reason; last matching entry wins) AND explicit `--force`; the decision alone refuses naming the missing flag, the flag alone refuses naming the missing decision, and a forced run prints `forced: dropped <n> scenario(s) — owner decision on record: <entry>`. An `ambiguous` key (a scenario key occurring more than once on either side) SHALL be refused as not forceable — disambiguate first; `missingLines` stays report-only (requirement-prose loss and scenario-body loss are S4's remaining, still-open gap). When the modified-block comparison cannot run at the integrity stage (after the structural preflight passed) and some MODIFIED old block carries a scenario, the run SHALL be refused (a guard that cannot see must not wave a deletion through); old blocks with no scenario need no matcher. Manifest fields SHALL be JSON-encoded and the manifest hashed byte-for-byte (no line-ending normalization of the manifest itself), while the store and delta content digests keep `fingerprint()`'s LF/CRLF normalization; an existing but empty store contributes its content digest, `new` marks only an absent store. The single-file form (`--store/--delta`) has no bundle to hold a decision: it SHALL refuse any dropping or ambiguous replacement outright and point at the high-level form, while merging title changes and body rewrites as before. `--force` remains a high-level-form flag; no ratio or threshold configuration key is introduced.
