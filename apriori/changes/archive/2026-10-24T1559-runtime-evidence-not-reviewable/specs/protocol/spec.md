# Delta — protocol (runtime-evidence-not-reviewable)

## ADDED Requirements

### Requirement: runtime evidence is a run or an open item, never the review
The runbook's Build & Test section SHALL say that review reads and does not run: a runtime behavior no test executes — a new or changed page or user-visible flow, a migration, a job, a call to a real service named as examples — is run once in the environment at hand (a dev server and a headless browser count; "there is no test runner here" is not "it cannot be run") and recorded as an `observed:` line stating what was done, what was expected, what happened and where the screenshot or output lives (`apriori/tmp/`); that a run of the normal path is evidence for that path only; that a run which genuinely cannot be made is an `## Open` item with a stable id — R1 case 2, the owner's — never only a sentence in the final report; and that the independent review confirms what reading settles and never closes a runtime gap. P2's Build & Test part SHALL carry the same clause to the producer with its condition intact — the run comes first ("no test runner" is not "cannot be run"), and only a run that genuinely cannot be made is the `## Open` item, naming what was tried — and the concepts handbook SHALL agree in both editions, saying that a change with no runtime behavior of its own needs no run because there is nothing to run, not because the review replaces it. The sentence "the independent review is the instrument there", and its paraphrase in VISION ("where none exists, the independent review is the instrument"), SHALL be gone from every live document. No gate, state-file field, UI-specific check or owner stop is added by this rule: a change that has its runtime evidence, or can obtain it, stops nowhere new; `verify`'s UNBOUND stays advisory.
