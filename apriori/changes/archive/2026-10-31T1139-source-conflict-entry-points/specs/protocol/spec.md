# Delta — protocol (source-conflict-entry-points)

## ADDED Requirements

### Requirement: a source constraint applies to the existing entry points too, and an observed conflict reaches the examples at those entry points
The runbook SHALL say, in §4 Ground, that source constraints apply to existing entry points too: where a source explicitly rules out an exception, override or continuation of behavior under a stated condition (for example "does not override", "regardless of", "no longer"), Ground checks how existing or reused paths handle that condition — within this change's requirement scope, which is the behavior being delivered including the caller-visible entry points the sources name or imply and the code they reuse, not just the files being changed — tracing each affected entry point far enough to establish what determines its observable result under that condition and recording the condition, entry point, deciding code and current result in the existing `observed:` entries; that the same trace applies to any conflict between a source and current behavior Ground has already observed; that only the paths needed to explain that result are followed, not a repository sweep; and that checking only new code does not settle the existing entry points governed by the same requirement. §4 Specify's minimal-contract rule SHALL say that for every conflict Ground observed between a source and current behavior the examples carry its triggering condition at the affected caller-visible entry points, existing ones included, with representatives for each distinct path that determines the result; that one representative may stand for several entry points only when an existing `observed:` entry establishes that the same path determines their result under that condition; and that each expected result retains every source obligation applicable to that example. P1 SHALL carry the trace (both triggers, the requirement scope defined in §4 Ground, the four recorded facts) and P2 SHALL carry the examples rule (triggering condition at affected caller-visible entry points including existing ones, representatives per deciding path, sharing only on observed evidence, every applicable source obligation retained) to the producer. No gate, flow-state field, checklist, diagram, search action, new document or task-specific text is added; §4 Build & Test and P3 are unchanged.

#### Scenario: PR-78 the runbook applies a source constraint to the existing entry points and carries an observed conflict into the examples there
- WHEN §4 Ground, §4 Specify's "Minimal means minimal" rule, P1, P2 and P3 are read
- THEN §4 Ground carries a rule that source constraints apply to existing entry points too, triggered by a source that explicitly rules out an exception, override or continuation of behavior under a stated condition and by any conflict between a source and current behavior already observed in Ground, scoped to the behavior being delivered (the caller-visible entry points the sources name or imply and the code they reuse, not just the files changed), tracing each affected entry point far enough to establish what determines its observable result under that condition, recording the condition, entry point, deciding code and current result as `observed:` lines, following only the paths needed to explain that result and not a repository sweep, and saying that checking only new code does not settle the existing entry points governed by the same requirement; the Specify rule says the examples carry each observed conflict's triggering condition at the affected caller-visible entry points including existing ones, with representatives per distinct deciding path, sharing a representative only on an `observed:` entry that the same path decides under that condition, and retaining every applicable source obligation in the expected result; P1 says the same trace and P2 the same examples rule to the producer; PR-75's entry-point and complete-assertion requirements, PR-76's trace and PR-77's safe default still stand; P3 reads exactly as before; and none of these texts adds a gate, a field, a checklist, a diagram, a search action, a new document or task-specific text
