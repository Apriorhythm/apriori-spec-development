## Why

站主自己录制了几十首歌(mp3,无版权问题),想放到网上给朋友听,目前没有任何现成的展示途径。需要一个公开访问、手机点开就能播放的个人音乐网站,并且站主不会命令行、更新频率低(录好一批传一批),所以维护方式必须是纯浏览器操作、近乎零运维。

## What Changes

- 从零搭建一个**纯静态**个人音乐网站,托管在 GitHub Pages(免费、免运维、无服务器)。
- 曲库按**专辑 = 文件夹**组织:站主在 GitHub 网页界面新建专辑文件夹、拖拽 mp3 和封面图、点击 Commit 即完成更新。
- 提交后由自动化流水线读取每首 mp3 的 ID3 标签(歌名、时长),生成专辑数据与页面并自动发布,站主无需任何本地工具。
- 网站结构:首页专辑墙 → 专辑页曲目列表 → 底部常驻播放条(顺序播放、切歌)。
- 移动端体验:浏览器原生 `<audio>` 流式播放,锁屏/通知栏显示歌名与封面并支持切歌(Media Session API)。
- 挂载**免登录的轻量第三方评论组件**,朋友可以留言,不引入自建后端。

**明确不做(v1 范围外):**
- 朋友自助上传(无真实需求,仅"觉得好玩";朋友的歌可由站主代传。若日后呼声真实存在,静态内容可平移升级,不在本变更内)。
- 账号体系、访问口令、搜索、推荐——公开链接即全部访问控制。

## Capabilities

### New Capabilities
- `album-library`: 曲库的组织与更新——专辑目录约定(mp3 + 封面)、浏览器拖拽更新流程、提交后自动提取 ID3 元数据并生成站点数据、自动发布上线。
- `music-playback`: 听歌体验——首页专辑墙、专辑页曲目列表、底部常驻播放条、顺序连播与切歌、移动端流式播放与锁屏媒体控制。
- `guest-comments`: 朋友留言——免登录的轻量评论组件,挂载于专辑页,不依赖自建后端。

### Modified Capabilities

(无——全新项目,不存在既有能力。)

## Impact

- **代码**:全新仓库,新增静态站点源码、专辑目录约定、构建/发布流水线配置。
- **依赖**:GitHub Pages + GitHub Actions(免费额度内:单文件 <100MB,整站几百 MB,朋友级流量);第三方评论服务(选型在 design 阶段确定,原则为免登录、免维护、免费额度够用)。
- **运维**:零服务器。站主日常操作 = GitHub 网页拖拽文件;域名先用免费的 `*.github.io`,自定义域名可日后随时叠加。
- **风险**:评论组件依赖第三方服务的存续;GitHub 免费额度是软约束(当前体量余量充足)。
