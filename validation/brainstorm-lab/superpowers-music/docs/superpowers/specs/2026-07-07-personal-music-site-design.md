# 设计文档:个人音乐站

日期:2026-07-07
状态:已通过用户确认

## 目标

为用户搭建一个展示自己录制歌曲的网站,给朋友试听。用户不熟悉命令行,日常加歌必须能通过浏览器界面(鼠标 + 打字)独立完成。

## 范围

**做:**

- 歌曲列表与播放(几十首 mp3,单曲约 8MB)
- 每首歌配:封面、创作背景、歌词
- 自我介绍区
- "朋友作品"分区(朋友把歌发给用户,由用户通过后台手动添加)
- 浏览器内容管理后台,加歌零命令行
- 免费托管,公开访问

**不做(明确排除):**

- 评论功能
- 朋友自助上传(多用户平台)
- 访问口令/鉴权(站点公开)
- 自定义域名(可后续绑定,不在本期)

## 整体架构

- **站点生成**:Astro 静态站点生成器,输出纯静态页面
- **托管**:Cloudflare Pages 免费版,自动 HTTPS,提供 `*.pages.dev` 网址
- **内容后台**:Sveltia CMS,挂载于 `/admin`,以 GitHub OAuth 登录(为用户注册一个 GitHub 账号,一次性设置)
- **内容存储**:mp3、封面图、歌曲元数据(Markdown/YAML)全部存于 GitHub 仓库;CMS 的"发布"操作即 git 提交,自动触发 Cloudflare Pages 重新构建,约 1–2 分钟生效
- 无服务器、无数据库、零月费

## 内容模型

每首歌为一条内容(一个 Markdown 文件 + 关联媒体文件),字段:

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 歌名 | 是 | |
| mp3 文件 | 是 | 后台上传 |
| 封面图 | 否 | 缺省时使用站点默认封面 |
| 创作日期 | 是 | 用于排序(新歌在前) |
| 创作背景 | 否 | 短文,详情页展示 |
| 歌词 | 否 | 全文,详情页展示 |
| 分区 | 是 | 「我的歌」/「朋友作品」二选一 |
| 朋友名字 | 分区为朋友作品时必填 | 列表与详情页标注 |

站点级内容(同样后台可编辑):自我介绍文字、头像。

## 页面结构

1. **首页**
   - 顶部:头像 + 自我介绍
   - 歌单:先「我的歌」区,后「朋友作品」区;每首显示封面缩略图、歌名(朋友作品附朋友名),按创作日期倒序
   - 每首歌有播放键(就地播放)与进入详情的链接
2. **歌曲详情页**
   - 大封面、歌名、创作日期、播放器、创作背景、歌词全文
3. **底部播放条**
   - 点任意播放键后出现,常驻页面底部:播放/暂停、进度条、当前曲名
   - 一首播完自动播当前分区的下一首

## 关键技术决策

- **移动优先**:朋友主要在微信内置浏览器中打开,页面按手机屏设计,桌面端自适应放宽
- **播放需用户触发**:不做自动播放(微信 WebView 禁止,且体验差)
- **音频 `preload="none"`**:点击播放才开始下载,节省访客流量
- **体量预案**:几十首 × 8MB 在 GitHub 仓库与 Cloudflare Pages 免费额度内(Pages 单文件上限 25MB,单曲 8MB 安全);若将来增长到数百首,再迁移音频至对象存储 —— 本期不实现

## 错误与边界处理

- 无封面 → 显示默认封面
- 无歌词/无创作背景 → 详情页隐藏对应区块,不留空标题
- 超长歌词 → 正常文档流滚动,不做折叠
- 音频加载失败 → 播放条显示简短错误提示,可重试
- CMS 表单校验:歌名、mp3、创作日期、分区必填;分区为朋友作品时朋友名字必填

## 测试与验收

- 构建通过,所有歌曲页面正确生成
- 手机(含微信内置浏览器)与桌面浏览器:浏览、单曲播放、连播、进度拖动均正常
- 无封面/无歌词的歌曲页面展示正常
- 端到端验收:用户本人通过 `/admin` 完成一次「加新歌 → 发布 → 朋友可听到」的完整流程,全程不使用命令行

## 一次性搭建事项(由开发者完成)

- 初始化 Astro 项目与页面
- 注册 GitHub 账号(交付用户)、创建仓库、配置 Sveltia CMS 与 GitHub OAuth
- 配置 Cloudflare Pages 自动构建部署
- 批量导入用户现有的几十首歌
- 交付一页图文版《加歌操作说明》
