# 全流程三方对比 + V3 循环优化 · 总报告

课题:quick-poll(UI+后端、文件存储、匿名投票)。三家从「我想做一个快速投票的小工具」一句话起,各跑完整生命周期(脑暴→规格→写码→测试→归档),人类闸口由我按同一底牌扮演,评审真实外调 codex。评估:独立重跑测试 + 12 项黑盒闯关(独立子代理)+ codex 静态对抗审计 + 规格库终态核对。

## 一、第一轮三方对比(基线)

| 维度 | V3 | OpenSpec | Superpowers |
|---|---|---|---|
| codex 静态缺陷 | **3(med3)** | 7(med5 low2)+**严重 DoS** | 5(med3 low2) |
| 黑盒闯关 | 11/12 | 12/12(但 DoS) | 11/12 |
| 崩溃/DoS | 无 | 16KB POST 崩整个进程 | 超大体粗暴断连 |
| 规格库终态 | living store 28 场景绑测 + KB | living store 16 需求,无 KB | 仅设计+计划文档,**无 living 规格、无绑定** |
| 过程开销 | 最重(~182k tok) | 最轻(~87k) | 中(~123k) |

**决定性事实:V3 的 STEP2 评审在过程中抓到并修掉的 id-碰撞覆盖数据丢失 bug,在 OpenSpec 和 Superpowers 里都原样出厂了。** 这是异构对抗评审核心价值的直接兑现。

## 二、V3 循环优化(每轮剥出下一层)

| 轮 | 发现 | 改进(发布) |
|---|---|---|
| r1 | 唯一真缺口:崩溃持久性只在 KB 声明、根本没测 | 保证声明纪律(PR-11)+reviewer-session落盘(PR-12)+tasks.md归属+台账清晰度 → **alpha.10** |
| r2 | 3改进全实战兑现;但挖深一层:持久性**做了却测错失败模式**(注入rename失败≠崩溃后存活)+**fsync漏目录**(high);UI**只走happy path**漏规格边界(选项上限4 vs 规格2..20、静默过滤空选项)(med×2) | 收紧:崩溃持久性必须kill-after-ack真测+fsync(file+dir);P7 UI必须压规格边界与拒绝路径 → **alpha.11** |
| r3 | 缺陷 **3(high:0 med:1 low:2)**——r2 的 fsync 目录 high **关闭**、UI 选项上限**修好**;残留 2 条"规则已有、执行 90%"(kill-after-ack 测试没重启走应用读回路;空选项 UI 仍预过滤) | 两处再收紧(PR-11 读回路+PR-13 呈现拒绝)→ **alpha.12**;循环收敛,停 |

**缺陷数轨迹**:V3 r1=3 → r2=6(1 high)→ **r3=3(0 high)**。r2 数字上升不是退步,是挖到更深一层(持久性从"没做"→"做了但测错失败模式");r3 把 high 关闭、UI 边界修好,降回 3 且无 high。对照:OpenSpec r1=7+严重DoS、Superpowers r1=5。**V3 r3 是全部构建里最优的:缺陷最少、零 high、零 DoS。**

**改进上溯的铁证**:r1 的持久性缺口(KB 声明没测)在 r3 的**设计文档**阶段就被写对了——fsync file+dir + kill-after-ack 对抗测试 + gate④ 追认的诚实边界(D4:2xx=已提交可见,跨崩溃持久性仅在 fsync 目录成功路径保证)。P8 复审还在 r3 抓到 agent 修 bug 时引入的"二阶保证措辞矛盾",按 §4.8 纪律诚实收窄措辞。规则改进真的把问题从"审计才发现"左移到了"设计阶段写对"。

## 三、G4 说明(不计为 V3 缺陷)

三轮里黑盒闯关 G4(防重)都"FAIL":客户端软限,裸 API 可灌票。但 V3 三次都**如实向用户描述了绕过方式**("换设备/清缓存/无痕就能再投"),用户在知情下明确选了浏览器软限。这是知情批准的产品取舍,规格诚实无过度承诺。在"匿名+免登录+浏览器级"约束内,localStorage 与 cookie 强度相当(都拦不住 curl)。
