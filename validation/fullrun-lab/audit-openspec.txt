    71	 * 校验一次投票提交并返回计票后的新 poll。
    72	 * choices: number[]（选项索引）

    75	export function castVote(poll, choices, now = new Date()) {
    76	  if (!isOpen(poll, now)) return fail('投票已结束');
    77	
    78	  if (!Array.isArray(choices) || choices.length === 0) return fail('请至少选择一项');
    79	  const uniq = [...new Set(choices)];
    80	  if (uniq.length !== choices.length) return fail('选项重复');
    81	  for (const c of uniq) {
    82	    if (!Number.isInteger(c) || c < 0 || c >= poll.options.length) return fail('存在无效选项');
    83	  }
    84	
    85	  if (!poll.multi) {
    86	    if (uniq.length !== 1) return fail('单选投票只能选择一项');
    87	  } else if (poll.maxChoices != null && uniq.length > poll.maxChoices) {
    88	    return fail(`最多可选 ${poll.maxChoices} 项`);
    89	  }
    90	
    91	  const counts = [...poll.counts];
    92	  for (const c of uniq) counts[c] += 1;
    93	  return { ok: true, poll: { ...poll, counts, totalVoters: poll.totalVoters + 1 } };
    94	}

     1	# Design: add-quick-poll
     2	
     3	## Context
     4	
     5	空仓库，从零构建。需求见 proposal.md 与 specs/：网页投票小工具，匿名免登录、多人共享结果、文件存储、发起人可关闭。用户明确约束：不上数据库、保持"小"。部署形态假定为单进程、单实例的小型 Node 服务。
     6	
     7	## Goals / Non-Goals
     8	
     9	**Goals:**
    10	- 一条命令启动的自包含 Web 服务（`node server.js` 或 `npm start`）。
    11	- 创建 → 分享 → 投票 → 看结果全流程，秒级上手，手机浏览器可用。
    12	- 并发提交下计票准确、文件不损坏。
    13	- 代码量与依赖面尽可能小，便于阅读与改造。
    14	
    15	**Non-Goals:**
    16	- 强防刷（跨设备/IP 级防重）、真实身份鉴权、登录体系。
    17	- WebSocket/SSE 实时推送（刷新即最新）。
    18	- 投票编辑、删除、列表/发现页、导出、多语言。
    19	- 多进程/多实例水平扩展（进程内写锁的前提是单进程）。
    20	
    21	## Decisions
    22	
    23	### D1: 零依赖 Node 原生 HTTP 服务（而非 Express/Fastify）
    24	需求只有约 7 个路由、无中间件需求。用 `node:http` + 手写小路由表即可，省掉 node_modules 与安全更新负担。备选 Express：更顺手但对这个体量是纯开销。**Node ≥ 18，ESM。**
    25	
    26	### D2: 服务端渲染 HTML 模板字符串，无前端框架、无构建步骤
    27	页面共 5 个（创建、创建成功、投票、结果、管理），均为简单表单/展示页。用模板函数（tagged template + HTML 转义工具）服务端拼 HTML，内联一份共享 CSS。表单用原生 `<form>` POST 提交（302 跳转），JS 仅用于"复制链接"按钮等增强，无 JS 也能完整投票。备选 SPA + JSON API：交互更花哨，但引入构建链与状态管理，违背"小"。
    28	
    29	### D3: 数据模型与文件布局
    30	```
    31	data/<pollId>.json
    32	{
    33	  "id": "x7Kp2mAq",            // nanoid 风格，[A-Za-z0-9_-]{8}，crypto 随机
    34	  "title": "午饭吃什么",
    35	  "options": ["面", "饭", "饺子"],
    36	  "multi": false,               // 单选/多选
    37	  "maxChoices": null,           // 多选上限；null = 不限
    38	  "deadline": null,             // ISO 8601 字符串或 null
    39	  "adminKey": "…",              // crypto 随机 24 字符
    40	  "closed": false,              // 手动关闭标记
    41	  "counts": [0, 0, 0],          // 与 options 对齐
    42	  "totalVoters": 0,             // 总提交人数（一人一次提交）
    43	  "createdAt": "…"
    44	}
    45	```
    46	开放判定为纯函数：`!closed && (!deadline || now < deadline)`。占比分母用 `totalVoters`（多选下各选项占比含义为"多少比例的人选了它"，总和可超 100%，页面注明）。
    47	
    48	### D4: 写并发控制——进程内每投票一条 promise 链 + 原子写
    49	每个 pollId 维护一条串行 promise 链（`Map<pollId, Promise>`），写操作（投票、关闭）排队执行"读文件 → 改 → 写临时文件 → rename"。rename 同目录内原子，读方永远看到完整 JSON。备选：文件锁库（proper-lockfile）——为多进程设计，这里单进程用不上；追加日志（JSONL）——重启需重放，复杂化读路径。
    50	
    51	### D5: 软防重用 Cookie
    52	投票成功后 `Set-Cookie: voted_<pollId>=1`（一年有效、SameSite=Lax、Path 限定该投票路径）。GET 投票页与 POST 投票时检查该 Cookie：GET 重定向到结果页，POST 拒绝（303 到结果页）。备选 localStorage：需要 JS 且服务端无法在 POST 时校验，Cookie 两端都能看到，更符合"无 JS 也能用"。
    53	
    54	### D6: 安全基线
    55	- pollId 与 adminKey 均来自 `crypto.randomBytes`，URL 安全字母表；ID 不可枚举。
    56	- 路由参数白名单校验 `^[A-Za-z0-9_-]+$`，杜绝路径穿越（specs/poll-storage）。
    57	- 所有用户输入输出经 HTML 转义，防 XSS。
    58	- adminKey 校验用 `crypto.timingSafeEqual`；错误一律 404，不暴露管理入口存在性。
    59	- 请求体大小上限（16KB）防滥用。
    60	
    61	### D7: 目录结构
    62	```
    63	openspec-poll/
    64	├── server.js          # 入口：http server + 路由分发

Static read-only audit; I did not run the app or tests.

- [security] `server.js:101` - Admin key is placed in `/created?key=...`, so it appears outside the management link in redirect headers, address bar, browser history, and typical proxy/access logs. This violates the spec’s “admin key only in storage file and management link” rule. Severity: med.

- [data] `lib/store.js:60` - `createPoll()` blindly writes `poll.id`. If `newPollId()` ever collides, the new poll overwrites the existing poll file, destroying votes and replacing the admin key. Severity: med.

- [data] `lib/store.js:55` - “atomic write” does `writeFile()` then `rename()` without fsyncing the temp file or directory. A host crash/power loss around the write/rename can leave the poll missing, stale, or not durably written despite the storage spec’s crash/restart expectations. Severity: med.

- [data] `server.js:122` - Soft duplicate prevention only checks the incoming cookie. Two near-simultaneous POSTs from the same browser before the first `Set-Cookie` response is processed both count as successful votes. Concrete case: double-submit a form quickly; total voters increases by 2. Severity: med.

- [robustness] `lib/store.js:89` - `writeChains` entries are never removed after a poll’s queue drains. Repeated creation/voting across many unique poll IDs grows this Map for the life of the process, enabling unbounded memory growth. Severity: med.

- [correctness] `server.js:115` - For a closed or expired poll, `GET /p/:id` redirects straight to results. The lifecycle spec says the participant link should display “投票已结束” and guide to results; `pages.closedPage()` exists but is only used after failed POSTs. Severity: low.

- [robustness] `server.js:124` - Vote choices are parsed with `Number()`, so malformed form values like `choice=` or `choice=0x1` become valid indexes `0`/`1`. A malformed POST can be accepted as a vote instead of rejected as an invalid option index. Severity: low.

Test quality: The unit tests cover domain logic boundaries and the store’s normal queued-write behavior, and the Playwright script exercises real browser/server flows, which is valuable. But several tests mirror implementation choices rather than the normative specs, especially closed/expired polls redirecting to results. They do not cover malformed POST values, in-flight duplicate submits, admin-key URL exposure, ID collision handling, memory growth in `writeChains`, or crash durability of file writes.
