# 需求：快速投票小工具（quick-poll）— FINAL

> 目标线（lineage）：master（主线，空仓起步，无 merge 禁忌）
> 状态：STEP0 收敛于 round 3，`VERDICT: no major issues`（内容等同 req-v3）。REQ-1..REQ-10 全部 verified。

## 1. 目标（Target State B）

一个零门槛的网页投票小工具。发起人填「标题 + 若干选项」建出一个投票，拿到两条链接：**投票链接**（分享给大家）和**管理链接**（只有发起人持有，用于关闭/管理）。拿到投票链接的人**无需登录、匿名**、一次点击即可投票；投完立即看到实时结果。适用于开会、群里几十人快速征集意见。

## 2. 目标用户与规模

- **发起人**：想快速征集意见的人（会议主持、群主、组织者）。
- **投票人**：拿到链接的同事/朋友，**匿名、不登录**，单次投票量级约几十人（数量级 10–100，非高并发）。

## 3. 数据模型与校验规则（REQ-1 / REQ-3 / REQ-4）

**投票对象（poll）字段**：`pollId`、`title`、`options[]`、`mode`、`deadline?`、`status`、`counts[]`、`adminKey`。

**标识符生成（REQ-3 / REQ-9）**：`pollId` 与 `adminKey` **均**由 **CSPRNG**（`crypto.randomBytes`）生成，**各 ≥128 bit 熵**，URL-safe base64 编码；**均不得从创建顺序/时间推断**（禁止递增或时间戳派生 ID）。`adminKey` 在任何日志/错误信息中不得出现。

**选项归一化（REQ-1，消歧）**：
- 每个提交的选项文本前后 **trim**；**trim 后为空 → 直接拒绝创建**（不做静默丢弃，避免"有效选项数"歧义）。
- 有效选项数 = 提交的选项数，必须落在 **2..20**。
- 允许两个选项显示文本相同（不去重文本），但每个选项由服务端分配**稳定 option ID**（`opt-0 … opt-{k-1}`，按提交顺序）。**投票提交的是 option ID，不是文本**——计票、去重、校验一律基于 option ID。
- 单个选项文本 trim 后长度 1..200 字符。

**创建请求 schema 与输入校验（REQ-4 / REQ-10）**：
- 类型契约：`title` 必须为 string；`options` 必须为 array of string；`mode` 必须为 string；`deadline`（若提供）为 string 或 integer。**任一字段缺失、为 null 或类型错误 → 400，且不创建任何记录。**
- `title`：trim 后长度 1..200，否则拒绝。
- 有效选项数：**2..20**（含空选项即拒绝，见上），否则拒绝。
- `mode` ∈ {`single`, `multiple`}，缺失或非法 → 拒绝。
- `deadline`：可选；提供时必须是合法时间且 **晚于当前服务器时间**，否则拒绝（malformed / 过去时间均拒绝）。

**管理密钥（REQ-3）**：`adminKey` 由 **CSPRNG** 生成（`crypto.randomBytes`），**≥128 bit 熵**，URL-safe base64 编码，随管理链接下发；**任何日志/错误信息中不得出现 adminKey**。

## 4. 时间与截止（REQ-2）

- 创建时 `deadline` 输入格式：**ISO 8601 带时区**（如 `2026-07-09T18:00:00+08:00`）或 epoch 毫秒整数；二者其一。
- 存储：一律转为 **epoch 毫秒（UTC 基准）**。
- 关闭判定基准：**服务器时间 `Date.now()`（UTC）**；「已到期」当且仅当 `Date.now() >= deadline`。
- 该判定在处理请求**进入 per-poll 临界区那一刻**求值（见 §7 并发）。

## 5. 核心场景（每个用户可见输出对应一个带稳定 ID 的验收项）

### 建投票
- **PC-01 创建投票**：提交合法「标题 + 2..20 有效选项 + mode + 可选 deadline」→ 创建投票，返回投票链接 + 管理链接（含 adminKey）。
- **PC-02 创建输入校验**：违反 §3/§4 任一校验（空标题/超长、选项<2 或>20、空选项、非法 mode、malformed 或过去 deadline）→ 拒绝创建，HTTP 非 2xx，可读错误，**不创建任何投票记录**。

### 投票
- **PC-03 投票（单选）**：单选下提交**恰好一个** option ID → 该选项计数 +1，进入结果视图。
- **PC-03b 单选多传拒绝**：单选下提交多于一个 option ID → 拒绝（非 2xx），计数不变。
- **PC-04 投票（多选）**：多选下提交 k(k≥1) 个**互不相同**的 option ID → 各 +1；k=0（未选）→ 拒绝并提示。
- **PC-05 浏览器软限重复投票**：同一浏览器对同一投票默认只记一次；成功投票（2xx）后本地置标记；再次打开投票链接 → 直接进入结果视图。标记存于浏览器 **localStorage**，key 作用域为 `origin + pollId`；换设备/清缓存/无痕不受本工具阻止（刻意的零门槛取舍）。
- **PC-12 非法投票请求**：unknown `pollId` → 404；unknown option ID、重复 option ID、payload 类型错误或为空 → 400；以上任一情况**计数与状态均不变**。

### 看结果
- **PC-06 投完即看实时结果**：提交成功后进入结果视图，显示各选项票数与总票数；结果页**加载即拉取一次**，此后每 **3000ms**（`POLL_INTERVAL_MS` 常量，可配置）自动拉取最新结果（轮询，非推送）。结果 endpoint 返回 `{title, options:[{id,text,count}], total, status, deadline}`。

### 关闭与生命周期
- **PC-07 到点自动关闭**：设了 deadline 的投票，当 `Date.now() >= deadline` → 视为「已关闭」；此后投票提交返回非 2xx 并提示已结束，结果仍可读。
- **PC-08 发起人手动关闭**：持**有效 adminKey** 者可将投票置为「已关闭」；无有效 adminKey 的关闭请求被拒绝（非 2xx），状态不变。关闭后投票提交返回非 2xx，结果仍可读。
- **PC-09 已关闭态可见**：已关闭时，投票/结果视图显式呈现「已关闭」（含关闭原因/截止信息），不渲染投票提交控件。

### 存储与并发（外部共享状态——三个时刻见 §7）
- **PC-10 并发投票不丢票**：多名投票人几乎同时对同一投票提交合法票时，所有合法票都被计入，最终各选项计数 = 各自合法提交次数之和（无读改写交叠覆盖）。
- **PC-11 崩溃不产生半写文件**：写入过程中进程中断，投票数据文件要么是旧完整内容、要么是新完整内容，绝不半写损坏（临时文件 + 原子 rename）。
- **PC-13 失败不产生"假成功"**：create/vote/close **仅在持久化写成功后**返回 2xx；写失败（disk full、rename 失败、超时等）→ 返回非 2xx，且计数/状态/浏览器已投标记均不改变。（REQ-7）

## 6. 验收标准（可测，"若…则…"）

- PC-01：若提交合法输入，则响应含两条链接，投票链接≠管理链接，管理链接含 adminKey。
- PC-02：若违反任一创建校验（含字段缺失/null/类型错误、空标题/超长、含空选项、选项<2 或>20、非法 mode、malformed 或过去 deadline），则非 2xx（类型/schema 错误为 400）且未创建任何投票记录。
- PC-03 / PC-03b：单选恰好一项 → +1 并导向结果；单选传多项 → 非 2xx 且计数不变。
- PC-04：多选传 k≥1 个不同 option ID → 各 +1；k=0 → 非 2xx。
- PC-05：同一浏览器已投后再次访问投票链接 → 直接结果视图（localStorage 标记，作用域 origin+pollId）。
- PC-06：投票成功 → 结果视图显示各票数与总数；加载即拉取一次，之后每 3000ms 拉取；结果响应形状如上。
- PC-07：若 `Date.now() >= deadline`，则状态为已关闭，投票提交非 2xx，结果可读。
- PC-08：持有效 adminKey 请求关闭 → 状态已关闭；无有效 adminKey 请求关闭 → 非 2xx 且状态不变。
- PC-09：已关闭时视图显式呈现「已关闭」且不渲染投票控件。
- PC-10：并发多次合法投票 → 最终各选项计数 = 各自合法提交次数之和（无丢失）。
- PC-11：写文件过程中模拟中断 → 文件为旧完整或新完整，绝不半写损坏。
- PC-12：unknown pollId→404；unknown/重复 option、非法/空 payload→400；计数与状态均不变。
- PC-13：写失败时 → 非 2xx，且计数/状态/浏览器标记均不变。

## 7. 外部共享状态的三个时刻（文件存储）

- **初始化**：创建投票时用 CSPRNG 生成 `pollId` + `adminKey`（各 ≥128 bit，不可枚举，见 §3），落一个投票数据文件（title、options[含 id]、mode、deadline(epoch ms)、counts=0、status=open）。
- **运行时更新**：每次 vote / close，在单一 Node 进程内用**按 pollId 串行化的写队列（per-poll lock）**执行读改写；**状态与截止判定在同一临界区内、进入临界区时求值**（REQ-6：若已 closed 或 now≥deadline → 拒绝，不计票）；写盘用**临时文件 + 原子 rename**（PC-11），rename 成功才算 durable，之后才返回 2xx（PC-13）。
- **清理 / 失效**：v1 无自动清理（非目标）；「已关闭」为逻辑失效标志，数据仍保留可读。

## 8. 技术方案（brainstorm 选定）

单个 Node 服务；**文件存储（无数据库）**；服务端渲染页面 + 少量前端 JS；结果视图轮询刷新。并发安全按 §7 处理。

## 9. 非目标（明确不做，附原因）

- 账号 / 登录 / 注册——要的就是零门槛匿名。
- IP 防刷票——同办公室共用出口 IP 会误伤同事。
- 改票——避免计数回滚复杂度。
- 建成后改标题/选项——已投票会与改后选项对不上。
- 结果导出（CSV 等）——v1 用不上。
- 结果可见性开关（隐藏/揭晓）——用得少，默认「投完即看」。
- 实时推送（WebSocket）——几十人量级轮询即可。
- 投票数据自动过期/垃圾回收——v1 不做。
- 数据库（含 SQLite）——发起人明确不装 DB；用文件存储（并发安全由 §7 保证）。
