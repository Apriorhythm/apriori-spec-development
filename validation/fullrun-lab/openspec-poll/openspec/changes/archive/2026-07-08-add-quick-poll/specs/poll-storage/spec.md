# poll-storage

## ADDED Requirements

### Requirement: 每投票一个 JSON 文件
系统必须（SHALL）将每个投票持久化为数据目录下以投票 ID 命名的单个 JSON 文件（`data/<id>.json`），不使用数据库。文件必须包含：标题、选项列表、投票模式、多选上限（如有）、截止时间（如有）、管理密钥、是否已手动关闭、各选项票数、总提交人数、创建时间。数据目录不存在时系统启动必须自动创建。

#### Scenario: 创建投票即落盘
- **WHEN** 投票创建成功
- **THEN** 数据目录下存在 `<id>.json`，内容为合法 JSON 且包含全部上述字段

#### Scenario: 服务重启数据不丢
- **WHEN** 服务进程重启后访问已有投票的参与链接或结果页
- **THEN** 投票定义与已有票数与重启前一致

### Requirement: 原子且串行的写入
系统必须（MUST）对同一投票文件的写入串行化（进程内按投票 ID 排队），且每次写入必须为原子写：先写入同目录临时文件，再 rename 覆盖目标文件。任何时刻目标文件必须是完整合法的 JSON，不得出现半写状态。

#### Scenario: 并发写不损坏文件
- **WHEN** 同一投票收到多个并发提交
- **THEN** 全部提交处理完毕后，该投票文件为合法 JSON 且计票与成功提交数一致

#### Scenario: 投票 ID 即文件名的安全性
- **WHEN** 请求路径中的投票 ID 包含 `.`、`/` 等非法字符
- **THEN** 系统必须拒绝该请求（404），绝不将其拼接为文件路径读写
