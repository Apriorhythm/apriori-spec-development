# poll-lifecycle Specification

## Purpose

定义投票的开放/关闭状态：截止时间被动判定与发起人手动关闭。

## Requirements

### Requirement: 投票开放状态判定
系统必须（SHALL）按以下规则判定投票是否开放：投票开放，当且仅当其未被手动关闭，且（无截止时间，或当前时间早于截止时间）。截止判定必须在每次请求时被动计算，不依赖定时任务。已关闭的投票仅可查看结果。

#### Scenario: 到达截止时间自动结束
- **WHEN** 参与者在截止时间之后打开该投票的参与链接
- **THEN** 系统展示"投票已结束"并引导至结果页，不提供投票表单

#### Scenario: 无截止时间且未关闭则持续开放
- **WHEN** 参与者打开无截止时间且未被手动关闭的投票
- **THEN** 系统正常展示投票表单

### Requirement: 发起人手动关闭投票
系统必须（SHALL）允许持有正确管理密钥者通过管理页 `/p/<id>/admin/<密钥>` 关闭投票。关闭操作必须校验密钥与存储中的管理密钥一致；密钥错误时必须返回 404（不提示"密钥错误"以避免确认投票管理入口的存在）。关闭为不可逆操作，关闭后再次访问管理页显示"已关闭"状态。

#### Scenario: 管理链接关闭投票
- **WHEN** 发起人打开正确的管理链接并点击"关闭投票"
- **THEN** 投票状态变为已关闭，后续投票提交被拒绝，结果页状态显示"已结束"

#### Scenario: 错误密钥被拒绝
- **WHEN** 任何人使用错误的管理密钥访问管理页或提交关闭操作
- **THEN** 系统返回 404，投票状态不变

#### Scenario: 重复关闭幂等
- **WHEN** 发起人对已关闭的投票再次提交关闭操作
- **THEN** 系统保持已关闭状态并正常展示"已关闭"，不报错
