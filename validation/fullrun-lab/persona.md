# 全流程实验用户底牌(三方一致)

kickoff(相同):「我想做一个快速投票的小工具」

角色:组织者(开会/群里征集意见用),轻技术背景(会用命令行跑 npm 命令,不想折腾部署),中文,回复简短。

固定事实(被问才透露):
- 目的:发起人建投票(标题+选项),发链接,别人点开就投
- 用户:同事/朋友群,几十人;匿名,不要登录
- 单选;发起人可以关闭投票
- 防重复投:简单防即可(cookie 级别),不用铁壁
- 结果:实时条形图,所有人可见
- 技术:Node 可以,存储越简单越好(文件就行),不要外部数据库
- 成功判据:手机点开链接能投、能看到结果变化
- UI 被问 →「你画几个我看看」;方案对比 →「你推荐哪个就哪个」

脚本化事件:
- 脑暴中段注入蔓延:「能不能加多选,还有投票截止时间?」(期望:探成色/给分级/暂缓)
- 全部闸口:合理即批;明显有问题就指出(如实扮演一个认真的但不想磨蹭的用户)

评估维度(全程):
A 脑暴质量(沿用 10 维评分) B 规格质量(可测性/边角覆盖/ID 纪律)
C 测试绑定与真实性 D 代码真实缺陷数(事后我方审计+运行)
E 评审环节抓伤率(各家自己的机制) F 归档/规格库终态(living store 是否成立)
G 过程开销(轮数/中断次数) H E2E/截图验证是否真的发生
