# Proposal — quick-poll（一页纸）

## WHY（为什么做）
开会 / 群里需要几十人快速表态时，现有工具要么要登录注册（门槛高），要么要装 App。目标：**发起人 30 秒建出投票，拿链接分享，几十人不登录、点一下就投，投完即看实时结果。**

## WHAT（做什么）
单个 Node 服务 + **文件存储（无数据库）**，服务端渲染页面 + 少量前端 JS：
- **建投票**：标题 + 2..20 选项 + 单/多选 + 可选截止时间 → 返回**投票链接**与**管理链接**（含 CSPRNG 密钥）。
- **投票**：匿名、不登录；单选恰一项 / 多选 ≥1 项；同浏览器 localStorage 软限重复。
- **看结果**：投完进结果页，加载即拉一次 + 每 3000ms 轮询刷新。
- **关闭**：到截止时间自动关闭；发起人凭管理密钥手动关闭。关闭后不能再投，结果仍可读。

覆盖 14 个带 ID 的验收场景（PC-01..PC-14，见 `specs/poll.md`）。

## 部署前提（锁定 · gate② 已确认）
**单进程、单实例部署（内网一台机器）。** 并发正确性（不丢票 / 不半写 / 无假成功）依赖"单 Node 进程内的 per-poll 写队列 + 原子 rename"，**只在单进程下成立**。多实例部署会使内存锁失效——本变更明确不支持，spec 与 design 均声明此前提。

## 三条硬保证 + 对抗测试（锁定 · gate② 要求）
| 保证 | 场景 | 对抗测试（注入条件） |
|---|---|---|
| 并发不丢票 | PC-10 | 并发 N 个投票请求打同一投票，断言最终计数 = 合法提交数之和 |
| 崩溃不半写 | PC-11 | 写入中途注入失败/中断，断言文件为旧完整或新完整、绝不半写 |
| 无假成功 | PC-13 | 注入写失败，断言返回非 2xx 且计数/状态/标记均不变 |

## OUT OF SCOPE（明确不做，附原因）
- 账号/登录/注册——要的就是零门槛匿名。
- IP 防刷——同办公室共用出口 IP 会误伤同事。
- 改票 / 建后改题改选项——避免计数与选项对不上的复杂度。
- 结果导出、结果可见性开关、实时推送(WebSocket)、数据自动过期——用不上或量级不需要。
- **数据库（含 SQLite）**——发起人明确不装 DB。
- **多实例/多进程部署**——见上"部署前提"。
