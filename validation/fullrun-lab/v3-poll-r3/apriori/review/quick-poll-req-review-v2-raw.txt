# 需求:quick-poll —— 快速匿名投票小工具

> change: `quick-poll` · tier: medium · track: harden
> target lineage: **master (mainline)** —— 全新仓库,无合并禁忌
> 状态:req-v2(据 quick-poll-req-review-v1 修订,待 STEP0 round 2 评审)

## 1. 目标(Goal / 目标态 B)

任何人都能在几十秒内创建一个**单问题投票**(标题 + 若干选项),拿到一条分享链接;几十位同事/朋友点开链接,**匿名、免登录、无需安装**,投一票后立刻看到实时汇总结果。发起人另持一条私密**管理链接**,可随时手动关闭投票,或预设截止时间到点自动关闭。

用途:开会或群里**征集意见**。核心价值 = 发起与参与都几乎零成本。

技术路线(brainstorm 拍板,方案 1):**Node 标准库 HTTP 服务 + 每个投票一个 JSON 文件**;前端为服务端渲染的简单页面 + 少量原生 JS;不使用数据库;并发写入由应用层解决(每投票串行化 + 原子落盘)。

## 2. 目标用户

- **发起人**:开会主持人、群主、任何想快速收集意见的人。免登录;创建投票后凭"管理链接"行使管理权。
- **投票人**:同事、朋友,数量级为**几十人(设计目标约 50 人并发)**。匿名、免登录、手机或电脑浏览器点开即用。

## 3. 核心场景

1. **创建投票**:发起人填标题 + 2–10 个选项,选择单选/多选(默认单选),可选设置截止时间,提交后得到两条链接:**分享链接**(投票用)与**管理链接**(私密,含管理凭证)。
2. **投票**:投票人打开分享链接,看到标题与选项;单选投票选一项,多选投票选一或多项;提交后立刻看到实时结果(每项票数 + 百分比 + 条形,顶部显示总投票人数)。
3. **看结果**:投过的人(同一浏览器)再次打开分享链接,直接看到结果页,不再显示投票表单(软拦截)。任何人打开已关闭投票的分享链接,看到结果且不能再投。
4. **关闭投票**:发起人打开管理链接可手动关闭;若设了截止时间,到点自动关闭。关闭后拒绝新票,结果仍可查看。

## 4. UI 形态(brainstorm 草图,详细设计在 STEP2)

- **创建页**:标题输入框、选项列表(可增删,2–10 项)、单选/多选开关、可选截止时间、"生成投票链接"按钮 → 结果展示两条链接。
- **投票页**(分享链接):标题 + 选项(单选=radio,多选=checkbox)+ 提交按钮;已关闭则不显示提交。
- **结果页**:每项条形 + 票数 + 百分比 + 总人数;顶部标明投票是否已关闭。
- **管理页**(管理链接):投票概览 + "关闭投票"按钮 + 结果视图。

## 5. 数据与内容

每个投票持久化为一个 JSON 文件(文件名 = `<pollId>.json`),字段至少含:

- `id`:poll id,服务端用 CSPRNG 生成,字符集 `[A-Za-z0-9_-]`(URL-safe,≥16 字符),避免路径穿越。
- `title`:标题(trim 后非空,≤100 字)。
- `options`:选项数组,每项 `{ id, text, votes }`;`text` trim 后非空、≤50 字;选项数 2–10;**允许重复选项文本**(不去重,由发起人负责)。
- `mode`:`"single"` | `"multi"`(默认 `single`)。
- `createdAt`:创建时间(epoch millis, UTC)。
- `deadline`:可选,epoch millis(UTC);缺省表示无自动截止。
- `status`:`"open"` | `"closed"`(手动关闭时持久化为 `closed`)。
- `totalVoters`:总投票人数(= 成功投票请求数)。
- `adminToken`:管理凭证,**仅存服务端此文件**,绝不出现在分享链接/分享页 HTML/JS/接口响应中。

约束:标题 ≤100 字、选项 ≤50 字均按 trim 后的字符数计;空白经 trim 判空。投票文件**长期保留**,不做自动清理;关闭后结果仍可查看。

**软拦截"已投过"状态**:记在投票人浏览器 `localStorage`,键按 **poll id 隔离**(如 `voted:<pollId>`);**仅在服务端返回投票成功(2xx)后**写入;写入失败不影响服务端计票,但页面仍显示结果页;投票失败(非 2xx)**不得**写标记。不同投票之间互不污染。

## 6. deadline 语义(REQ-1)

- 输入格式:ISO 8601(前端 `datetime-local` 采集,提交给服务端换算为 epoch millis UTC 存储)。
- 判定:请求到达时若 `now >= deadline`(含刚好相等)→ 该投票视为 **closed**,拒绝新票。
- 创建时:`deadline` 必须晚于当前时间;**提交过去或等于当前的 deadline → 拒绝创建**(错误码 `DEADLINE_IN_PAST`)。

## 7. 管理凭证安全(REQ-2)

- `adminToken` 用 CSPRNG 生成,**≥128-bit** 熵(如 32 hex / 24 字节 base64url)。
- 仅存于服务端 poll JSON;校验用**常量时间比较**。
- 缺失或错误 token 的管理操作 → `403 INVALID_ADMIN_TOKEN`,不改变投票状态。
- 分享链接、投票页 HTML/JS、以及任何面向投票人的接口响应**均不得包含** `adminToken`。

## 8. 持久化与失败回滚(REQ-3)

- 一次投票**只有在持久化成功后才返回 2xx 成功**。
- 原子落盘 = 写临时文件 → `fsync(临时文件)` → `rename` 覆盖 → `fsync(目录)`;任一环节失败 → 返回 `500 PERSIST_FAILED`,**不更新任何可观测结果**(内存计数在持久化成功后才对外可见,失败即回滚/不提交)。
- 旧 JSON 文件在写入失败时必须保持可读(rename 前不破坏旧文件)。
- 启动时读到损坏/无法解析的 JSON 文件 → 记日志并跳过该文件,不导致进程崩溃。

## 9. 并发与"成功请求"定义(REQ-4)

- **成功请求 = 服务端返回 2xx 的投票请求**。AC-11 的"成功请求数"以此为准。
- 每个 poll 一条**串行化写入队列**:进入临界区的请求按序完成"计票 + 持久化",互不覆盖。
- 计票只在持久化成功后对外可见;若持久化失败则该请求返回非 2xx 且不计票。
- MVP 规模(数十人)不设人为队列上限;请求体设**大小上限**(如 16KB)防滥用,超限 → `413 PAYLOAD_TOO_LARGE`。

## 10. 结果展示与百分比(REQ-6)

- 百分比公式:`round(optionVotes / totalVoters * 100)`,显示为**整数(四舍五入)**。
- `totalVoters == 0` 时,所有选项显示 `0%`。

## 11. 错误码与 HTTP 状态(REQ-7)

统一 JSON 错误体 `{ "error": "<CODE>", "message": "<可读说明>" }`:

| 场景 | HTTP | error code |
|---|---|---|
| 标题空/仅空白 | 400 | `TITLE_REQUIRED` |
| 标题超长 | 400 | `TITLE_TOO_LONG` |
| 选项空/仅空白 | 400 | `OPTION_REQUIRED` |
| 选项超长 | 400 | `OPTION_TOO_LONG` |
| 选项数 <2 或 >10 | 400 | `OPTION_COUNT_OUT_OF_RANGE` |
| deadline 非未来 | 400 | `DEADLINE_IN_PAST` |
| 投票/管理:poll 不存在 | 404 | `POLL_NOT_FOUND` |
| 投给不存在的选项 id | 400 | `OPTION_NOT_FOUND` |
| single 模式投多项 | 400 | `SINGLE_CHOICE_VIOLATION` |
| 未选任何项 | 400 | `NO_SELECTION` |
| 投票时 poll 已关闭/过截止 | 409 | `POLL_CLOSED` |
| 管理 token 缺失/错误 | 403 | `INVALID_ADMIN_TOKEN` |
| 请求体超限 | 413 | `PAYLOAD_TOO_LARGE` |
| 持久化失败 | 500 | `PERSIST_FAILED` |

## 12. 接口草案(最小,详细在 STEP2 design)

- `POST /api/polls` → 创建;body `{title, options[], mode, deadline?}`;返回 `{shareUrl, adminUrl}`。
- `GET /poll/<id>` → 投票/结果页(HTML)。
- `POST /api/polls/<id>/vote` → 投票;body `{optionIds[]}`;返回结果 JSON。
- `GET /api/polls/<id>` → 结果 JSON(**不含 adminToken**)。
- `POST /api/polls/<id>/close` → 关闭;需带 `adminToken`(header 或 body)。
- `GET /admin/<id>?token=<adminToken>` → 管理页(HTML)。

## 13. 可测收尾标准(Acceptance —— 每条 "if … then …" 可测)

### 维度 2: 边界与异常路径是否覆盖

结论: 有新增阻塞问题 REQ-10、REQ-11。

#### REQ-10: 单次投票请求内重复 optionIds 的语义未定义

描述: multi 模式允许提交多个选项，但未说明同一个 `optionId` 在一次请求中重复出现时应去重还是拒绝。single 模式也只说明“多于一项”拒绝，未说明 `["a","a"]` 算一项还是违反。

风险: 恶意或异常客户端可在一次请求中重复同一选项，导致某选项 +2 但 `totalVoters` 只 +1；不同实现会产生不同计票结果。

建议修复: 明确 `optionIds` 在一次请求内必须去重后处理，或更严格地要求出现重复即 `400 DUPLICATE_OPTION_ID` 且不计票。建议采用拒绝重复，便于测试和防止计票膨胀。

#### REQ-11: 关闭操作与投票操作的并发顺序未明确

描述: §9 明确了投票请求的串行化写入，但未明确管理关闭操作是否也进入同一 poll 的写入队列，以及关闭与投票同时到达时按什么顺序判定。

建议修复: 明确所有会修改同一 poll 文件的操作，包括 vote 和 close，都必须进入同一 per-poll mutation queue；按进入队列顺序串行执行。vote 执行时重新检查 `status/deadline`；close 成功持久化后，后续 vote 必须返回 `409 POLL_CLOSED`。
