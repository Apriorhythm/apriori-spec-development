# 需求:quick-poll —— 快速匿名投票小工具

> change: `quick-poll` · tier: medium · track: harden
> target lineage: **master (mainline)** —— 全新仓库,无合并禁忌
> 状态:**req-final**(STEP0 于 round 3 通过 —— VERDICT: no major issues;REQ-1..REQ-11 全部 verified)

## 1. 目标(Goal / 目标态 B)

任何人都能在几十秒内创建一个**单问题投票**(标题 + 若干选项),拿到一条分享链接;几十位同事/朋友点开链接,**匿名、免登录、无需安装**,投一票后立刻看到实时汇总结果。发起人另持一条私密**管理链接**,可随时手动关闭投票,或预设截止时间到点自动关闭。

用途:开会或群里**征集意见**。核心价值 = 发起与参与都几乎零成本。

技术路线(brainstorm 拍板,方案 1):**Node 标准库 HTTP 服务 + 每个投票一个 JSON 文件**;前端为服务端渲染的简单页面 + 少量原生 JS;不使用数据库;并发写入由应用层解决(每投票串行化 + 原子落盘)。

## 2. 目标用户

- **发起人**:开会主持人、群主、任何想快速收集意见的人。免登录;创建投票后凭"管理链接"行使管理权。
- **投票人**:同事、朋友,数量级为**几十人(设计目标约 50 人并发)**。匿名、免登录、手机或电脑浏览器点开即用。

## 3. 核心场景

1. **创建投票**:发起人填标题 + 2–10 个选项,选择单选/多选(默认单选),可选设置截止时间,提交后得到两条链接:**分享链接**(投票用)与**管理链接**(私密,含管理凭证)。
2. **投票**:投票人打开分享链接,看到标题与选项;单选投票选一项,多选投票选一或多项;提交后立刻看到实时结果(每项票数 + 百分比 + 条形,顶部显示总投票人数)。
3. **看结果**:投过的人(同一浏览器)再次打开分享链接,直接看到结果页,不再显示投票表单(软拦截)。任何人打开已关闭投票的分享链接,看到结果且不能再投。
4. **关闭投票**:发起人打开管理链接可手动关闭;若设了截止时间,到点自动关闭。关闭后拒绝新票,结果仍可查看。

## 4. UI 形态(brainstorm 草图,详细设计在 STEP2)

- **创建页**:标题输入框、选项列表(可增删,2–10 项)、单选/多选开关、可选截止时间、"生成投票链接"按钮 → 结果展示两条链接。
- **投票页**(分享链接):标题 + 选项(单选=radio,多选=checkbox)+ 提交按钮;已关闭则不显示提交。
- **结果页**:每项条形 + 票数 + 百分比 + 总人数;顶部标明投票是否已关闭。
- **管理页**(管理链接):投票概览 + "关闭投票"按钮 + 结果视图。

## 5. 数据与内容

每个投票持久化为一个 JSON 文件(文件名 = `<pollId>.json`),字段至少含:

- `id`:poll id,服务端用 CSPRNG 生成,字符集 `[A-Za-z0-9_-]`(URL-safe,≥16 字符),避免路径穿越。
- `title`:标题(trim 后非空,≤100 字)。
- `options`:选项数组,每项 `{ id, text, votes }`;`text` trim 后非空、≤50 字;选项数 2–10;**允许重复选项文本**(不去重,由发起人负责)。
- `mode`:`"single"` | `"multi"`(默认 `single`)。
- `createdAt`:创建时间(epoch millis, UTC)。
- `deadline`:可选,epoch millis(UTC);缺省表示无自动截止。
- `status`:`"open"` | `"closed"`(手动关闭时持久化为 `closed`)。
- `totalVoters`:总投票人数(= 成功投票请求数)。
- `adminToken`:管理凭证,**仅存服务端此文件**,绝不出现在分享链接/分享页 HTML/JS/接口响应中。

约束:标题 ≤100、选项 ≤50,长度口径统一为 **Unicode code points**(`[...str].length`,trim 后计;避免 emoji/代理对在边界测试中不一致);空白经 trim 判空。投票文件**长期保留**,不做自动清理;关闭后结果仍可查看。手动关闭时 `status` 持久化为 `"closed"`;因 deadline 过期而"视为 closed"的投票,首次被访问/写入时**也持久化** `status:"closed"`(便于文件状态观察,REQ-ADV-2)。

**软拦截"已投过"状态**:记在投票人浏览器 `localStorage`,键按 **poll id 隔离**(如 `voted:<pollId>`);**仅在服务端返回投票成功(2xx)后**写入;写入失败不影响服务端计票,但页面仍显示结果页;投票失败(非 2xx)**不得**写标记。不同投票之间互不污染。

## 6. deadline 语义(REQ-1)

- 输入格式:ISO 8601(前端 `datetime-local` 采集,提交给服务端换算为 epoch millis UTC 存储)。
- 判定:请求到达时若 `now >= deadline`(含刚好相等)→ 该投票视为 **closed**,拒绝新票。
- 创建时:`deadline` 必须晚于当前时间;**提交过去或等于当前的 deadline → 拒绝创建**(错误码 `DEADLINE_IN_PAST`)。

## 7. 管理凭证安全(REQ-2)

- `adminToken` 用 CSPRNG 生成,**≥128-bit** 熵(如 32 hex / 24 字节 base64url)。
- 仅存于服务端 poll JSON;校验用**常量时间比较**。
- 缺失或错误 token 的管理操作 → `403 INVALID_ADMIN_TOKEN`,不改变投票状态。
- 分享链接、投票页 HTML/JS、以及任何面向投票人的接口响应**均不得包含** `adminToken`。

## 8. 持久化与失败回滚(REQ-3)

- 一次投票**只有在持久化成功后才返回 2xx 成功**。
- 原子落盘 = 写临时文件 → `fsync(临时文件)` → `rename` 覆盖 → `fsync(目录)`;任一环节失败 → 返回 `500 PERSIST_FAILED`,**不更新任何可观测结果**(内存计数在持久化成功后才对外可见,失败即回滚/不提交)。
- 旧 JSON 文件在写入失败时必须保持可读(rename 前不破坏旧文件)。
- 启动时读到损坏/无法解析的 JSON 文件 → 记日志并跳过该文件,不导致进程崩溃。

## 9. 并发、串行化与"成功请求"定义(REQ-4 / REQ-11)

- **成功请求 = 服务端返回 2xx 的投票请求**。AC-11 的"成功请求数"以此为准。
- **每个 poll 一条 per-poll mutation queue**:所有会修改该 poll 文件的操作——**投票(vote)与关闭(close)一律进入同一队列**——按入队顺序串行执行,互不覆盖(REQ-11)。
- vote 在**执行时(而非入队时)重新检查** `status`/`deadline`:若此刻已 closed 或已过 deadline → `409 POLL_CLOSED`,不计票。
- close 成功持久化后,队列中其后的 vote 必检查到 closed 并返回 `409`。
- 计票只在持久化成功后对外可见;若持久化失败则该请求返回非 2xx 且不计票。
- MVP 规模(数十人)不设人为队列上限;请求体设**大小上限 16 KiB(16384 字节)**防滥用,超限 → `413 PAYLOAD_TOO_LARGE`。
- **重复关闭**:对已 closed 的 poll 再次 close(合法 token)→ **幂等返回 2xx**(状态已是 closed,不视为错误,REQ-ADV-2)。

## 10. 结果展示与百分比(REQ-6)

- 百分比公式:`round(optionVotes / totalVoters * 100)`,显示为**整数(四舍五入)**。
- `totalVoters == 0` 时,所有选项显示 `0%`。

## 12. 接口草案(最小,详细在 STEP2 design)

- `POST /api/polls` → 创建;body `{title, options[], mode, deadline?}`;返回 `{shareUrl, adminUrl}`。
- `GET /poll/<id>` → 投票/结果页(HTML)。
- `POST /api/polls/<id>/vote` → 投票;body `{optionIds[]}`;返回结果 JSON。
- `GET /api/polls/<id>` → 结果 JSON(**不含 adminToken**)。
- `POST /api/polls/<id>/close` → 关闭;需带 `adminToken`(header 或 body)。
- `GET /admin/<id>?token=<adminToken>` → 管理页(HTML)。

### 12.1 请求体 schema 与解析规则(REQ-9)

所有 `POST` 接口:`Content-Type: application/json`,body 上限 **16 KiB**(超限 `413 PAYLOAD_TOO_LARGE`);body 非合法 JSON → `400 INVALID_JSON`。

- `POST /api/polls`:`title` 必须为非空(trim 后)string;`options` 必须为长度 2–10 的 string 数组,每项 trim 后非空;`mode` 缺省 `"single"`,取值仅 `"single"`/`"multi"`,否则 `400 INVALID_MODE`;`deadline` 可选,必须为可解析的 ISO 8601 string,否则 `400 INVALID_DEADLINE`,且须为未来时间(否则 `400 DEADLINE_IN_PAST`)。字段缺失或类型不符 → `400 INVALID_PAYLOAD`。
- `POST /api/polls/<id>/vote`:`optionIds` 必须为**非空 string 数组**;空数组 → `400 NO_SELECTION`;含不存在的选项 id → `400 OPTION_NOT_FOUND`;数组内重复 id → `400 DUPLICATE_OPTION_ID`;single 模式长度 >1 → `400 SINGLE_CHOICE_VIOLATION`;类型不符 → `400 INVALID_PAYLOAD`。
- `POST /api/polls/<id>/close`:`adminToken` 经 body 或 header 提供;缺失/错误 → `403 INVALID_ADMIN_TOKEN`。

## 13. 可测收尾标准(Acceptance —— 每条 "if … then …" 可测)

- **AC-1 创建**:提交合法标题 + 2–10 选项 → 返回 shareUrl 与 adminUrl,投票初始 open、计票全 0。
- **AC-2 选项数下界**:少于 2 个选项 → `400 OPTION_COUNT_OUT_OF_RANGE`,不创建。
- **AC-3 选项数上界**:恰好 10 个选项 → 创建成功;多于 10 个 → `400 OPTION_COUNT_OUT_OF_RANGE`。
- **AC-4 单选投票**:single 选一项 → 该项 +1、totalVoters +1,返回结果。
- **AC-5 单选拒多**:single 提交多于一项 → `400 SINGLE_CHOICE_VIOLATION`,不计票。
- **AC-6 多选投票**:multi 选多项 → 所选各项各 +1、totalVoters +1(百分比按人数,允许合计 >100%)。
- **AC-7 软拦截**:同一浏览器成功投票后再打开分享链接 → 直接显示结果页,不显示投票表单;失败投票不置标记。
- **AC-8 手动关闭**:经管理链接(合法 token)关闭 → status 转 closed;此后投票 → `409 POLL_CLOSED`,结果仍可查看。
- **AC-9 到点自动关闭**:设了 deadline 且 `now >= deadline` → 投票视为 closed,新票 `409 POLL_CLOSED`。
- **AC-10 管理凭证隔离**:分享链接/投票页/面向投票人的接口响应均不含 adminToken;无 token 或错 token 关闭 → `403 INVALID_ADMIN_TOKEN`;仅持管理链接者能关闭。
- **AC-11 并发不丢票**:约 50 个并发投票请求(全部合法)打到同一投票 → 最终 totalVoters = 返回 2xx 的请求数,各项计票之和一致,无丢失/覆盖(**对抗性并发测试**:并行发起、校验持久化后计数)。
- **AC-12 非法输入**:空标题、空选项、超长标题/选项、不存在的选项 id、不存在的投票 → 均按 §11 错误码表拒绝,且**不写坏数据文件**(旧文件仍可解析)。
- **AC-13 XSS 防护**:标题/选项含 HTML(如 `<script>`)→ 在投票页/结果页/管理页均被转义为文本呈现,不被作为 HTML 执行。
- **AC-14 deadline 拒过去**:创建时 deadline 为过去或等于当前 → `400 DEADLINE_IN_PAST`。
- **AC-15 持久化失败不谎报成功**:注入落盘失败 → 投票返回 `500 PERSIST_FAILED`,计数不增加、旧文件不被破坏(**对抗性注入测试**)。
- **AC-16 payload 解析边界**(REQ-9):malformed JSON → `400 INVALID_JSON`;`mode` 非法 → `400 INVALID_MODE`;`deadline` 不可解析 → `400 INVALID_DEADLINE`;字段缺失/类型错误 → `400 INVALID_PAYLOAD`;body >16 KiB → `413 PAYLOAD_TOO_LARGE`。均不写坏数据。
- **AC-17 重复 optionId**(REQ-10):一次 vote 的 `optionIds` 含重复 id → `400 DUPLICATE_OPTION_ID`,不计票(不出现某项 +2 而 totalVoters 只 +1)。
- **AC-18 close/vote 并发串行**(REQ-11):close 与多个 vote 并发到达同一 poll → 二者进同一 per-poll 队列;close 持久化后其后到达的 vote 一律 `409 POLL_CLOSED`;最终 totalVoters = close 生效前成功 vote 数,无因竞态丢失或越权计票(**对抗性并发测试**)。
- **AC-19 重复关闭幂等**:对已 closed 的 poll 用合法 token 再次 close → 幂等 2xx,状态仍 closed。

## 14. 不做(Out of scope —— 附原因)

import { promises as fsp } from 'node:fs';

import { randomBytes } from 'node:crypto';

export function createStore(dataDir, opts = {}) {
  const queue = createQueue();
  // opts.injectFailure: () => boolean  — when true, atomicWrite fails (test hook, CC-04)
  // opts.atomicWrite: full override (advanced)
  const injectFailure = opts.injectFailure;

  function fileFor(id) {
    if (!ID_RE.test(id)) return null; // reject path traversal / illegal ids
    return join(dataDir, id + '.json');
  }

  async function ensureDir() {
    await fsp.mkdir(dataDir, { recursive: true });
  }

  async function atomicWrite(filePath, dataStr) {
    if (injectFailure && injectFailure()) {
      throw new ApiError('PERSIST_FAILED', 'injected persist failure');
    }
    if (opts.atomicWrite) return opts.atomicWrite(filePath, dataStr);
    const tmp = filePath + '.tmp.' + randomBytes(6).toString('hex');
    try {
      const fh = await fsp.open(tmp, 'w');
      try {
        await fh.writeFile(dataStr);
        await fh.sync(); // fsync the temp file
      } finally {
        await fh.close();
      }
      await fsp.rename(tmp, filePath);
      // fsync the containing directory so the rename is durable across a crash
      const dh = await fsp.open(dataDir, 'r');
      try { await dh.sync(); } finally { await dh.close(); }
    } catch (e) {
      // best-effort cleanup of the temp file; old file (if any) is untouched
      await fsp.rm(tmp, { force: true }).catch(() => {});
      if (e instanceof ApiError) throw e;
      throw new ApiError('PERSIST_FAILED', e.message);
    }
  }

  // Pure read. Returns the raw poll object or null (not found / corrupt).
  async function load(id) {
    const fp = fileFor(id);
    if (!fp) return null;
    let raw;
    try {
      raw = await fsp.readFile(fp, 'utf8');
    } catch (e) {
      if (e.code === 'ENOENT') return null;
      throw e;
    }
    try {
      return JSON.parse(raw);
    } catch {
      console.error(`[store] skipping corrupt poll file: ${fp}`);
      return null;
    }
  }

  // Create a brand-new poll file (id is fresh, no contention).
  async function create(poll) {
    await ensureDir();
    const fp = fileFor(poll.id);
    await atomicWrite(fp, JSON.stringify(poll, null, 2));
    return poll;
  }

  // Serialized read-modify-write for an existing poll.
  // fn(poll) may throw ApiError or return { changed: boolean }.
  async function mutate(id, fn) {
    const fp = fileFor(id);
    if (!fp) throw new ApiError('POLL_NOT_FOUND');
    return queue.runExclusive(id, async () => {
      const poll = await load(id);
      if (!poll) throw new ApiError('POLL_NOT_FOUND');
      const res = (await fn(poll)) || {};
      if (res.changed) {
        await atomicWrite(fp, JSON.stringify(poll, null, 2));
      }
      return poll;
    });
  }

  return { load, create, mutate, ensureDir, _queueSize: queue._size };
}

// Per-poll serial mutation queue (design SPEC-5).
// Guarantees: same-id fns run in enqueue order; a rejected fn does NOT poison
// the chain; cleanup only deletes a tail that is still current.
export function createQueue() {
  const map = new Map();

  function runExclusive(id, fn) {
    const prev = map.get(id) ?? Promise.resolve();
    // chain onto prev regardless of prev's outcome, so a prior failure never
    // skips this task.
    const run = prev.then(() => fn(), () => fn());
    // tail never rejects, so followers are never chained onto a rejected promise.
    const tail = run.then(() => {}, () => {});
    map.set(id, tail);
    tail.finally(() => {
      if (map.get(id) === tail) map.delete(id);
    });
    // caller gets the real result/error.
    return run;
  }

  return { runExclusive, _size: () => map.size };
}

function isPlainObject(v) {
  return v !== null && typeof v === 'object' && !Array.isArray(v);
}

// Returns { title, options, mode, deadlineMs } or throws ApiError.
export function validateCreate(body, now = Date.now()) {
  if (!isPlainObject(body)) throw new ApiError('INVALID_PAYLOAD');

  // title
  if (typeof body.title !== 'string') throw new ApiError('INVALID_PAYLOAD');
  const title = body.title.trim();
  if (title.length === 0) throw new ApiError('TITLE_REQUIRED');
  if (codePoints(title) > LIMITS.TITLE_MAX) throw new ApiError('TITLE_TOO_LONG');

  // options
  if (!Array.isArray(body.options) || !body.options.every((o) => typeof o === 'string')) {
    throw new ApiError('INVALID_PAYLOAD');
  }
  if (body.options.length < LIMITS.OPTIONS_MIN || body.options.length > LIMITS.OPTIONS_MAX) {
    throw new ApiError('OPTION_COUNT_OUT_OF_RANGE');
  }
  const options = body.options.map((o) => o.trim());
  for (const o of options) {
    if (o.length === 0) throw new ApiError('OPTION_REQUIRED');
    if (codePoints(o) > LIMITS.OPTION_MAX) throw new ApiError('OPTION_TOO_LONG');
  }

  // mode
  let mode = 'single';
  if (body.mode !== undefined && body.mode !== null) {
    if (body.mode !== 'single' && body.mode !== 'multi') throw new ApiError('INVALID_MODE');
    mode = body.mode;
  }

  // deadline (optional)
  let deadlineMs = null;
  if (body.deadline !== undefined && body.deadline !== null) {
    if (typeof body.deadline !== 'string') throw new ApiError('INVALID_DEADLINE');
    const t = Date.parse(body.deadline);
    if (Number.isNaN(t)) throw new ApiError('INVALID_DEADLINE');
    if (t <= now) throw new ApiError('DEADLINE_IN_PAST');
    deadlineMs = t;
  }

  return { title, options, mode, deadlineMs };
}

// Returns { optionIds } or throws ApiError.
export function validateVote(body) {
  if (!isPlainObject(body)) throw new ApiError('INVALID_PAYLOAD');
  if (!Array.isArray(body.optionIds) || !body.optionIds.every((x) => typeof x === 'string')) {
    throw new ApiError('INVALID_PAYLOAD');
  }
  const optionIds = body.optionIds;
  if (optionIds.length === 0) throw new ApiError('NO_SELECTION');
  if (new Set(optionIds).size !== optionIds.length) throw new ApiError('DUPLICATE_OPTION_ID');
  return { optionIds };
}

const BODY_LIMIT = 16 * 1024; // 16 KiB

function sendJson(res, status, obj) {
  const s = JSON.stringify(obj);
  res.writeHead(status, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(s);
}
function sendHtml(res, status, html) {
  res.writeHead(status, { 'Content-Type': 'text/html; charset=utf-8' });
  res.end(html);
}
function sendError(res, err) {
  if (err instanceof ApiError) return sendJson(res, err.status, { error: err.code, message: err.message });
  console.error('[server] unexpected error:', err);
  return sendJson(res, 500, { error: 'INTERNAL', message: 'internal error' });
}

// Read a JSON body, enforcing content-type and the 16 KiB cap. Empty body -> {}.
function readJsonBody(req) {
  return new Promise((resolve, reject) => {
    const ct = (req.headers['content-type'] || '').split(';')[0].trim().toLowerCase();
    if (ct !== 'application/json') return reject(new ApiError('UNSUPPORTED_MEDIA_TYPE'));
    let size = 0;
    const chunks = [];
    let aborted = false;
    req.on('data', (c) => {
      if (aborted) return;
      size += c.length;
      if (size > BODY_LIMIT) {
        aborted = true;
        req.pause();
        req.removeAllListeners('data');
        req.resume(); // drain remaining bytes so the socket can carry our 413 response
        reject(new ApiError('PAYLOAD_TOO_LARGE'));
        return;
      }
      chunks.push(c);
    });
    req.on('end', () => {
      const raw = Buffer.concat(chunks).toString('utf8');
      if (raw.trim() === '') return resolve({});
      try { resolve(JSON.parse(raw)); }
      catch { reject(new ApiError('INVALID_JSON')); }
    });
    req.on('error', reject);
  });
}

function safeTokenEqual(a, b) {
  if (typeof a !== 'string' || typeof b !== 'string') return false;
  const ba = Buffer.from(a);
  const bb = Buffer.from(b);
  if (ba.length !== bb.length) return false;
  return timingSafeEqual(ba, bb);
}

export function createApp(store) {

  async function loadEffective(id, now = Date.now()) {

        if (p.status === 'open' && isExpired(p, now)) { p.status = 'closed'; return { changed: true }; }
        return { changed: false };
      }).catch(() => {});
      return await store.load(id);
    }
    return poll;
  }

export async function startServer(opts = {}) {
  const dir = await mkdtemp(join(tmpdir(), 'qp-test-'));
  const store = createStore(join(dir, 'polls'), opts.storeOpts);
  const server = createApp(store);
  await new Promise((res) => server.listen(0, '127.0.0.1', res));
  const port = server.address().port;
  const base = `http://127.0.0.1:${port}`;
  return {

    },
  };

export async function api(base, method, path, body, headers = {}) {
  const init = { method, headers: { ...headers } };
  if (body !== undefined) {
    init.body = typeof body === 'string' ? body : JSON.stringify(body);
    if (!('content-type' in Object.fromEntries(Object.entries(headers).map(([k, v]) => [k.toLowerCase(), v])))) {
      init.headers['Content-Type'] = 'application/json';
    }
  }
  const res = await fetch(base + path, init);
  const text = await res.text();
  let json;
  try { json = JSON.parse(text); } catch { json = undefined; }
  return { status: res.status, json, text, headers: res.headers };
}

位置: `src/server.js:125-127`。代码用 `(typeof body.adminToken === 'string' && body.adminToken) || header`，当 body 里 `adminToken: ""` 且 header 带合法 token 时会回退到 header 并成功关闭；规格明确“两者都在时 body 优先”。  
建议: 用“字段是否存在”决定优先级，而不是 truthiness；body 存在但为空应按 body 校验并返回 `403 INVALID_ADMIN_TOKEN`。

GAP-3 — CL-04/SPEC-2: admin token 比较不是全路径常量时间。  
位置: `src/server.js:56-61`。长度或类型不匹配时提前返回，未执行常量时间比较；场景 CL-04 明确要求错误 token 校验用常量时间比较。  
建议: 对候选 token 先规范化为固定长度 buffer，长度不匹配也执行一次 dummy `timingSafeEqual`，最终再结合长度/类型结果返回 false。

GAP-4 — CL-06/CL-02: expired poll 首次“写入路径”不会持久化 `closed`。  
位置: `src/server.js:113-121`。过期 poll 收到 vote 时，`applyVote` 直接抛 `POLL_CLOSED`，`store.mutate` 因异常不会写盘，所以磁盘 JSON 仍可能保持 `status:"open"`。CL-06 要求 deadline 已过的 poll 首次被读取/写入时持久化 closed；现有 CL-06 测试只覆盖 GET 读路径。  
建议: vote mutation 内先检测 deadline，若过期则在同一 per-poll queue 中持久化 `status:"closed"`，再返回 `409 POLL_CLOSED`；补测“过期后首次请求是 vote”时磁盘状态为 closed。

GAP-5 — CC-04/REQ-3: `atomicWrite` 在 `rename` 后的目录 fsync 失败时会返回 `PERSIST_FAILED`，但新 JSON 已经对外可见。  
位置: `src/store.js:39-47`。REQ-3 要求任一持久化环节失败时返回 `500 PERSIST_FAILED` 且“不更新任何可观测结果”；当前若 `rename` 成功、`fsp.open(dataDir)` 或 `dh.sync()` 失败，catch 会返回失败，但文件内容已替换。现有 CC-04 注入点在写入前，无法覆盖 rename/dir-fsync 后失败。  
建议: 扩展 atomic write 失败模型并补测 rename/dir-fsync failure；实现上需保证返回 500 时可观测文件仍为旧版本，或调整错误处理契约使 ack/可见性/持久化语义一致。

**Advisories**

GAP-ADV-1 — 若干绑定测试比场景意图弱，但静态阅读显示当前代码大体满足对应行为：PC-11 未测 deadline 等于当前时间；PC-16 只测 create 的 Content-Type；SEC-02 TAP 测试未覆盖管理页 SSR，动态 XSS 主要在 e2e on-top 层；VT-08/VT-09 TAP 主要是正则级客户端绑定；SEC-01 的 shareUrl 断言分散在 PC-01 而非 SEC-01。建议补强这些测试以降低回归风险。
