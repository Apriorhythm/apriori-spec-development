# 遗留项目实验 · 评估(2026-07-09,inherited-poll,alpha.14)

靶子:superpowers-poll 改造的"前同事留下的无文档项目"(18 测试绿)。委托:medium(服务端防重)+ trivial(body 校验 500→400)。全程 Sonnet,闸口由我扮演,评审真实 codex。途中经历 1 次连接断、1 次卡顿、1 次会话被杀——**全新会话仅凭盘上 flow-state 无损续跑**(还用 reviewer-session 字段复活了死掉的 codex 会话续完评审)。

## 主验证目标:P10/KB 循环 —— 通过,质量超预期

- **反向捕获(P10)**:API 契约、三时刻、6 条坑、诚实的 needs-human-confirmation 标记;还做了 git 考古(挖出前任删掉的设计稿并如实声明"不编造意图")。
- **KB 闸口的现实压力**(我注入:"我也不熟,确认不了"):代理没有卡死也没有假装确认——保留未确认标记继续走,并把"前任无决策记录"固化为 **DEC-0 长期 caveat**。这个即兴处置正确,值得成文。
- **KB 真的发力了**:STEP1 从代码(不只 KB)读出两个设计关键(store 写失败留脏内存→写后提交重构;全同步链=并发保证→DEC-5 成文不变量);STEP2 评审抓到**遗留特有兼容 bug**(旧数据无 voters 字段→500,DES-001)。
- **回写质量**:source-commit 链条干净(3f1d309→c7a1605→8699ca8),DEC-1..5 把边界写诚实(DEC-4"持久化等级不虚标"——保证声明纪律渗透进 KB 写作)。
- **边界确认**:KB 捕获≠缺陷审计——5 个已知地雷只覆盖 2(委托目标的无防重 + null-body);其余 3 个潜伏 robustness 缺陷未入坑清单。这符合 P10"记录现状"的职责,但值得一句话写明,免得用户以为捕获=体检。

## 次验证目标:Trivial 档 —— 基本合格

light explore → 1 条失败测试(RB-01)→ 单文件修复 → 1 轮评审 → 归档+KB。仪式量与事体相称。**亮点:复现先行纠正了我的错误报告**(真 500 的是 JSON `null`,不是空 body)——"用户报症状不报病因,trivial 的 light explore 也挣回了票价"(代理原话)。唯一可议:KB 有变时 trivial 也要过 gate④,这是规则一致的正确行为,不改。

## 意外收获:会话死亡全谱系恢复

同一变更经历三种中断(断连/卡顿/整会话被杀),包括最狠的"换一个全新会话接手"——凭状态文件+盘上产物精确定位续点(还识别出 next-action 的描述先于实际进度,靠对账工件纠正)。协议的无损恢复主张拿到了最强证据。

## 摩擦收成(11 条,可修清单)

**Runbook 文本(6):** ① 遗留 kickoff 时 KB 前置检查可以/应该提前到 STEP0 之前——未言明;② gates 标签词汇表没有 KB 签核的专属标签(被迫用 note,而 KB 签核是 §1 保护闸口!);③ P10 对陌生代码的"模块"划分无指引;④ next-action 一行塞两步,会话死后续点模糊——应一行一动作;⑤ R2 只写了台账代录,评审文档本体同机制未写明;⑥ root 环境下 chmod 故障注入静默无效——保证纪律应提示 DI 替代。加 ⑦ STEP6 归档后 gate④ 期间 flow-state 在 archive 路径下——未言明;⑧ P10≠缺陷审计一句话。
**CLI(3):** ⑨ verify 解析到 0 条 TAP 结果时应提示"test-cmd 可能没输出 TAP"(而不是全列 UNBOUND);⑩ archive 首跑:store 文件不存在报 ENOENT(应自动建空 store);⑪ archive `--write` 不带 `--changes-dir` 不挪目录(prose 暗示自动)+ 半完成后重跑撞同 ID 冲突(应识别"内容完全相同=已合并"为幂等无操作)。
