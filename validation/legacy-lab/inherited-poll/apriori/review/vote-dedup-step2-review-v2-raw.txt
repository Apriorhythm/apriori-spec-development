    17	
    18	Owns cookie parsing/building and signing. Zero new dependencies — `node:crypto` only.
    19	
    20	- `loadOrCreateSecret(dataDir)`: reads `<dataDir>/cookie-secret`. Missing → `fs.mkdirSync(dataDir,
    21	  {recursive:true})` then generate 32 random bytes via `crypto.randomBytes(32)` and
    22	  `fs.writeFileSync` (sync — this module does its **own** `mkdirSync`, does not assume `store.js` has
    23	  already created `dataDir`, closing gap-report risk #3). Present but wrong length → `throw` (server
    24	  construction fails loudly; no silent regeneration — VD-10).
    25	- `issue(secret)` → `{value, raw}`: `raw = crypto.randomBytes(16).toString('base64url')`;
    26	  `sig = crypto.createHmac('sha256', secret).update(raw).digest('base64url')`; cookie value =
    27	  `raw + '.' + sig`.
    28	- `verify(cookieValue, secret)` → `raw string | null`: splits on `.`, recomputes HMAC over the `raw`
    29	  part, `crypto.timingSafeEqual`s against the provided signature; malformed input or mismatch → `null`
    30	  (never throws — HTTP layer treats `null` as "no valid identity").
    31	- `digest(raw, secret)` → `crypto.createHmac('sha256', secret).update('voters:'+raw).digest('base64url')`:
    32	  a **different** HMAC input prefix than the cookie signature, so the persisted `voters[]` digest can
    33	  never be replayed as a valid cookie signature or vice versa. This is what gets stored in
    34	  `poll.voters` — never the raw identity, never the cookie value (B7 privacy).
    35	- `parseCookieHeader(header)` → tiny hand-rolled `Cookie:` header parser (no library) returning
    36	  `{pv: '...'}`-shaped object; `buildSetCookie(value)` → the literal
    37	  `pv=<value>; HttpOnly; SameSite=Lax; Path=/; Max-Age=31536000` string.
    38

    61	  fs.renameSync(tmp, file);

    64	  const snapshot = { ...data, [poll.id]: poll };
    65	  save(snapshot);       // throws → `data` untouched, caller sees the throw

    67	}
